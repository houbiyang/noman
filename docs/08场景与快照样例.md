## 1. 状态与使用边界

原基线建立于 2026-10-26，本轮按三项目融合修订；仍为设计草案，关联 D-04、D-07、D-09、D-10、D-14、D-15。本文补齐领域数据字典和一份完整最小准备态样例，用于字段审阅与夹具设计；不代替 API 的角色投影，不表示数据库或校验器已经实现。

下文所有数值来自隔离测试配置 `fixture-params-v1`，不是产品默认值或真实距离。JSON 能解析只证明语法；跨字段、几何、阶段与权限必须另校验。暂不包含运行中全部动作／事件联合变体，不称全量 JSON Schema 已完成。

<a id="section-02"></a>

## 2. 三种数据各自归属

| 类型 | 用途 | 不得混用 |
| --- | --- | --- |
| 场景与规则配置 | 静态地图、导航、部署、对象、模板和参数版本 | 图片不是道路／阻挡数据，模型不能改规则版本 |
| 内部状态快照 | 完整世界，供持久化和恢复 | 不向红蓝原样返回完整双方世界 |
| 角色 GameView | API 按同一快照投影的允许字段 | 不把局部 GameView 当完整存档恢复 |

标识区分 UUID 实体与场景内稳定对象代码。样例 UUID 是固定测试值；场景代码 `A/B/C` 不作为所有地图通用数据库主键。正式编码方案随场景版本锁定。时间戳不在世界样例中伪填当前时间，实际持久化现实时间在记录元数据中保存。

<a id="section-03"></a>

## 3. 通用字段与校验规则建议

| 字段类别 | 约定 | 必须检查 |
| --- | --- | --- |
| 坐标 | x、y 为规范十进制字符串，带 coordinate_system_id | 有限值、同一坐标系、边界、精度与几何政策 |
| 量值 | value 十进制字符串、unit_code 明确量纲 | 能源、补给、库存、耐久不混用，不适用为空 |
| 计数／步数 | 整数；修订等 BIGINT 在外部传字符串 | 非负、仿真 0 至 60、同一步允许多修订 |
| 空值 | 明确无对象／不适用，与零和未知分别表达 | 未知有状态与最后有效时间，不靠 null 表达所有原因 |
| 引用 | 稳定对象标识 | 对象存在、所属局／分支／阵营正确 |
| 判别联合 | 以 unit_type、action_type、event_type 等区分变体 | 必需键、允许键、禁止字段和跨字段约束 |
| 版本与哈希 | schema_version、rule_version、hash_format_version | 规范序列化、十进制形式、键和数组顺序；不使用 jsonb 文本外观作协议 |

本文样例未提供 payload_sha256，不伪造已验证哈希。正式实现需先确定规范化规则，再计算和校验。未知字段的拒绝／扩展机制随 Schema 版本决定，不能静默忽略用于改变动作的未知输入。

<a id="section-04"></a>

## 4. 完整状态根字段字典

沿用 DB 的十二个 state_payload 根对象，避免另起一套同义可写字段。

| 根字段 | 必需内容 | 交叉校验 |
| --- | --- | --- |
| manifest | 格式、场景、规则、参数和资源引用 | 与外层对局版本匹配 |
| lifecycle | 步、截止、阶段、暂停原因、双方准备 | 与快照列相同，待确认不允许推进 |
| camps | 双方兵营、占地、入口、停靠、补给功能、待命清单 | 完整占地合法，清单与单位等待状态相等 |
| units | 阵营类型、归属、位置、主动作、任务、资源和 role_details | 标识唯一，一个活动编队和主任务 |
| formations | 成员、节点分工、能力依赖、受阻原因 | 所有成员本方，不重复占用 |
| tasks | 模板、目标修订、三节点、期限、状态和旧目标 | 成功失败与节点定义一致，旧目标不累计新分 |
| routes | 地面／空中类型、点段、当前位置进度、合法性和依据 | 引用正确单位与连接，不能存屏幕像素 |
| observations | 每方探索、来源、报告、最后发现及未知状态 | 双方独立，历史位置冻结 |
| logistics | 库存引用、服务占用、物资／设备与持有关系 | 对象唯一持有，同次服务不重复恢复 |
| conditions | 预设、活动、已恢复事件及作用区间 | 实例唯一、五步按确认政策、结束不补步 |
| decisions | 分析请求、待确认引用、采用计划和处理事实 | 无真实建议不得填内容，读档不重放 |
| scores | 三分项、预算、独立损失、权重与冻结结果 | 来自实际事实，未结束不伪造胜负 |

运行态还须定义 formations、routes、reports、active conditions、adopted plans 和计分事实等嵌套 Schema。根对象非空验证不能替代这些定义。

## 7. 从准备到运行必须补齐的变体

| 变体 | 必需字段 | 不变量 |
| --- | --- | --- |
| 行进 | action_id、类型、route_id、开始步、当前段及进度、已计费执行引用 | 当步单主动作，路线从真实位置延续 |
| 现场 | 节点、执行者、开始和剩余操作、信息前提 | 到场与能力满足；辅助动作不增加计分节点 |
| 服务 | 服务实例、双方对象、预约、库存、完成事实 | 一对象一次服务，不同线程不重复恢复 |
| 运输和交接 | 对象、唯一持有者、位置状态、交接事实 | 成功才转移，恢复不复制 |
| 观察 | 来源、对象、位置、observed_step、last_valid_step、certainty、可共享状态 | 失视当步停止实时更新 |
| 事件 | 实例、来源、对象、触发修订、影响转换和恢复点 | 按 D-02，不从现实时间推导 |
| 待确认／已采用 | 原建议、依据指纹、人工处理、采用计划、可执行指令 | 不能把 pending 标为已执行 |
| 抽象对抗 | 当步参与者、资格、共同依据、前后值和独立失效事实 | 顺序无关、无重复损失 |
| 最终结果 | 结束原因、双方分项总分、计分事实与胜负 | 结果冻结，不按新模型或规则重算 |

上述字段是待确认设计。每个变体至少补一份成功、拒绝及恢复样例后，才能标记其完整契约已交付。

<a id="section-08"></a>

## 8. 数据校验清单与负例

1. 外层 simulation_step 与 lifecycle 不同：拒绝；不能选一个值悄悄覆盖。
2. 六单位中出现重复 unit_id 或错误 camp_id：拒绝；不按列表索引重编号。
3. 红方成员加入蓝方编队、一个对象两持有者：拒绝，事务不部分提交。
4. 无主动作却带路线进度，或服务对象与预约不一致：按联合结构拒绝。
5. score 计费次数与实际执行事实不符：拒绝或诊断失败，不能靠页面重新减分修补。
6. 准备完成但缺合法兵营／入口：拒绝开始；地图上画出建筑不等于合法。
7. 报告当前有效但来源已受影响、已失视仍更新对方坐标：信息边界失败。
8. 引用其他规则版本、原文缺失或向量空间混用：不得伪成功发布或恢复。
9. 不认识 schema_version：明确不兼容，保留当前有效游戏，不填默认字段强行加载。

<a id="section-09"></a>

## 9. 契约产物与完成条件

实施 B0 形成已确认的 OpenAPI、请求响应模型、内部状态 JSON Schema 和前端类型的生成／校验方式；不手工维护四份不同规则。静态语法 Schema 与领域语义校验器分开，跨字段引用和几何由领域验证承担。

原基线包含字典、两个可解析 JSON 样例及负例计划，本轮另加三份明确标记的融合夹具；没有创建 JSON Schema 文件、生成类型、运行数据库或完整仿真。后续验收必须区分语法可解析、结构验证、业务合法和新进程恢复四种证据。

## 10. 三项目融合字典与夹具

### 10.1 数据身份与扩展位置

对齐 [接口融合契约](06接口契约.md#fusion-contracts) 与 [融合数据设计](07数据库设计.md#fusion-data)。原最小场景和准备态两个 JSON 块保持不变；新增内容是独立契约夹具，不能直接拼接进原 `state_payload` 或称为完整运行态。

| 数据 | 拟议归属 | 必须区分的身份与校验 |
| --- | --- | --- |
| 源资产与目标发布 | 制作态资产及场景发布清单 | 源工程、源格式、源节点、目标节点、模板与游戏单位 ID 分开；映射版本与校验报告可追溯 |
| 模板与组织展开 | 资产定义、对局准备配置及快照实例 | 父子统计不重复，复制产生新身份，人数和装备数量不能直接当作参战单位数量 |
| 场景与 Unity 资源 | 场景 `asset_manifest` 及快照 `manifest` 的版本引用 | 坐标、导航与公开表现资源一致；内部隐藏动态对象不放入公开清单 |
| 命令与实际执行 | 应用命令、方案处理、事件及快照关联 | 草稿修订、预览依据、请求键、命令 ID、方案 ID、动作 ID 与独立事实键各自表达 |
| 单位 Agent | 后续受控绑定及运行上下文 | 单位、阵营、分支、绑定修订和会话独立；不替代原四逻辑角色或绕过采用 |
| 导入预览 | 暂存输入、兼容检查及目标上下文 | 输入摘要、规则/格式/资源版本、冲突及最终确认必须对应同一内容 |
| 分析结果 | 后续独立分析记录 | 来源冻结快照、分析 ID、干预项、假设和证据状态；不写入主局 `scores` |

新增字段的名称、必填性、量纲和规范哈希由 D-07 审阅，预览与幂等由 D-09 约束，兼容与保留由 D-10 约束。没有填入真实摘要前，不使用貌似有效的 SHA-256 字符串冒充完整性校验通过。

### 10.5 融合数据负例与完成条件

| 编号 | 输入或操作 | 独立预期 |
| --- | --- | --- |
| DATA-MERGE-01 | 组织树存在环、缺父节点、重复 ID 或跨方挂接 | 定位并拒绝，不自动重编号或覆盖当前编制 |
| DATA-MERGE-02 | 父子同时展开、复制子树或装备同名不同 ID | 身份与实例数正确；零值保留，断引用不静默修复 |
| DATA-MERGE-03 | 地图映射版本不匹配、断路或资源缺失 | 不发布或加载伪成功场景，保留有效版本 |
| DATA-MERGE-04 | 总览跟随切换、改变高度或视觉插值 | 业务坐标、步、观察与计分事实不受相机和动画影响 |
| DATA-MERGE-05 | 受理收据无结果，或同一事实在多个读取中出现 | 不提前显示执行成功，不重复扣费、损失或任务节点 |
| DATA-MERGE-06 | 预览后改内容、来源不兼容或身份冲突 | 重新校验或拒绝，不切头、不生成半份恢复状态 |
| DATA-MERGE-07 | 读档后旧请求、绑定或模型结果晚到 | 不写入新分支；Unity 旧跟随与实时对象引用清理 |
| DATA-MERGE-08 | 将分析结果、局部 GameView 或 DSH 检查点作为完整游戏存档 | 拒绝混用；无完整状态和依赖不能宣称可恢复 |
