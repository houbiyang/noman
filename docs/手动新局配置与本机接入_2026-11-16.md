# 手动新局配置与本机接入

分支：`codex/ditu`。本次保持地图及规则文件不变，不合并main、不提交推送、不迁移用户数据库。

## 已实现

1. 战斗入口选择「本地手动测试」后，主持人可打开「配置手动新局」。此按钮只打开配置，不启动旧局；Agent入口仍不冒充已接通。
2. 延用深绿居中面板和背景遮罩。蓝红分栏填写数量、每个单位的整数毫米坐标/支撑面、各自三座兵营及服务锚点；不生成默认兵力或合法位置。
3. 单类0～10、每方至少1个单位，双方可非对称；此限制来自软件容量清单而非总册固定编制。仅无人机方提示缺乏占点能力，非对称场景不宣称平衡。改变数量保留已填写的部署草稿。
4. 从后端读取并校验60秒/轮、最多60轮、地图身份、规则/场景/容量UUID及摘要、软件容量契约。数量、资源和部署合法性的最终权威仍在后端；客户端不能提交资源、发布状态或验收标记。
5. 创建前先在非静态私有目录原子保存原请求键/配置；响应不确定时冻结配置，只能恢复结果或原键原正文重试。刷新后可重新读取待核对配置并还原为只读表单。
6. 新局成功及主持人会话签发后才切换独立active pointer。后续蓝方、红方和主持人接入同一新局；每次只返回所选席位的令牌。旧演示记录与存档不覆盖。
7. 创建收据增加`creation_payload_sha256`。恢复时核对创建键、带手动协议前缀的原配置摘要及规则/场景版本，避免误接其他协议或同键异参的对局。

## 本机入口

均为同源POST，要求Origin和Host精确匹配本机监听端口。手动入口另须真实主持人Bearer，验证其属于当前本机对局；不相信请求体角色，不接受任意上游地址。

| 入口 | 用途 |
| --- | --- |
| `/api/local-manual/setup` | 读取配置来源和当前源对局的待核对创建意图，不发布版本 |
| `/api/local-manual/create` | 先保存意图，后调用受bootstrap保护的新局创建API |
| `/api/local-manual/recover` | 查询原创建收据，已有game_id时恢复会话和本机接入，不另建新局 |

- bootstrap仅由Python服务端读取。新入口`Cache-Control: no-store`，拒绝跨源、缺席位、额外字段及超过64KiB的正文。
- 明确拒绝的规则/版本/部署错误经白名单脱敏展示，可重新读取后修改；未知5xx、网络及磁盘失败保留原意图，不自动换键。
- 本机已切换其他对局时，旧源局不能重新激活历史新局。
- 本机锁串行同一Web服务进程；不声称支持多个独立Web进程同时管理同一私有记录目录。

## 测试结果

证据位于项目`.local/manual-entry-20261116/`，不是发布产物。

- `regression.log`：279项纯回归通过，含原核心/几何支撑测试及新增本机创建、同源HTTP、安全和故障恢复测试。
- `database.log`：95项随机隔离PostgreSQL库回归通过。新增桥接联调覆盖新局创建→三席位接入→蓝红锁定→主持人结算60秒→持久回放→蓝方读取主持人回放被拒绝。另保留60轮持久化测试。
- `unity-all.log`：204项Editor断言通过：新局配置31、战斗入口20、手动面板69、回放46、单位控制19、部署提示19。
- `git diff --check`及Python语法检查通过。

**验证边界**：DB联调用合成SetupGeometry，仅写随机测试库；Editor使用合成数据且不发网络请求。不是实地图行军、交火或WebGL截图验收，不能把合成surface ID用于真实部署。

## 尚未发布/完成

- 生产场景仍需真实地表/服务面/路径及总册地图执行器验收。`manual_setup.can_create`保持保守false；配置可编辑与提交验收不等于能够开战。创建API仍严格拒绝未通过的场景，不用旧引擎或默认合法桥头绕过。
- 支撑面ID和位置目前需显式填写，尚无经地图适配器验证的可选支撑面目录或地图点选部署。
- 本轮未重新构建发布WebGL、未重启本机API/Web服务。因此正在运行的旧网页不会自动出现本次新面板。
