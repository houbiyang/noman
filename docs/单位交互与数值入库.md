# 单位交互与数值入库

本次依据《青岚_游戏规则_v1.1》实现**单位交互子系统**，沿用项目既有 PostgreSQL、命令事务、快照、席位权限和 Unity WebGL 界面。不是完整 v1.1 比赛模式验收。

## 1. 数据与结算

- `backend/unit-rules-v1.json`：移动、攻击、观察、野外服务、兵营补充的版本源；启动登记进 PostgreSQL `sandbox.rule_versions.definition`，内容散列决定不可变版本 ID。
- `sandbox.game_snapshots.state_payload.unit_interactions`：冻结规则 ID、完整参数、五秒时钟、当前任务和近期内部交互事件；移动地形/方式参数一同冻结。
- `state_payload.units`：耐久、能源、武器弹药、容量、保障库存、生命实例 ID、停靠状态、最近开火/受伤时间等持久化。沿用 JSONB 快照，不另建不一致的实时单位表。
- `sandbox.game_commands`：记录 `enable_unit_interactions`、`unit_order` 等真实命令。校验席位、上下文、生命实例后原子提交；相同幂等键重试不重复扣除资源。
- 存档恢复恢复对应资源、任务、规则和时钟，不从客户端显示值重建状态。
- 沿用原项目“一步 = 一仿真分钟”；单位模式每步内部结算 12 次，每次五仿真秒。暂停时可以布置任务，但**下达任务本身不造成伤害/补给，推进仿真才结算**。

## 2. 当前冻结基础数值

| 项目 | 无人机 | 履带地面单位 | 保障单位 |
|---|---:|---:|---:|
| 耐久上限 | 40 | 100 | 80 |
| 自身能源上限 | 100 | 100 | 100 |
| 基础移速（米/仿真分钟） | 800 | 400 | 300 |
| 每公里基础能源 | 5 | 8 | 10 |
| 基础观察范围（米） | 1400 | 900 | 700 |
| 自身武器弹药上限 | 无武器 | 60 | 无武器 |

保障库存：能源 200、弹药 120、维修材料 100；与自身能源和自身武器弹药分开。

- 地面攻击：每 10 仿真秒最多一次，每次耗 1 弹，伤害 16；地面射程 600 米、空中射程 800 米；实际移动开火伤害为 9.6。移动射击预算先按 1.25 倍预留；未实际开火仅扣基础移动耗能，不追加位移。
- 无人机飞行/悬停额外耗能 2/仿真分钟，合法停靠不扣此项。林内观察和林外看入树林的距离限制按当前保守几何检查。
- 野外保障：双方停止、距离不超过 100 米、地面可达且视线合法；每五秒只服务一个目标的一种资源，增加最多 2 点，同时扣同量库存。维修消耗维修材料。无人机须先在本方兵营合法停靠。
- 一个目标每五秒只接受一个补充/维修来源，不能叠加野外与兵营服务。
- 兵营补充：合法接触、连续 15 仿真秒未开火/未受伤后，每五秒最多服务四个目标；耐久/能源/武器弹药各最多 +50，保障库存能源/弹药/维修材料各最多 +50/+60/+50，不超过容量。
- 同一五秒内双方攻击意图统一冻结、伤害同步提交，再结算服务；允许互相击毁，维修不能复活本步已击毁单位。
- 能源为零不能移动、侦察或攻击；本步补能不追补本步观察/据点资格。

## 3. 界面与操作

地图悬浮单位会显示深绿浮卡：真实耐久、**基础移速与最近五秒实际移速**、能源与武器弹药。实际移速由后端五秒内的位移计算，受地形和移动方式影响，并非浏览器帧动画速度；总览下悬浮单位标签也可显示。保障库存另在单位卡显示，无武器单位不显示虚构弹药。

| 按钮 | 功能 | 条件/结果 |
|---|---|---|
| 侦察目标 | 指定当前可见敌单位，或转为在地图指定侦察区域 | 无人机；区域任务使用真实移动路线；发现即时共享本方，失视不追踪隐藏坐标 |
| 攻击目标 | 下达持续攻击任务 | 履带地面单位；每次开火重新检查可见、射程、独立视线、能源、弹药、生命实例、冷却 |
| 补充单位 / 维修 | 选本方目标，再选能源/弹药/维修耐久 | 保障单位；服务前请先移动到合法接触位置；没有武器容量的单位不能补武器弹药 |
| 合法停靠 | 在本方兵营合法接触范围内停靠 | 无人机；停止路线、停止飞行维持消耗，允许接受保障 |
| 兵营补充 | 请求本方兵营补能、补弹、修复并恢复保障库存 | 需要先返回兵营合法接触范围；等待脱战条件；补满后不额外消耗资源 |
| 取消任务 | 取消本单位当前侦察/攻击/服务任务 | 不回滚已结算数值；**不等于取消已有移动路线**，停止移动沿用原移动控制 |

准备阶段上述作战任务按钮禁用；开局后的暂停/运行阶段才能下达。非主持人只能操作本方单位；敌方面板仅显示当前合法可见情报，不显示敌任务和保障库存。失视后不从隐藏状态刷新位置或资源。

### 本地体验

1. 打开 `http://127.0.0.1:18766/`，进入“军队”并选择兵种/单位。
2. 旧空间对局可由主持人在准备/暂停阶段点击“启用单位交互”；不会重置单位位置与已有耐久、能源。已启用旧协同测试的对局不可再叠加，应另建单位交互对局。
3. 按原有准备流程完成开局；给单位下达任务。攻击不会自动追击；补充/维修不会自动把双方传送到一起。
4. 主持人推进时间/运行仿真，刷新后查看资源变化。双方待确认方案仍遵循原有推进阻塞，不绕过审核。

本次已为当前本地对局创建“启用单位交互前备份”，并通过正式主持人命令启用；仍保留原准备阶段和原单位位置。新创建的网页空间对局默认启用。

## 4. 验证与边界

- 后端回归：`python -m backend.portable test`，当前共 **200** 项通过，包括 18 项单位逻辑、4 项真实 HTTP/PostgreSQL 集成检查，以及原有功能回归。
- Unity：`Qiongtu.Sandbox.Editor.SandboxUnitInteractionChecks.Run`，17 项通过，包含三兵种按钮、准备阶段禁用、目标筛选、资源项目、无候选禁用、区域侦察、浮点耐久和命令 JSON 字段。
- C# 全部现有运行时/Editor 源码编译通过；WebGL 构建成功。网页视觉验收截图保存在本机 `.local/unit-interactions/`，不作为源代码提交。

**尚不属于本次完成范围：**正式地图三角面/桥层/全程扫掠的验收、完整 20 槽编制与五据点/核心攻防、复活及保护、完整 AI 授权策略（含规则文档新增的30点能源底线、路程预留与自动补给预案）和正式兵营公平排队规则。当前仍沿用旧三阶段演示外壳；视线与服务接触使用保守测试包络，不宣称正式地图规则已验收。兵营候选目前按稳定 ID 排序，而非完整竞技优先级与轮换。
