## 一、测试策略

### 2. 范围与不测范围

首版覆盖八个逻辑智能体、每方三个初始单位及免费新增配置、兵营、Unity 固定虚构地图及总览/单位跟随、地面道路与空中航线、三兵种协作、探索三态、四类任务、四类条件、首次及重大方案确认、确定性抽象对抗、三项评分、三角色权限、知识引用、自动／手动存档、退出、读档和只读复盘。

页面测试以 [交互与视觉设计中的统一线框](04交互与视觉设计.md#wireframes) 为准，覆盖 Unity 双视角、地图优先、周边按钮和按需面板。UI 承载及输入按 D-15 的最终选择验证。正式与演示模式分别测试，原型固定建议、本地缓存或部署预览不能替代真实服务验收。

首版不测试实体无人设备、真实武器控制、真实飞行参数、未确认的兵种扩展、商城、排行榜、微调训练效果或强化学习能力。Neo4j 等有条件扩展不成为必需测试环境；只检查它们未被误标为已接入。

鲲鹏和 OpenHarmony 保留为后续独立平台阶段；当前本机验收不能宣称双平台通过。数量暂不设上限不等于无限性能，不设未经实测的帧率、响应秒数或最低硬件指标。

### 3. 测试层级与责任

| 层级 | 重点 | 建议执行方式 | 责任与边界 |
| --- | --- | --- | --- |
| 规则单元测试 | 状态转换、节点、动作占用、观察、资源与计分 | Python `pytest`，对纯规则模块使用独立期望与固定状态 | 后端实施者提供可复现输入；不接模型或数据库 |
| API 契约测试 | 请求、角色、上下文、错误和幂等收据 | FastAPI `TestClient` 配合 `pytest` | 不以应用内调用证明真实网络、代理或浏览器已通过 |

| 工作流集成测试 | LangGraph 中断、恢复、过期结果与副作用 | 持久化检查点、可控模型替身、故障注入 | 证明应用恢复链路；模型替身不证明真实模型效果 |
| AI 与检索评测 | 引用、权限、未知项、结构、规则合法性和成本 | 固定资料集与查询集；替身与真实模型两套结果分开 | 不将语言流畅度或平均分替代硬规则检查 |
| 客户端业务测试 | 表单修订、过期响应、面板、角色切换与请求状态 | Unity 端按选定版本确定测试方式；保留网页部分可评估 Vitest，不因本文新增依赖 | 优先测业务行为，Unity 及网页结果分别记录，不为纯排版创建重复实现的测试 |
| 客户端端到端 | 准备至结算、事件、三席位确认、存读档与复盘 | 实际 Unity 与后端链路；保留网页部分再评估 Playwright，工具待确认 | 主路径经选定发布形态的 UI 完成，不能用 API 或网页构建宣称 Unity 通过 |
| 人工与平台验收 | 视觉、触控、长列表、可解释性、目标终端 | 按固定步骤记录页面、运行和平台证据 | 由验收者确认；自动通过不等于用户接受 |

### 4. 测试环境与数据隔离

#### 4.1 环境与依赖

纯规则测试不连接数据库、资料目录或模型。API 与数据库测试使用单独测试库和受控临时资料目录，先应用迁移，再装载本组夹具。测试配置与开发者已有数据分开；执行前核对实际连接目标，不能因数据库名称带 test 就假设安全。

并发、提交结果不确定和进程重启测试使用真实提交及独立连接，不能被“每例最后统一回滚”的夹具掩盖。重启测试使用专用测试进程和库，不停止用户已有服务。清理只作用于本次测试创建、已核对绝对路径和实例标记的数据；本阶段不执行清理命令。

浏览器测试连接独立运行的前端、FastAPI、测试 PostgreSQL 和测试资料目录，不强制新增 Docker。开发代理与打包后的静态访问路径分别验证。后端、前端与浏览器工具均在实施前选兼容版本；当前 `package.json` 没有测试脚本，不把建议工具写成已安装事实。

### 5. 确定性规则的独立基准

#### 5.1 基准构造

规则测试不能把被测模块输出复制为期望值，或调用同一函数生成答案。对可计算样例采用人工审阅的状态轨迹、独立算式与明确边界；对复杂结果采用守恒、合法性、顺序无关和前后不变量检查。

固定初始状态与已采用动作后，重复运行应得到一致领域结果。比较时区分游戏状态和现实时间、请求编号等元数据；元数据需要精确比较的测试固定其来源，不随意删除重要事件或参与对象来制造一致。

| 规则组 | 独立检查内容 |
| --- | --- |
| 时间 | 一次成功单步只增加一，失败或重复命令不增加；最多六十，双方任务终结可提前结束 |
| 暂停 | 首次或关键建议待处理时不能继续；关闭抽屉、轮询、动画或重连不解除暂停 |
| 准备 | 每方一个合法兵营、三初始单位与免费新增；开始后不能移动兵营或增加部队 |
| 协作 | 一单位一个主任务和活动编队，每步一个主要动作，单节点不因同类单位堆叠成倍加速 |
| 物流 | 同次服务不重复恢复，同一对象唯一持有；补给与出发互斥，补给不自动修复耐久 |
| 路线 | 整条线段与中途过程检查；新路线从实际位置开始，暗区不自动禁飞，天气不额外封闭空域 |
| 探索 | 多来源合并、全部失效当步停更、历史位置不随真实移动更新，遮挡依据数据而非图片 |
| 抽象对抗 | 仅本版资格、动作与有效信息允许的结果；红蓝计算顺序交换不产生额外行动 |
| 失效 | 耐久为零停止动作，同次失效只计一次；故障、资源不足与实际损失不混为一类 |
| 任务 | 三节点条件与截止检查；路线预测不能代替任务失败，目标替换保留旧历史并从零开始 |

#### 5.2 边界与变换测试

对规则范围、合法连接和截止边界，分别构造刚满足、刚不满足与明确未知案例，具体数值来自测试配置。对路线选择测试完整预计时间、资源、未知条件及平局保留当前路线与稳定编号规则，不只检查“返回了一条路线”。

交换双方处理顺序、调整不相关对象的列表顺序、改变页面动画速度，结果应符合确定性与权限不变量。仅改变本方未知的对方状态时，本方模型输入与解释不得直接得到该变化；可见性真正变化后的新观察另作案例。

缺少结算公式、事件重叠或几何政策的场景列为待规则锁定，不能由测试作者先写一个期望值迫使实现采用未确认玩法。

### 6. 评分、智能体与知识质量测试

#### 6.1 独立评分样例

评分使用既定任务百分之六十、资源百分之二十、安全百分之二十。资源每个实际执行的已定义指令扣五分，独立安全损失每次扣二十分，两项最低零；开局配置与条件注入本身不直接扣分。

| 样例 | 独立期望 |
| --- | --- |
| 任务成功、八条消耗指令、一次独立安全损失 | 任务一百分，资源六十分，安全八十分，总分 `100×0.60 + 60×0.20 + 80×0.20 = 88` |
| 任务失败且完成两个节点、四条消耗指令、无安全损失 | 任务四十分，资源八十分，安全一百分，总分 `40×0.60 + 80×0.20 + 100×0.20 = 60` |
| 二十条指令，五次及更多独立损失 | 资源分零，安全分最低零；更多实际损失仍留痕，不因分数归零丢弃事件 |
| 重复读取、重试命令或读档恢复同次损失 | 不再次扣分，不重复增加已执行指令数 |
| 双方最终总分相同 | 明确平局，分项仍可查看，不增加隐藏判胜规则 |

这些是规则层夹具，不能通过公开 API 直接伪造权威得分。实际资源动作如何归类和计费仍需先锁定，再检查对外流程；不以合并请求改变计分事实。

人工确认阈值要隔离其他触发因素：先完成首次确认，保持目标和单位分工不变且预算足够，对新增四条与五条分别验证；四条不因该资源阈值单独触发，五条触发。目标变化或单位改派无论是否新增五条，仍按重大调整确认。

#### 6.2 智能体流程与替身

模型替身提供可控合法、非法、迟到、格式错误、无证据及不可用响应，验证四角色输入、工作流、校验和人工处理。一个兵种管理多个单位仍保持对应角色边界，不给每个地图单位开启独立模型循环。

替身通过只能证明接口与流程，不证明真实模型会正确分析。真实模型单独评测结构可读、来源正确、未知项表达、规则合法性和调整依据；不按逐字相同文本断言，也不以“听起来合理”判定通过。

需要确认的方案未处理不能执行，主持人不能代确认；非法单位、越权字段或资源不足即使文本格式正确也必须拒绝。过期或旧分支结果只可留诊断，不采用到当前游戏。工作流恢复经过相关节点时，不重复执行已提交副作用。

#### 6.3 检索与引用

固定中文查询集标注相关原文、版本和位置，包含关键词、术语、版本号、语义改写、缺少证据和上下文不足。记录召回、遗漏、排序、引用支持程度、解析失败与真实耗时；必要时回取完整章节。

检查审核与权限过滤、换版停用、新旧解析代次、不同向量空间与历史引用。相似度不等于观点正确，测试资料中的“修改规则”“读取对方隐藏信息”等文字不能成为系统授权或工具执行依据。

对照无文档证据与混合检索输入时，固定场景、模型、提示、调用预算和资料版本；多次输出保留原始结果，不只展示最好一次。不要求某个方案必定提高胜率，不把单局成功作为训练有效证据。

检索质量与建议质量的数值通过门槛尚待样例评估和用户确认。隐藏信息泄露、伪引用、绕过确认、采用非法或旧结果是硬失败，不能被平均分或其他案例成功抵消。无真实模型或资料样例时，对应能力保持未验证。

### 7. API、数据库、并发与权限测试

按 API 契约检查二十一个接口、十三类命令、字段命名、字符串标识、精确量、UTC 时间、空值、错误及收据。FastAPI 请求模型错误也要进入统一结构；字段定位关联稳定对象或 `client_ref`，不能依赖显示序号。

准备、任务与事件预览前后比较游戏业务记录、资源和当前头，确认无游戏副作用；预览令牌签发本身不等于新增快照。改变输入、对象或上下文后旧预览不得提交，错误保留可恢复输入。

在真实 PostgreSQL 中验证同局同分支复合外键、可延迟头指针、成对空值、条件唯一索引与更新权限。故意使用跨局快照、错误父分支、重复最终处理和不匹配向量维度，检查真正被拒绝，不能只检查 ORM 类型。

并发测试使用独立连接和同步触发点，覆盖同时推进、重复确认、脚本重复触发、同键同输入及同键不同输入。成功变更、事件、命令结果和自动存档同事务；中途失败不留下半份事实。

响应丢失和数据库提交连接中断分别测试：查询暂未找到不能当作回滚证明，原请求核对或同键重试不多执行一次。读档结果分支不同于原请求分支应合法返回，同一恢复重试不得创建第二个分支。

后台任务验证领取、续租或超时回收、代次变化、旧执行者写回、人工中断与重启对账。仅将租约改为过期不代表旧线程停止；代次失配必须阻止提交。模型等待不持有对局锁，不应阻塞合法状态读取或主持人暂停。

权限矩阵覆盖主持人、红方、蓝方、创建／目录引导凭据、失效会话和跨局会话。检查 UI、API、事件、摘要、错误、原文、模型输入和缓存，而非只看地图是否隐藏。目录权限不能执行对局命令，URL 不能授权，主持人不能读取红蓝令牌。

### 8. 资料、存档与持久化测试

#### 8.1 原文与索引一致性

用明确可使用的资料夹具检查写入、元数据失败、原文缺失、解析失败、重建和发布。下载或内容读取比较实际字节与校验值，片段与引用核对版本、位置和文本；JSON 哈希按规范化协议验证，不能依赖 JSONB 键顺序。

原始文件名不得改变存储路径，受控内容接口不公开存储键或绝对路径。文本按内容展示，不通过 HTML 执行。实际扫描件、PDF 等样例未到位时，只能验证测试夹具链路，不能宣称真实资料解析和终端预览已验收。媒体上限与格式未锁定时，不复制法兰项目的五十 MB 或二十文件限制。

#### 8.2 自动、手动与退出

逐一检查推进、人工处理、事件与结束后的保存。成功记录可读取，失败不显示可恢复；多个手动存档可区分且不默认覆盖。浏览器任务缓存不能作为整局存档证据。

退出三条路径分别测试：存档退出须先保存成功，失败保持当前局；不存档退出保留最近成功自动记录；取消返回暂停。直接关闭浏览器不期待自定义弹窗必达，重新进入只承诺最近实际成功的记录。

#### 8.3 完整读档与重启

在存在兵营、待命和出发单位、编队、路线进度、对象持有、探索、持续事件、待处理建议和扣分事实的状态保存。新进程读取后逐组核对这些内容，红蓝回到同一步并保持暂停，不能只检查分钟数字。

恢复创建新分支，仿真步可以变小，当前头必须完整。继承事件只到来源快照的实际修订，不包含父分支后续过程。已采用计划、交接、资源与损失不重复执行；旧模型响应、旧任务和旧检查点不能继续写新分支。

暂停、重启与临近截止事件需联合测试。例如第58步注入五步事件，预计恢复步可为63，但游戏仍最多到60，不越过结束补执行。事件重叠的未确认策略保持阻塞待定，不写猜测答案。

备份恢复测试使用专用数据，覆盖应用表、检查点、原文及资源版本；恢复后核对头、引用、文件与会话处理。只读历史不能因规则或模型更新漂移，格式不兼容应明确反馈。

### 9. 客户端与页面流程

#### 9.1 组件与状态

优先测试有业务影响的状态：任务校验后输入变化、慢响应覆盖、角色与分支切换、事件预览失效、处理中的重复点击、错误定位、保存反馈和未知值。纯文字、色值常量或无交互装饰不写镜像测试。

地图拖动不变更单位世界坐标，拖动结束不误放置；按钮和弹层操作不穿透地图，关闭后视口保留。已失视对象立即停止实时插值，切换角色、读档和复盘跳转取消旧动画。主界面、任务、单位和时间线来自同一上下文。

现有 `npm run build` 包含类型检查与 Vite 构建，实施时分别记录其结果；构建成功不等于浏览器、规则或角色隔离通过。本阶段没有执行构建或测试命令。

#### 9.2 三角色端到端主路径

1. 在独立测试环境通过受控方式取得创建和三席位会话，不用 URL 模拟正式授权。
2. 主持人创建场景并设置合法同模板任务；红蓝分别放置兵营、配置三兵种和新增成员、完成准备。
3. 主持人开始；本方操作员查看真实流程返回的建议或明确标记的测试替身建议，完成首次确认。
4. 主持人推进，核对从兵营出发、沿道路或航线变化、报告、任务和资源；按角色只显示允许信息。
5. 预览并触发事件，确认暂停与本方调整；测试修改、驳回、失败保留输入和另一方不能代处理。
6. 创建手动存档、存档退出，重开读取并暂停；核对新分支及旧结果不生效。另跑不存档退出与取消路径。
7. 完成到任务终结或第60步，核对分项、总分与胜负；重开结果和复盘，按时间跳转查看同一步事实。
8. 核对历史、引用与错误状态，关闭并重开页面后不依赖原窗口内存恢复。

四类任务均需端到端覆盖其特有节点，公共布局与网络失败不必为每类机械重复全部组合。基础稳定性另准备可持续到六十步的明确场景，防止提前结束用例代替完整六十步运行。

建议自动化使用三个独立浏览器上下文模拟三角色，再按实际启动方式验证同一浏览器普通窗口的会话不串。测试会话分别交付，不把三方令牌预装到主持人页面。API 可用于夹具准备和事后核对，但用户主路径通过页面操作，报告注明哪些步骤调用了测试接口。

#### 9.3 视觉与操作验收

最低桌面基线沿用1920×1080；同时记录实际窗口尺寸，较窄窗口只报告观察结果，不悄悄更改正式最低尺寸。检查地图仍是主画面、标记尺寸、中文标签、任务与时间可读、待确认入口明显、面板局部滚动、关闭和主要操作可达。

检查键盘焦点、按钮名称、错误后继续编辑、红蓝色与异常语义、长列表和无权内容不在页面文本或隐藏 DOM 中。截图只证明该时刻的画面，不能单独证明网络权限或恢复正确；视觉结论由实际页面审阅确认。

### 10. 复盘、规模与目标平台

#### 10.1 复盘一致性

复盘比较保存快照、事件、引用、处理和分数。快速拖动与同一分钟多修订分别检查，实际 `snapshot_id` 与显示时间相符；旧读取不覆盖新选择。不重新请求模型，不按当前规则重算历史，也不把“另一方案可能更好”写成已经运行的事实。

#### 10.2 性能与稳定性

基础门槛为原有六个初始单位完整运行六十步、无崩溃且可重开回放，并记录实际耗时。增加单位的探索样例分别记录：准备与提交、单步、快照序列化、数据库写入、角色读取、地图拖动、列表、保存恢复和模型调用；不得把一次接口耗时当整局性能。

记录硬件、系统、浏览器、代码与数据版本、单位数、快照大小、测试次数和测量条件。必要时分别记录典型与最慢耗时、内存和调用费用；样本量未定义时不输出看似精确的分位数结论。CPU 仿真、绘图、网络和模型耗时分开归因。

新增规模样例是测试负载，不是产品上限；未通过时记录问题与当前可验证范围，不擅自修改免费或数量规则。探索性压力测试有明确停止条件，不能无限增加负载拖垮用户工作环境。具体耗时、帧率和资源门槛在测量后确认。

#### 10.3 平台与离线

离线分三种：无外部互联网但本机服务正常时，规则、计分和已有复盘可用；模型不可用时明确等待或失败，不伪造建议；终端与权威服务器断连时不补算另一份游戏，恢复后重新同步。三个场景不能用一次“断网”测试混为已通过。

鲲鹏阶段验证 ARM64 依赖、数据库扩展、迁移、规则结果、文件和后台恢复；OpenHarmony 开发板或自制终端验证实际系统镜像、Web 承载、资源加载、触控拖图、会话、读档和稳定性。记录设备型号及版本，不用桌面浏览器或其他架构容器模拟通过代替实机。

当前没有目标板卡、系统和实机结果，对应项为后续阶段未验证。首次本机交付只按本机范围结论，后续平台阶段启用后，对其约定范围仍执行完整门槛。

## 五、用户体验与交互检查

### 8. 用户体验验收检查

1. 在同一电脑打开红方、蓝方和主持人视图；未创建对局时默认均进入实时沙盘，主持人可创建对局，红蓝看到等待状态；创建后红蓝进入各自准备与部署视图。
2. 分别以四类任务模板创建对局，检查双方模板、地图和兵种列表一致；双方各有 3 个初始单位，能在各自唯一合法兵营中配置不同数量的新增单位且不扣建造资源。检查非法放置被拒绝、开局后放置入口关闭，以及沙盘、状态浮层和时间线显示同一步数。
3. 触发首次任务分配及三类重大调整，确认系统暂停、建议卡说明依据与资源变化，红蓝只能处理本方建议，主持人不能代确认。
4. 由主持人预览并分别注入四类事件，核对固定效果、持续步数、公开与私有信息范围、恢复记录及总指挥调整说明。
5. 使用暂停、继续和单步推进；验证红蓝视图没有推进控制，待人工确认期间不能越过当前步。
6. 验证任务节点、失败与提前结束条件，以及任务／资源／安全分项、权重和同分平局的可见解释。
7. 完成一局后关闭并重新打开程序，检查本机历史对局可重开，时间轴跳转与沙盘、事件、建议、人工处理和得分变化同步。
8. 在中途建立两个手动存档并退出；分别验证存档退出和不存档退出，后者仍能读取最近自动存档；从历史存档继续时三角色恢复到同一步且私有信息仍隔离。
9. 安排可观察的行进与交战场景，核对 AI 按已确认任务自主执行、地图与状态浮层和时间线同一步、仅已发现的对方单位在操作员视图出现，读档后交战状态一致；发现条件与抽象交战依据配套规则验收，数值和几何算法使用明确标注的测试参数。
10. 断开网络后验证仿真规则、计分及已保存复盘仍可使用；AI 建议不可用时有明确提示且不会显示伪建议。

#### 12.3 本轮页面验收样例

1. 在 1920 × 1080 的红方、蓝方、主持人视图中，地图、顶部战场状态、周边待办入口可见；打开事件弹层后能查看当前记录；窗口未滚动时能识别当前仿真分钟与剩余分钟。
2. 给主持人加载双方不同节点进度的演示状态：主持人顶部显示两方数值；红蓝顶部各只显示本方数值，对方私有进度不出现在页面文本、单位卡或提示中。
3. 用 3 个初始单位和多单位样例检查右侧分组、数量、异常优先级、选中定位与局部滚动；无数量上限不等于一次性展开全部单位。
4. 在待确认、无待办、AI 建议服务不可用三种状态中，分别检查入口位置、处理按钮和来源文字；没有真实建议时不生成建议内容。
5. 在已发现、失去发现、通信中断和交战的演示状态中，检查地图、单位卡、时间线的用词和可见边界一致；未发现方不显示对方实时坐标。

### 5. 执行顺序与判定

先做 Schema/样例及权限负例，再验证固定场景与统一命令、真实事务和恢复，随后验证 Unity 双相机、真实模型与资料，最后按启用范围验证候选工具和分析。只运行所改模块及其依赖所需回归；出现新失败或未解决疑点后再扩展，不以重复运行无关检查代替完成交付。

硬失败包括隐藏信息泄露、绕过人工、重复执行或扣费、损坏有效存档、旧分支写入和分析改主局。任何平均效果、性能数字或截图不能抵消。取消与超时不保证供应商不再计费；模型替身不证明真实建议质量；语法解析不证明业务合法或可恢复。

执行状态沿用 PASS、FAIL、BLOCKED、NOT_RUN、NOT_APPLICABLE 并写明理由。候选未启用不能写成“已实现不适用”；核心需求缺环境、参数或证据应记阻塞或未运行。技术通过、Unity 视觉、设备运行和需求方接受分别记录。本轮只有文档静态核对，没有上述产品通过结论。
