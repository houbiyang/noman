# 手动对战：接口变更、功能完成度与已知问题

**核对版本：** `codex/ditu`（`072fa7e`），2026-11-18。接口与本地已获取的 `upstream/main`（`7be85a5`）直接对比；“本分支没有”不表示该接口曾被谁主动删除。范围为手动对战、沙盘页面及相关 Agent 服务，不是全仓缺陷审计。本次对照源码和已有验收记录，未重新运行对局或浏览器测试。

**交付结论：** 现地图上，本地手动测试已能从六营部署走到双方下令、主持人结算、刷新恢复和原沙盘回放；已有一条从初始部署到占点的 HTTP 全流程记录。它不是全图自动寻路或正式 Agent 对抗版本。最影响演示的是两个不同的问题：P-05 桥面与地面不连通；当前对局从第 3 轮起的单轮播放异常，原因仍待前端复现。

## 一、接口变了什么

以下后端路径以 `/api/v1` 开头；表中的 `G` 代表 `/games/{game_id}`，不是 URL 中的字面量。

### 新增 9 个后端 HTTP 接口

| 方法与路径（省略前缀） | 调用者与用途 | 返回或副作用 |
|---|---|---|
| `GET /battle/setup` | 引导服务读取手动模式配置 | 返回规则、地图、容量、推荐配置（如有）和验收状态；只读，不是开战许可。 |
| `POST /battle/deployment-preview` | 引导服务预览单座兵营的放置 | 返回候选兵营及生成位置，或给出失败原因；不写入对局，不能代替六营整体验证。 |
| `POST /battle/deployment-validate` | 引导服务验证双方完整部署方案 | 校验兵营、编制和位置；成功返回 `valid: true`，不创建新局。 |
| `POST /battle/games` | 引导服务按已确认配置创建独立手动局 | 需要 `Idempotency-Key`；首次成功为 `201`，同请求重放为 `200`，不把旧演示局原地改成手动局。 |
| `POST G/battle/preflight` | 主持人检查手动或 Agent 模式依赖 | 返回核心检查、AI 检查及是否可手动降级；默认不探测外部模型，显式同意费用后才联网。检查不推进对局。 |
| `GET G/battle/rounds` | 主持人列出当前活动分支已结算轮次 | 返回连续的轮号、起止秒、摘要，不一次下载全部帧。 |
| `GET G/battle/rounds/{round_number}` | 主持人读取指定轮（1～60） | 返回持久化的单轮记录；未结算轮不可读。累计播放由页面依次取轮组成，不是另一个写接口。 |
| `POST G/knowledge/query` | 红蓝席位按本方权限和知识版本检索 | 返回检索结果，不接受客户端自选阵营或传入世界状态；不是给单位下令。 |
| `POST G/agents/models/test` | 使用本方配置草稿测试消息、向量或重排服务 | 需显式同意可能产生的费用；不自动保存配置，也不创建 Agent 对局。 |

### 原有接口：路径没变，契约或返回内容变了

| 接口 | 对调用方有影响的变化 |
|---|---|
| `POST G/commands` | 手动局复用统一写入口：`battle_draft` 暂存本方指令，`battle_submit` 锁定本方本轮，`battle_resolve` 由主持人在双方锁定后结算。不是三个新 URL；重复结算应沿用原请求键。旧空间测试局另有 `enable_unit_interactions`、`unit_order`，不能替代手动轮次命令。 |
| `POST /games` | 旧演示新局可通过 `unit_interactions` 启用单位交互（要求空间测试）；总册手动新局走 `/battle/games`，两种新局不可混用。 |
| `GET G/view` | 增加手动轮次、双方锁定状态、本方草稿、可执行操作、持续移动标志、单位资源和据点进度。返回内容按席位过滤；敌方未公开的路线和草稿不能从标签反查。 |
| `GET G/result`、`GET G/archives`、`GET G/archives/{archive_id}` | 手动局使用自己的完成轮数、仿真时间和比分；归档保存相应席位可见的单位、据点和轮次摘要，不套用旧演示计分。档案不是逐帧动画来源。 |
| `GET G/replay` | 仍是快照读取。与对照 `main` 相比，`simulation_step` 上限从 720 变为 60；读取手动局一轮内的事件和帧应使用 `G/battle/rounds/{round_number}`。 |
| `GET/POST G/agents/configuration`、`POST G/agents/runs` | 本方配置扩展了向量、重排及消息模型参数；运行时可按配置检索知识并保留检查点。已有协同运行接口不等于已接通总册手动局的自动对抗。 |

**页面同源入口（不带 `/api/v1`）：** 新增五个 `POST /api/local-manual/` 入口，后缀分别为 `setup`（读取配置）、`preview`（单营试放）、`validate`（整体验证）、`create`（建局并接入主持人）、`recover`（按原请求键恢复建局流程）。它们由本机页面服务转接，不把后端引导密钥交给浏览器；现有 `POST /api/local-session` 用于接入席位。

**合并时不能漏掉的差异：** 对照 `main` 有 `POST G/fivepoint/planning`、`GET G/fivepoint/frame`、`POST G/fivepoint/advance-round`，本分支未注册这三条路由，也未在普通 HTTP 命令契约中提供 `enable_fivepoint`、`submit_fivepoint_plan`、`retry_fivepoint_planning`、`abort_fivepoint`。数据库迁移 013 兼容历史命令值，**不等于接口兼容**。合并时需保留或明确迁移原调用方，不能整文件覆盖路由，也不能把 5 秒帧号直接当作手动轮号。

## 二、哪些已实现，验证到了哪里

| 功能 | 当前实现 | 已有证据与边界 |
|---|---|---|
| 部署与开局 | 双方在原沙盘各放置三座兵营，按确认编制生成单位；进入手动局后不能重配数量。 | 有单营预览、整体校验和独立建局流程；仅限已接入的本地测试地图范围。 |
| 手动指令与轮次 | 选中本方单位后在底部面板下令。双方各自暂存并锁定，主持人一次结算 60 仿真秒，最多 60 轮；每轮生成 12 个 5 秒内部帧。空草稿并不取消持续任务。 | 隔离数据库中已验证双方提交、持久化、服务重启恢复，以及相同请求键重试不额外推进。 |
| 单位交互 | 支持移动、途经点、停止、侦察、起降、攻击、能源／弹药补充、修复和兵营服务。占点由后端裁决，不需要“占领”按钮。 | 已验证从指定初始部署出发，8 轮占领 P-03；攻击、补给和修复另有受控位置样例。后者不能当作“从兵营出发直到交战和补给”的同一条端到端记录。 |
| 沙盘与回放 | 单位与据点显示轮末状态；主持人在原沙盘单轮或累计播放，可暂停、拖动、调速和跳转事件。攻击、命中和补给效果来自已记录事件，不重新结算。 | 隔离历史样例曾播放第 8 轮；当前用户局又报告第 3 轮起单轮异常，两者不是同一数据和入口，不能据前者关闭问题。 |
| 测试放置 | 本地手动测试允许将轮首放置记为首帧事件；保留上一轮末态，播放时直接出现，不伪造行走路径。 | 属于测试能力，不是正式模式指令，也不是关闭全部回放校验。 |

## 三、未实现、未验收与有意限制

| 状态 | 范围 | 对使用者意味着什么 |
|---|---|---|
| 未实现 | 全图自动规划道路、跨层连接与遇阻绕行 | 可提交有序途经点，但“不报坐标错误”不代表可达；只有局部已验证路线。给出终点不会自动规划过桥或绕路。 |
| 未作为本分支闭环交付 | 正式 Agent 双方自动下令、按总册结算并完成全图对抗 | 模型连通、知识检索和 Agent 工作台可用，与正式比赛就绪是两件事。当前交付标记为 `local_manual_test`、`competitive_ready=false`。 |
| 尚无相应全流程验收 | 从初始部署出发，连续完成交战、补给、修复并在实际页面验收到第 60 轮 | 已有各环节与局部路线证据，不足以承诺所有组合、所有地图位置或整场浏览器流程通过。 |
| 按决定暂缓 | 林底疏密、田间 Mud 语义、完整覆盖层裁剪和建筑实体 | 不根据材质名擅自决定通行，也不把暂缓项列为运行故障。 |
| 有意限制 | 回放权限、无人机空中服务 | 完整逐轮回放仅主持人可读；符合条件的悬停无人机可接受能源补给，不等于开放空中弹药或修复。 |

## 四、仍存在的故障与风险

| 优先级／状态 | 现象与证据 | 如何判定修复 |
|---|---|---|
| **P1 · 用户已遇到，根因待复现** | 当前对局第 3 轮起单轮播放不可见。此前主持人接口核查第 1～12 轮均可读；第 3、4 轮分别覆盖 120～180、180～240 秒，且有移动事件。不是只保存了前两轮。切换单轮时进度条的新下界超过旧上界、触发中间跳转，是代码疑点，尚非定论。 | 在普通项目入口加载同一局，按第 2→3→4→2 轮切换，核对请求、进度条上下界、首末帧及沙盘是否移动；另测累计播放后切回单轮。 |
| **P1 · 已确认，地图连接缺失** | P-05 两辆履带单位先在桥面移动，随后停住；仍有电量和移动意图。当前本地目录有地面、桥面两个有效层，却有 0 条跨层连接。从停点再朝目标移动触发 `BATTLE_SURFACE_OUTSIDE_VERIFIED_DOMAIN`。不是下一轮丢指令，也不是桥上完全不能动。 | 分开验证桥面内移动、从桥头驶入地面、从地面驶回桥面；不可达时页面应能区分“仍有指令但路线受阻”和“没有指令”。 |
| **P2 · 性能已实测，前端影响待逐例确认** | 一组 HTTP 验收单轮结算耗时 1.952～30.847 秒；另一次 21 个单位位置变化的只读试算约 278 秒。WebGL 通用请求只等待 12 秒。存在前端先报失败、后端仍在处理的窗口，但不能据此解释每次“提交中”。 | 同一请求键关联前端时刻、后端完成时刻和回执。覆盖超过 12 秒的轮次，确认页面最终能区分成功、失败和仍在处理，刷新或重试均不多推进一轮。 |

**验收顺序：** 演示前先复现单轮播放，再核对慢结算回执；已知需要上下桥的路线不要当作通过样例。合并 `main` 前，另跑一组原五点接口及旧回放调用方的兼容检查。
