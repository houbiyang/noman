### 6. 性能与资源验证

基础门槛维持六初始单位、六十步、无崩溃且可重开复盘。使用不会提前终结的专用稳定性场景，提前结束的成功任务样例不能替代60步轨迹。

扩展可沿测试策略探索六十、三百、六百单位，但这些是待确认样例，不是容量承诺或产品数量上限。记录单位、路线、报告、事件、资料和快照规模及实际硬件，分开测规则CPU、绘制、网络、模型与数据库耗时。停止条件按可用资源确认，不无依据填帧率或分位数。

真实模型评测与普通规则回归分开安排，调用预算到位再执行收费样例。不以模型替身快来证明真实建议响应快。

模型微调、强化学习、Neo4j／GraphRAG、独立向量数据库、所有文件格式 OCR、无限文档规模和任意模型部署不因本 SOW 纳入当前范围。知识检索与真实模型建议仍属于首版，不能以这些扩展未实施为由降为固定文案。

未确认的采购、云资源开通、付费调用、生产发布和长期维护继续独立确认。本文件不新增第三方依赖。鲲鹏及 OpenHarmony 按第 10 节执行后续范围，不以本机结果替代。

### 8. 模块依赖与阶段安排

### 13. 工作量、排期与费用估算规则

以第 6、7 节功能编号为最小管理单元，分别估算前端、后端／规则、数据、模型／资料、测试和交付工作。可以将耦合紧密的功能合并排期，但仍保留各自完成证据。

### 4. 实施顺序与职责

下表描述拟实施的职责顺序，**不是现存代码目录**。实际文件名与层级应在单批任务卡中按已确认接口确定；没有调用方前不创建空包。

| 2 | 会话与角色投影 | 从服务端会话确定对局成员及权限；分别生成主持人、红方、蓝方视图；覆盖无权、失视、历史观察和原文访问 |

| 5 | 持久化与迁移 | 根据数据库设计落实关系、约束、索引、快照与版本；迁移和演示初始化显式执行，服务启动不自动覆盖数据 |

| 8 | 运行与诊断 | 分开报告进程存活、数据库就绪、模型/索引能力；记录脱敏追踪标识、版本、失败和持久化结果；进行实际备份恢复演练 |

### 5. 数据、并发与恢复检查点

| 主题 | 实施检查 | 独立验证 |
| --- | --- | --- |
| 单局权威版本 | 所有命令以有效对局/分支/版本为依据；同一步双方变化统一结算 | 并发推进仅一次成功，交换动作处理顺序不改变结果 |

| 自动快照 | 与状态变化及事实记录保持一致的提交边界 | 提交后新进程能读取；持久化失败不返回成功 |
| 角色与探索 | 投影前过滤允许信息，报告来源及有效步可追溯 | 红蓝接口、智能体输入及引用均不含对方未授权状态 |
| 后台任务 | 领取、执行代次、暂停、失败和恢复状态持久化；模型等待不持锁 | 服务重启和租约过期后旧执行者不能覆盖有效结果 |
| 人工采用 | 核对本方资格、建议版本、当前世界与分支 | 重复处理可核对，过期建议拒绝且不会改变游戏 |
| 完整读档 | 校验格式、规则与资源版本后切换当前分支和恢复状态 | 失败保留原局；成功后所有角色同一步暂停，旧任务无效 |
| 复盘 | 读取已冻结帧、事实、结算及引用 | 跳步不重新调用模型、不按新规则重算、不改当前对局 |

运行态 Schema 的完整性、规范哈希、格式兼容及动作变体仍受 D-07 约束；手动存档命名、覆盖与保留受 D-10 约束。最小样例可以用于审阅，不能直接称为全量恢复契约。
