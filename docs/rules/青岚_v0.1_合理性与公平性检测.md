# 青岚 v0.1 合理性与公平性检测报告

日期：2026-11-11。对应规则：`qinglan-rules-v0.1`。

## 1. 总结：总稿可交付，正式公平验收不通过

| 维度 | 本次结论 | 证据边界 |
| --- | --- | --- |
| 规则完整性 | 已形成第一版；显式补齐时间、失能、核心、服务、复活与计划边界 | 文字审计，不是运行正确性证明 |
| 数值量纲 | 已检算的关键关系自洽 | 标准库脚本复算；不代表平衡性已验证 |
| 双方制度对称 | 数量、单位、资源、得分、复活、权限一致 | 对称参数不等于地理和计算机会相等 |
| 地图地理公平 | **未通过／证据不足** | 区域不对称；正式5点、核心与几何未批准；探针未代替正式导航 |
| AI计算机会公平 | **未通过／存在结构性风险** | 异步推理期间仿真继续，模型抖动和倍速影响任务采用时间 |
| 玩法平衡 | **待新模式首测** | 未运行完整新模式，不提供虚构胜率或“无bug”承诺 |
| 现有代码符合新规则 | **未通过／未实施** | 现行代码包含旧规则，本次未改执行器 |

**建议状态：设计总稿 v0.1 已定；地图与执行器发布门保持关闭。** 可以进入实现与定向平衡测试，不宜直接用于声称公平的正式竞技。

## 2. 检测方法与可复现范围

本次执行：
1. 检查本次对话已确认决定和最后覆盖关系，形成统一总稿。
2. 读取真实地图 JSON，统计部署区、节点、道路、桥梁、建筑与高程。
3. 对源道路无向图检查连通分量；在部署区与道路的线段交集上设置最佳预部署起点，Dijkstra计算平面图距离。
4. 以250米圆盘与非桥道路交集近似可占领位置，计算旧点和诊断探针的到达估计。不把桥面当中央陆地。
5. 分别比较“对应本岸近点”与“同一中央探针”，避免错误地要求双方到每个本岸点的时间都一样。
6. 检算时间、收入、击毁分、火力、补给、飞行续航。
7. 对核验脚本运行独立几何单元测试。未启动比赛、后端服务、Unity或真实模型。

复现命令（在仓库根目录）：

```bash
python3 docs/rules/tools/check_qinglan_v01.py --self-test
python3 docs/rules/tools/check_qinglan_v01.py
```

第二条仅向标准输出返回JSON，不修改地图或服务；本次输出另保存为 `青岚_v0.1_核验数据.json`。脚本不是新比赛执行器，不验证新规则的实际战斗实现。

### 2.1 必须遵守的局限

- 线段图没有证明道路整段合法、坡度可走、桥头连续、无树林／楼体侵占、宽度够单位通过。
- 不包含区外未来批准的所有接入段；因此是**当前道路子模型的乐观估计，不是完整新规则导航问题的严格数学下界**。
- 地图真实高度虽存在，诊断路径权重只用水平长度，不包含高度射线与实体占地。
- 对250米圆盘内所有非桥道路求最早进入，尚未应用最终有效地表掩码；可能将实际非法路段计入候选。
- 同圆中两条不相连道路可能分别成为双方最快入口，不等于双方实际能在同一合法占领表面交互。
- 使用连续秒数便于识别偏差；正式验证须按5秒步和完整单位占地复算。
- 仅检查少量探针，没有穷举全地图。探针不过线**不能证明地图无解**；探针过线**不能认证公平**。

### 3.2 部署区机会不对称

| 阵营 | x范围 | z范围 | 面积 |
| --- | --- | --- | ---: |
| 红 | 1000～1900 | 3200～10400 | 6.48平方公里 |
| 蓝 | 10000～11200 | 1600～8800 | 8.64平方公里 |

蓝方面积为红方 **4/3，约多33.33%**；矩形宽度1200米对900米，两者南北起止位置还错开1600米。

这是可部署空间的几何不对称，**不等于蓝方有效可建面积一定多33.33%，更不等于胜率多33.33%**。水域、坡面、建筑与道路分布会改变真实有效空间；红方可能在某些关键路线更近。自由兵营布局、返营往返和后方展开仍须分别验证。

处理：保持用户要求的部署区不变；不缩蓝区、不扩红区、不限制最优合法起点来掩盖差异。

## 4. 合理性与平衡压力

### 4.1 时长与据点经济

每点每5秒1分＝每分钟12分：

| 长期持有点数 | 每分钟收入 | 从收入开始到1500分 |
| --- | ---: | --- |
| 1 | 12 | 125分钟 |
| 2 | 24 | 62分30秒 |
| 3 | 36 | 41分40秒 |
| 4 | 48 | 31分15秒 |
| 5 | 60 | 25分钟 |

上述不含行军、首次30秒占领、被争夺时间、丢点或击毁分，不能当实际平均对局时长。3对2时每分钟净领先12分，但双方各自都在接近终局阈值；控制3点有优势，2点一方仍可凭击毁与反攻追回。

**压力：** 4点方既获得更多收入，又解锁不可回复的核心伤害，会产生优势滚雪球。由于1500核心耐久不是一轮轻易击毁，且失第4点立即保护，至少存在抢回一处据点的反制窗口。是否够用尚需实测，不擅自改成3点解锁或加伤害回滚。

### 4.2 攻击与核心

- 普通静止命中单位16伤害，移动9.6；静止命中核心10，移动6，不逐次强制取整。
- 100耐久地面单位需要7次16伤害命中；40耐久无人机需要3次；80耐久保障车需要5次。只是静止单发算术，不包含敌方还击、集火、服务或移动减伤。
- 满血核心需要150次静止地面命中。单单位60发只造成600伤害，至少3个满弹匣总量才足够；不是3单位就一定能接近并存活。
- 12个地面单位若全部持续合法攻击，需要13轮齐射，且最后一轮有过量伤害；首次命中到第13轮相隔120秒，不应误写为瞬间获胜或固定130秒。行军、保护和射击条件会延长。
- 核心8伤害／5秒＝1.6耐久／秒，与单个地面单位16／10秒的持续单位伤害率相同，但核心900米对地面攻核心600米有300米防御距离优势。
- 核心每步仅打一目标，大军集火可能承受得住，孤军接近会吃较多先手伤害；这是设计方向，不是平衡已验证。

### 4.3 基地与野外补给差距

| 项目 | 野外保障 | 兵营 |
| --- | --- | --- |
| 一目标耐久恢复率 | 2／5秒＝0.4／秒 | 50／5秒＝10／秒 |
| 一目标空弹补满60发 | 150秒 | 2次服务，共10秒 |
| 一目标空能源补满100 | 250秒 | 2次服务，共10秒 |
| 每来源每步目标数 | 1 | 4 |
| 同一目标多资源 | 每步只能一种 | 可同时恢复全部适用资源 |
| 资源来源 | 有限库存 | 无限储备、有限吞吐 |

仅“每目标同一资源速率”基地就是25倍；基地还有并补与四目标优势，不能把25倍误当整体保障能力比。接收服务不能射击，是重要限制，但可以轮换接收并集中防守。

**风险：高。** 不可摧毁兵营靠近核心或交通口时，可能形成高强度防守补给阵。已要求据点与任意兵营服务区隔离，但没有禁止核心与兵营服务区相近。不能用该据点隔离要求冒充已解决核心龟缩。首测必须测敌军在600米核心射程内能否持续作战，以及防守方在补给／开火间轮换的强度。

本版保持已选的50／50／50／50／60／50；任何降补给、加核心周围兵营禁放区或削减容量都需后续版本批准。

### 4.4 重复击毁与免费复活

一整编制每次被击毁总分：4×5＋12×10＋4×8＝**172分**。所有5点一分钟收入仅60分，因此重复歼灭的价值不可忽视；但172分不代表实际能一分钟消灭一整编制，不能据此推断真实每分钟收益。

免费满资源复活、不可摧毁兵营、最多15秒保护（且可提早解除）、所有再次死亡仍全额给分，形成围营刷分风险。出口等待减少强制生成即死，但敌军不封死出口、留出可攻击通路时仍可能反复击毁。

**风险：高。** 首测记录复活后30／60秒内死亡率、出口受阻时长、同一槽位贡献的敌方击毁分，以及是否存在劣势方无法脱离的刷分循环。仍保持原“无击毁衰减”决定，不偷偷加保护或减分。

### 4.5 能源与续航

- 无人机100能源、飞行维持2／分钟：不移动、不补给也最多50分钟；60分钟局不能无脑全程悬停。合法停靠免维持消耗和补给安排必须清晰展示。
- 地面单纯移动理论总里程12.5公里，移动射击更短；保障车10公里，无人机还受飞行时间影响。
- 本图宽12公里，不能把所有点都看作满能源可轻松往返。返程及救援必须纳入AI计划，且无默认自动撤退。
- 能源0不自动死，会留下无法主动移动的实体；若堵在窄桥可能长期阻塞。允许现场补能、敌方击毁，不自动挪走。应测友军能互穿移动但不能在其位置停车时的可恢复性。

**风险：中高。** 需要路线能源预估、任务受阻回执与救援能力，不应为“不卡住”而偷偷加免费能源或自动回收。

### 4.6 轮换裁决与局部机会

确定性轮换避免固定红先、固定低ID先，但有限局面中，关键点争抢恰好落在某个奇偶步，仍可能获得一次先机。它不是严格每次同时机会对称的数学证明。

核验需交换内部存储顺序、保持轮换游标重放，以及用等距到达的对称场景观察是否只有明确规则造成差异。敌军迎面冲突仍双方停下，不能用停车优先伪装推挤敌军的权限。

### 4.7 不可摧毁兵营的实体占位

兵营不挡子弹，已降低永久无敌掩体风险，但占地仍阻挡通行。自由布置与不可摧毁结合，可能永久挤占道路周边展开空间；“不得堵路”必须检查完整路线净宽、接近与安全停车，不只是中心不在道路上。

部署前应验证三座兵营放置后出口、核心两条攻击接近路和必要通路仍成立；否则以布局非法拒绝，不等对局发生后临时挪建筑。

## 5. AI机会公平专项

已确认：普通轮异步、仿真不等推理、每60仿真秒最多启动一次、整轮120现实秒、主持人可调倍速。

例：2倍速下，一方10现实秒返回约经过20仿真秒，另一方60现实秒返回约经过120仿真秒。两者都未超时，但第二方会更久依赖旧任务，并可能错过一个60秒启动窗口。

因此须区分：
1. **规则对称：** 同样超时／频率／权限；本稿满足设计对称。
2. **配置对称：** 同模型版本、工具、预算、硬件与连接条件；正式验收尚未提供。
3. **实际机会：** 推理／检索耗时、成功采用延迟、有效轮数、计划陈旧度；必须运行采样。

主持人改倍速还会改变每仿真分钟可用的现实推理时间。全部双方共同生效仍不能消除当时在途状态不同的影响。

**结论：高风险，不认证严格AI计算公平。**

不改变本次已确认机制，建议首测：
- 基线固定2倍运行，再单独测试改倍速，不混报为同一平衡样本。
- 记录每方每轮开始、返回、采用时间及其仿真时间，成功轮数、错过窗口数、故障恢复次数。
- 以相同策略注入0／10／30／60／120现实秒延迟，区分位置优势与推理速度优势。
- 红蓝检索库、供应商配置和工具隔离检查，管理员全局调试信息不可进入模型输入。
- 换边可用于定位原因，但最终必须验证单局地图公平，不能用双局总分掩盖地图缺陷。

若目标提高到严格比赛级计算机会一致，需新版本重新讨论锁倍速、同步规划屏障或固定采用延迟；本版不擅自采用。

## 6. 冲突审计与编纂补齐

本次已消解的旧新冲突：

| 冲突 | 总稿处理 |
| --- | --- |
| 旧不靠摧毁基地 vs 后续核心直接胜利 | 使用最后确认的条件性核心胜利；兵营仍不可摧毁 |
| 旧1分钟步／60步 vs 新5秒步 | 新模式5秒／720步，不照搬旧60子步逻辑 |

| 旧友军排队／退让 vs 友军移动可互穿 | 移动不排队，停车与敌军阻挡仍检查 |

## 8. 验收计划与改版触发条件

### 8.1 先做确定性规则测试

### 8.2 地图先于胜率

先补齐G-01～G-03；按最优合法初始位置分别测地面与保障到对应近点和中央点，要求时间差不超过 `max(5秒,较短×5%)`。独立路线必须在合并同坐标与真实几何后确认，不能数两条道路ID就声称独立。

### 8.3 平衡首测

先用可重复的相同策略、等计算条件做对称场景，再测试实际AI。建议首批至少每个阵营50局（总100局），报告置信区间、平局与技术中止比例，不只给一条胜率。

初步预警线而非公平认证：任一方胜率持续偏离50%、大量复活后短期死亡、长期出口／桥头堵塞、基地无限轮修形成不可攻破局面、4点后一边倒、能源搁浅导致长期无行动。样本不足、模型延迟未控制或地图门未过时，不用胜率宣布平衡。

定向压力测试应包括：围营刷分、兵营靠核心轮换补给、20单位集中停驻、敌军窄桥对撞、全保障缺能救援、无人机长局续航、4点保护来回切换、120秒推理延迟与改倍速。

### 8.4 需新版本批准的改动

目前不采用，只在实测支持时提出：缩放部署区、调整据点和核心位置、降低基地补给、限制兵营靠核心位置、加入击毁分衰减、改变核心解锁阈值、锁定比赛倍速或同步AI规划。地图坐标正式批准与数值改变都应明确版本，不能追改既有对局。
