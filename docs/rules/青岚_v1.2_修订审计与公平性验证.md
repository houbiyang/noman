## 2. 确认决定与关联清理

| 决定 | 本版有效口径 | 关联清理 |
| --- | --- | --- |
| 固定共同步长 | 每60仿真秒共同规划，每5秒同步结算 | 战斗、资源、占领、冷却、脱战、时限只看仿真时间；现实预算与播放进度不驱动规则 |
| 同时采用 | 同一权威边界、各自合法视图，等双方返回校验 | 先返回者不得先走、额外规划或看对方方案；每方整轮120现实秒包含修复 |
| 缓存实机演示 | 开播预填180秒，正常领先约2～3轮 | 只播已确认历史；耗尽暂停、补120恢复，提前终局排空；全UI按播放进度投影 |
| 集群简化 | 友军移动及停车不互挡，友军穿模暂缓 | 不再要求友军停车位竞争、最小间距、非重叠联合求解；不把部署试走当作战中实现 |
| 敌军阻挡 | 敌对地面单位仍按完整轨迹接触阻挡 | 不只查终点，不得相穿、推挤或无空间换位；静态地形和逐车能源要求不删 |
| 取消核心 | 不设核心实体、伤害、防御、观察或建筑胜利 | 删四点解锁、AI核心任务、核心情报和地图核心隔离；历史方案移入建议 |
| 固定编制 | 每方开局4无人机＋12地面＋4保障，共20单位 | 永久退场，不复活、不生产、不替补、不保护；兵营只部署与补给 |
| 胜负优先级 | 完整步末先全灭，再1500分，再3600秒 | 同灭比分；单方全灭立即负，即使该方同一步积分达标；同分平局 |
| 能源与服务沿用 | max(30,预计服务前消耗＋10)，兵营脱战15秒 | 六项50／50／50／50／60／50；野外仍每车每步单目标单资源2点，不隔空补给 |

全文复核覆盖：胜负、开局、单位表、移动、情报、据点、武器、缺弹、能源、死亡、流水线、AI、日志、地图、默认D-*、发布门G-*与36项未来验收条目。正文保留的“核心／复活／保护”等字样用于明确取消与版本边界，不是剩余的正向能力条款。

## 3. 交叉冲突与处理结果

| 编号 | 反例或冲突 | 本版处理 | 证据与限制 |
| --- | --- | --- | --- |
| C-01 | 红10秒返回，蓝120秒返回；画面倍速不同导致红多走一轮 | 共同采用屏障，推理不消耗仿真时间，双方指挥次数一致 | 参考规划／播放用例；真实调度和模型会话待验 |
| C-02 | 权威已胜但画面尚未播到，HUD或导出先显示胜负 | 全部展示投影至播放时间；终局后停止生产、只排空结果 | 参考事件投影过滤；未测试实际HUD／API／导出 |
| C-03 | 只查步末，两辆敌军高速换位或十字交叉 | 对双方同步运动轨迹查接触，在接触前合法停止 | 二维线性参考轨迹可拒绝穿越；不证明多车寻路、停车或任意折线路径正确 |
| C-04 | 领车进点或进100米服务圈，尾车自动享有资格 | 每辆独立判位置、实际能耗、完整停止、存活和距离 | 边界参考断言；未做真实队形控制器联调 |
| C-05 | 死亡后旧等待生成流程补回单位，刷分或重置脱战历史 | 开局固定名册，死亡永久退场，单位标识不复用 | 参考名册数量单调、重复死亡幂等；真实存储／队列待实现 |
| C-06 | 红末个单位死亡，但红同一步达到1500 | 全步收入／击毁分先汇总，随后红因单方全灭判负 | 正反阵营和末步参考例覆盖 |
| C-07 | 双方同灭且分数不同，沿用旧“双方核心同毁平局” | 同灭比较步末总分，同分才平局 | 与核心规则彻底分开；没有恢复核心路径 |
| C-08 | 点内敌军同一步被击毁，收入判定与争夺判定不一致 | 冻结移动后伤害前S_point，两者一致；同一步死亡不回溯 | 参考快照例覆盖；完整占领状态机与导航待验 |
| C-09 | 射击后5／10秒补给，或本步致死伤害后维修救回 | 15秒脱战，伤害先服务；本步受伤取消兵营服务，致死不可恢复 | 沿用参考服务用例；野外非致命受击不新增脱战门槛 |
| C-10 | 只剩能源0单位便提前判全灭，或补能当步追补占领 | 失能仍存活；步初能源0者本步补能不追补资格 | 存活数、点资格参考例；空中断电状态仍未定 |
| C-11 | 取消停车复杂度顺带允许穿墙、跨桥层或免费队形偏移 | 仅取消友军彼此排斥，静态占地、轨迹、能源与敌军阻挡仍保留 | 文档审阅；真实地形／桥梁／多车算法未运行 |
| C-12 | 将不可摧毁兵营继续当出生刷分源、核心防御源 | 兵营无生产、攻击或胜利功能；只服务存活单位 | 旧围营复活刷分分析删除，改查有限兵力封锁、补给和损耗 |

**未把“有文字规则”当成“已修好代码”。** 本轮未改运行实现；目前对上述冲突的处理是设计定向修订和有限参考断言，不是所有漏洞均已排除。

## 4. 数值合理性与有限兵力影响

| 项目 | 核验与判断 |
| --- | --- |
| 正常规划数量 | 0～3540秒共60个边界，5秒共720步；3600秒不再开普通规划。恢复轮覆盖失败轮，不是额外战术轮 |
| 单方击毁分上限 | 4×5＋12×10＋4×8＝172分；击毁是辅助积分与消耗路径，全灭本身另裁决，不可能靠同一单位再生累计到1500 |
| 据点得分节奏 | 每点12分／仿真分钟；3点36、2点24。只按收入，3点需41分40秒、4点31分15秒、5点25分钟；还应加行军和占领，并考虑压制 |
| 两点持有 | 纯收入1500需62分30秒，超过时限；但60分钟按总分判胜，不能据此断言两点方必败 |
| 占领驻留 | 中立点6个完整步＝30秒；敌点两阶段各30秒；新占领下一完整步首次收入，如30秒完成、35秒首次得分 |
| 补给速度差 | 兵营单项50／5秒，野外2／5秒，速率差25倍；兵营每步最多4人且须15秒脱战，仍可能有补给区龟缩与出口封锁 |
| 永久损耗 | 丢失射手、保障与侦察不能再补；可能滚雪球，但不在没有真实对局时擅改单位数值、击毁分或积分门槛 |
| 失能和最后存活者 | 失能、无弹药或只剩无人机仍不算全灭；已占点无人驻守仍保留，可能靠收入／时限获胜。此为本版明确后果，不自动引入投降或“无战斗力”判负 |
| 无人机续航 | 仅悬停满能源约50仿真分钟，飞行移动更短；30点触发线无法保证可达补给，更无法替代未确认的降落／断电规则 |
| 友军重叠 | 不加速占领、不扩大服务范围，但可能增加窄路通行和集中火力密度；需要实测，不假定双方同样可用就已平衡 |

## 7. 保留风险与待决缺口

| 风险 | 状态与影响 | 后续处理 |
| --- | --- | --- |
| 无人机空中断电／降落 | **未决规则缺口**；一般失能条款不决定空中状态转换，不能推导自动降落或坠毁 | 另行向用户确认流程、合法地表、能耗和受击资格；未明确前G-04相关运行验收阻断 |

| 仅无人机／失能者存活 | 可避免全灭，旧据点还能收入；可能形成追捕和拖时 | 统计此类终局及比分来源，保留当前全灭定义 |
| 有限兵力雪球 | 数量、侦察与保障损失不可恢复，先手局部优势可能扩大 | 对称策略与实际AI对抗；统计伤亡交换、剩余兵种与胜负路径 |
| 友军密集重叠 | 可能提升集中火力、狭路通过和补给附近密度 | 逐车射程／服务资格落实；暂缓友军穿模修复不意味着其平衡已证明 |
| 敌军实体算法 | 连续轨迹规则需要多车、低能源与静态地形联合合法停止；不能只做成终点碰撞 | 真实引擎实现后验证多体会车、追越、交叉及确定性；不要求恢复严格友军停车 |
| 不可摧毁补给区 | 高速修复、永久兵营与出口封锁仍可能偏向防守；没有复活刷分不等于不存在围营损耗 | 统计脱战间隔、受补后再战、封锁持续时间及往返成本 |

已失效的“复活后短期死亡率、同槽多次击毁贡献、复活待命暴露”不作为本版有效风险指标。改记单位首次且唯一死亡、永久损耗、无任务暴露、失能存活、服务可达、出口封锁及全灭／积分／时限三类胜负路径。

def energy_supply_threshold(estimated_service_cost):
    """只验证已确认估算的阈值算术，不证明路线、停靠点或服务可用。"""
    if (not isinstance(estimated_service_cost, (int, float))
            or isinstance(estimated_service_cost, bool)
            or not math.isfinite(estimated_service_cost)
            or estimated_service_cost < 0):
        raise ValueError('a finite nonnegative confirmed cost estimate is required')
    return max(30, estimated_service_cost + 10)

def swept_ok(a0, a1, b0, b1, same_side=False, clearance=5):
    """Linear, simultaneous 2D candidate trajectories only; no path solver."""
    if same_side:
        return True
    r = [a0[i] - b0[i] for i in (0, 1)]
    v = [(a1[i] - a0[i]) - (b1[i] - b0[i]) for i in (0, 1)]
    vv = sum(x*x for x in v)
    t = max(0, min(1, -sum(x*y for x, y in zip(r, v))/vv)) if vv else 0
    return sum((r[i]+t*v[i])**2 for i in (0, 1)) >= clearance**2


def area_member(position, radius, energy=1, kind='ground', start_energy=1):
    return (kind in ('ground', 'support') and energy > 0 and start_energy > 0
            and math.hypot(*position) <= radius)


def point(owner, stage, units):
    """Units: side, inside snapshot, fully stopped, survives, eligible.
    Reports income/contest/progress eligibility, not a complete capture FSM.
    """
    present = {s for s, inside, _, _, eligible in units if inside and eligible}
    contested = (len(present) == 2 or
                 (stage is not None and any(s != stage for s in present)))
    income = bool(owner and not any(s != owner for s in present))
    progress = {s for s, inside, stop, alive, eligible in units
                if inside and stop and alive and eligible} if not contested else set()
    return income, contested, progress


class Roster:
    def __init__(self):
        self.alive = {(side, i): True for side in ('red', 'blue') for i in range(20)}
        self.score = dict(red=0, blue=0)

    def die(self, victim, killer):
        if (victim not in self.alive or not self.alive[victim]
                or killer not in self.score or victim[0] == killer):
            return False
        self.alive[victim] = False
        self.score[killer] += POINTS[KINDS[victim[1]]]
        return True

    def survivors(self, side):
        return sum(live for (s, _), live in self.alive.items() if s == side)


def terminal(red_alive, blue_alive, red_score, blue_score, seconds):
    def compare():
        return 'red' if red_score > blue_score else 'blue' if blue_score > red_score else 'draw'
    if red_alive == blue_alive == 0:
        return compare()
    if red_alive == 0:
        return 'blue'
    if blue_alive == 0:
        return 'red'
    if red_score >= 1500 or blue_score >= 1500:
        return compare()
    return compare() if seconds >= 3600 else None
