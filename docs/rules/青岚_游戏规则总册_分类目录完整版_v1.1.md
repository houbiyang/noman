#### 1. 游戏目标与基本约定

<a id="main-1-1"></a>

##### 1.1 获胜目标

红蓝双方在同一地图争夺五个等值目标，利用自行配置的无人机、坦克和保障车完成行动。正常结束时计算：

**总分＝占点分＋击毁分＋期末资源分。**

本版基准上限依次为70、20、30分，合计120分。120为理论上限，不要求对局实际达到，也不是提前结束阈值。单方全部开局单位永久退场时，该方提前告负。

<a id="main-1-2"></a>

##### 1.2 兵种职责

- 无人机：侦察、移动、起降；不能攻击、占领或压制收入。
- 坦克：地面移动、观察、攻击、占领、争夺；消耗自身能源和武器弹药。
- 保障车：地面移动、观察、占领、争夺、提供能源／弹药／维修服务；没有武器。
- 三兵种没有额外编队属性加成。共享观察、前置任务和资源转移构成协作；不强制每次行动都必须三类齐全。

<a id="main-1-3"></a>

##### 1.3 术语

| 术语 | 唯一定义 |
| --- | --- |
| 仿真秒 | 游戏规则使用的时间，不等于现实等待秒数 |
| 一步 | 连续5仿真秒的完整结算区间 |
| 一轮 | 每60仿真秒一次的共同决策机会，包含之后最多12个执行步 |
| 存活 | 单位尚未永久退场，包括能源0、弹药0、停靠和待命 |
| 击毁 | 敌方合法攻击使耐久降为0的永久退场 |
| 故障退场 | 本版仅指飞行无人机能源实际耗尽造成的永久退场 |
| 完整停止／驻留 | 整个5秒区间没有规则位移，且持续位于要求的合法位置 |
| 在场快照 | 本步移动后、伤害前，按统一资格检查得到的圈内单位集合 |
| 点步 | 一个目标在一个完整5秒收入区间为一方形成的1笔有效控制量 |
| 规则位置 | 用于距离、移动、遮挡的权威位置；不采用图标或动画偏移 |
| 归属 | 目标当前属于中立、红方或蓝方，与有无驻军分开 |
| 公共储备 | 本方三座兵营共用的一份有限资源余额 |

“允许”仍须满足全部前置条件；没有对应能力的单位不能通过任务名称绕过限制。

<a id="main-2"></a>

#### 2. 参数分类、修改权限与版本

<a id="main-2-1"></a>

##### 2.1 三类参数

| 类别 | 举例 | 何时可变 | 规则 |
| --- | --- | --- | --- |
| 规则常量 | 5秒步长、伤害16、占领30秒、70／20／30分 | 发布新参数版本时 | v1.0对局中不可修改 |
| 开局配置 | 红蓝各类数量、部署位置、五点清单、控制模式 | 准备阶段 | 双方准备后修改会取消双方准备状态 |
| 动态状态 | 当前能源、位置、耐久、进度、库存、冷却 | 已完成规则步或明确边界事件 | 只能由本文指定事件修改 |

参数表中的“允许域”用于验证输入，不表示v1.0允许玩家随意改全部数值。修改规则常量后应使用新参数版本或明确标注自定义规则局；不能仍称为相同v1.0基准结果。

<a id="main-2-2"></a>

##### 2.2 配置权

用户作为对局配置者决定双方初始兵力。AI只能指挥本方已有单位，不能修改属性、创建单位、改变分数或增加公共库存。操作员仅能提交本方方案和本方投降。主持人负责准备及技术管理，进入正式对局后不能用管理权限给予某方额外行动。

地图、规则参数、初始名册、资源基准、模型和提示词版本在开局冻结。读取存档时使用原版本，不能用新伤害、分母或占领规则直接续算旧局。

<a id="main-2-3"></a>

##### 2.3 参数改变的连带影响

- 数量变化：重新生成名册、初始各类资源、敌方击毁价值分母及每单位折合击毁分。
- 单位容量／公共库存变化：重新计算本方各类资源基准；不会让已开始对局重新获得满额资源分。
- 计分点数、总时长或步长变化：必须重算控制容量，且不再是本版五点60分钟基准。
- 伤害、冷却、速度或补给量变化：发布新参数版本；不得仅修改显示文本。
- 规则版本发生变化：双方重新准备，历史对局结果继续保留原规则。

#### 6. 开局配置、兵营与部署

<a id="main-6-1"></a>

##### 6.1 编制规则

用户分别填写每方无人机U、坦克T、保障车L。U、T、L均为非负整数，U＋T＋L>0。可以相同或不同，不设置隐藏购买价格、固定20单位或强制比例。

数量为0允许，但能力后果照常：没有坦克就不能攻击；没有坦克与保障车就不能占点；没有保障车就没有野外补给。所有单位均为无人机的阵营不自动判负，仍按失能、全灭和时限规则处理，但应明确标注配置缺乏占点能力。

<a id="main-6-2"></a>

##### 6.2 初始状态

单位满耐久、满自身能源、满适用自用弹药，保障车满货物。无人机初始停靠；坦克和保障车初始停止。任务为空，武器首发已就绪，最近开火／受伤时间为空，无默认受伤。五点中立、占领阶段为空、进度0、点步0、击毁价值0。资源预估分为30，后续可以下降。

所有单位直接位于用户选定的合法预部署位置，没有出生保护期。初始位置不能进入计分点有效区域或非法静态占地。单位不从兵营无限生成。

<a id="main-6-3"></a>

##### 6.3 兵营规则

每方三座兵营赛前在本方部署区合法选址，战中不能移动、增建、攻击、夺取或摧毁。选址为合法开阔地或碎石平整面，完整占地局部坡度≤5%，不压道路、桥面、水域、森林覆盖、农田或实体建筑；每营需要可接近的服务锚点及范围内合法无人机停靠面。不能堵塞必要道路、桥头和通路。兵营本体阻挡移动，不阻挡视线／射线、不提供掩体；普通建筑按地图遮挡处理。

兵营不是存活单位、得分目标或观察源。敌方正常占住道路可能阻碍接近，但不直接关闭兵营功能。兵营公共资源不因敌方靠近转移归属；没有仓库、机场或装饰建筑提供免费补给。

<a id="main-6-4"></a>

##### 6.4 开局锁定

开局必须锁定：双方单位名册及唯一标识、数量、位置、兵营、五点标识及地表、规则版本、公共库存、资源分母、击毁价值分母、控制模式和模型配置。五点恰为5个、ID唯一、有效区域不重叠且不进入任何本局兵营100米服务区。

配置不合法则停留准备阶段，不以自动替换坐标或缩减数量修正。修改已准备配置取消双方准备；正式开始后不能追加配置。名字可以展示不同，但单位标识不能因改名重置死亡或得分。

公共库存仅随合法服务支出减少。各类已消耗量、已损失量单调累计；内部转移不增加这些累计量。有效击毁价值K单调累计，控制量N单调累计，剩余资源单调不增（按全方汇总），总分预估可以升降。

对局状态依次为准备、等待共同计划／确认、运行、技术暂停、终局或技术中止。等待计划属于正常规则屏障，不能当成一方的行动窗口。终局有正式胜负；技术中止只有统计，没有竞技胜负。

<a id="main-8"></a>

#### 8. 仿真时间与统一结算顺序

规则区间为[t,t＋5]。除准备、投降和技术管理边界外，战斗结果统一记在t＋5，不由动画帧率决定。

1. 共同边界采用同轮合法计划，检查单位步初资格。
2. 锁定服务接收意图，预留移动、可能移动射击和起降能源；互斥命令先拒绝或依已采用顺序取合法活动任务。
3. 双方同时处理移动与碰撞，扣实际基础移动能源、飞行维持及起降费用；移动射击额外能源此时只预留，第5项实际开火时才扣。空中断电在此永久退场。
4. 更新合法观察，冻结各点在场快照及旧归属。
5. 同时确定攻击，检查并扣除实际移动射击额外能源、扣弹，再汇总伤害。没有实际开火则释放额外预留。记录攻击死亡、击毁价值、实际开火／受伤时间及携带资源损失。
6. 处理仍合法的服务供需双方，核销库存并增加接收账户；新补能资格下步才恢复。
7. 更新占领阶段及归属，结算合格收入；快照中的压制不会被后来的死亡追溯取消。
8. 起降存活者完成状态转换，推进至t＋5，计算存活名册和三项分数，判全灭／时限终局。
9. 整步保存并提供观看结果；失败恢复到最后完整步，不保留半次转移或半次伤害。

同一步开始起飞／降落的单位，在第5步作为空中目标，在第6步不能接受服务；第8步才进入新稳定状态。下一步才能按新状态侦察或补给。

0秒首次规划，双方均完成才推进；规划等待、人工确认、缓存背压及技术暂停不增加任何规则时间。最后一步为3595～3600秒，完整结算后结束。

<a id="main-9"></a>

#### 9. 移动、阻挡与能源

<a id="main-9-1"></a>

##### 9.1 移动公式

```text
地面分段速度 = 基础速度 × 地表系数f × 坡度系数s
分段耗时 = 实际水平路径长度（米） × 60 / 分段速度
地面分段基础消耗 = 实际路径长度（米） × 基础每公里能耗 / (1000 × f × s)
本步所有路段耗时合计 ≤ 5秒；基础移动消耗为所有实际路段消耗之和
无人机不套地面f、s，按基础速度与移动能耗计算，并另扣飞行维持能源
坦克实际移动且开火时的移动消耗 = 基础移动消耗 × 1.25
```

无人机以及平道路上的坦克、保障车每步最大基础路程分别为200／3、100／3、25米。地面经过不同地表及坡面时分段使用剩余时间，不因跨边界重获5秒。按实际合法路径长度扣费，不按起终点直线距离；走多少扣多少。到达目的地后停止，剩余距离不转存下一步。转向不另收费，未执行位移不扣移动费用。

启用地形模块规定的地表与坡度倍率：例如平农田坦克速度200米／分钟、能耗16能源／公里；保障车为90米／分钟、100／3能源／公里。没有冲刺、倒车或伤残减速。坡度使用纵横坡最大值，桥面使用自身坡度，超过兵种上限即禁止，不以无限减速代替非法通行。

<a id="main-9-2"></a>

##### 9.2 合法路径

本方地面单位在本方部署区的合法地面可以移动；区外仅走合法道路、桥梁及地图核验的任务／服务接入段。敌方部署区不是本方自由越野区。道路双向共用，二维相交不能当作桥面与桥下连通。

无人机依合法空域移动，不依地面道路；可以飞越的区域不一定能停靠。没有合法路线时保持最后合法位置并报告受阻，不能传送到目标附近。

授权允许绕障时可在原目的地范围内找合法路线；路线成本按分段实际旅行时间选择，等时先取预计能源较少者，再优先合法道路，再按地图固定路径编号序列比较，不能随红蓝遍历次序随机选路。寻路只能使用本方合法信息，未知敌方阻挡不作为透视路径输入。

<a id="main-9-3"></a>

##### 9.3 阻挡和编队

友军移动和停车互不阻挡，但每个单位仍独立检查地图占地、敌方实体、位置、速度及能源。领车入圈不代表尾车入圈；编队调整真实位置要付真实路程，不免费瞬移。

敌对地面单位按半径及1米余量检查完整运动轨迹，接触前停止，不能互穿、推挤或无空间互换。已有合法占用不被轮换驱逐。无人机飞行无单位碰撞；停靠仍检查静态与敌方地面占地。

本步受阻后阻挡者在伤害阶段死亡，不补走本步余下路程；下一步残骸只显示，不阻挡、不遮挡、不提供减伤。受阻提示不泄露隐藏敌军身份、数量或精确位置。

<a id="main-9-4"></a>

##### 9.4 能源不足

计划前预留可支付的路程及合法停止点。部分能源只够走到较近合法位置就在那里停止；不足到达下一合法停止位置则不进入。不能停在墙、河、敌方实体内，不能透支成负能源。

坦克若具有本步移动射击意图，先用1.25倍率限制路程；最终不开火则只扣基础费用，未用预留释放，但不补走距离。移动消耗后能源为0，不能继续观察、开火、占点或提供服务。

移动阶段先扣基础费用；额外0.25倍仅预留。攻击阶段扣额外费用后必须仍有正能源，才能开火；若恰好耗到0则拒绝该次射击并释放额外预留，不扣弹、不重置冷却。本步已经发生的观察与在场快照使用基础移动后状态；合法开火不会使其能源从正数变0，因此不产生“快照合格但因射击耗到0”的矛盾。

地面单位停止不扣怠速能源。飞行无人机无论移动还是等待，都另扣维持能源。取消路线不返还已经消耗的能源，等待不积攒未来速度。

<a id="main-10"></a>

#### 10. 无人机起降与低能源

<a id="main-10-1"></a>

##### 10.1 状态转换

停靠→起飞中→飞行→降落中→停靠，每次起降各一个步。起降步不水平移动、不侦察、不接受服务；起降费用为1＋1／6＝7／6能源。支付后必须仍大于0。

起飞必须位于合法停靠点且上方空域合法。能源≤7／6时拒绝起飞，保持停靠、费用0。合法起飞第一个步完成后，下一步可以正常观察与移动。

降落必须位于当前批准停靠地面正上方，地表为道路、碎石、开阔地或农田中的合法停靠面、局部坡度≤5%，完整占地及敌方阻挡合法；森林覆盖、水面、泥地、屋顶、桥面本版默认不能停靠。不能把邻近100米范围当作免费降落位移。能源≤7／6或步初地面不合法，降落请求不成立，继续按飞行状态处理，只扣实际飞行维持；不能预扣未开始降落的1能源。已合法开始的降落若在同一步被敌方地面运动占住停靠点，则步末失败并保持飞行，已耗费用不退，按地形模块第11.2节处理。

合法起降遭受致命伤害则永久退场，已付费用不退。非致命伤害不中断合法起降。落地完成当步还不能补给，下一步完整停止才具备服务资格。

<a id="main-10-2"></a>

##### 10.2 飞行维持与故障

正常飞行步先预留1／6能源，再计算移动预算。能源不足或恰好只够维持、支付后成为0，在该步能源阶段永久退场；不再形成新观察，也不进入该步攻击目标集合。能源归零损失不产生敌方击毁价值。

停靠状态能源0不退场，可以接受合法补给和被攻击。飞行无人机不能隔空补给，不能免费应急降落、返航或回收。

<a id="main-10-3"></a>

##### 10.3 低能源阈值

```text
提示线 E_trigger = max(30, C_service + 10)
触发条件：自身能源 E ≤ E_trigger
```

C_service是以本方合法信息估算到合法服务位置并满足服务条件前的能源，包括路线、飞行维持、起降和已知等待。未知路程不当作0；超过满能源预算意味着安排不可行，不把阈值截为100。

提示本身不扣分。已有授权补给分支则执行；没有可行预案，不继续执行会突破阈值的深入移动，在合法位置等待下一共同决策。坦克静止观察／交火、已有驻留和接受补给仍按自身资格执行；30不是失能线。飞行等待仍耗能源，阈值不是必然救援成功保证。

服务完成后按既定后续任务行动，不自动创造新的目标。模型规划应计入下次共同边界前的耗能，不能把触线当成额外模型调用机会。

<a id="main-11"></a>

#### 11. 观察、隐藏信息与共享

<a id="main-11-1"></a>

##### 11.1 观察资格和时刻

初始0秒与每个5秒步移动后更新观察。来源必须步初存活且能源为正，移动后仍有正能源，并处于具有观察能力的状态。停靠、起降、能源0和退场无人机不新增观察；坦克与保障车按自身资格观察，缺弹不影响观察。

本方任意有效来源当前观察到目标，全方共享当前记录。多个来源不叠加距离、不加分。所有来源失效、目标超距或遮挡后只保留历史记录。来源本步后续死亡，其刚才取得的信息不抹除；如果这是唯一来源，步末记录转为历史，不作为下一步的持续可见资格。

<a id="main-11-2"></a>

##### 11.2 可见条件

目标须在观察半径内，并通过规则锚点的建筑／地形射线判断。双方自己的源和目标实体不自挡；普通建筑、地形阻挡，兵营例外不阻挡。模型在画面上很高或图标露出不代表规则可见。

无人机林外看林内目标：总距≤1400米，且观察线在目标所属连通林区内的累计长度≤600米；凹形林区内反复进入的段相加，不能每次重置。无人机自身在林内时使用1000米，不再额外叠600限制。林边算林内，相接林区合并；不把无关林区再叠加为额外扣距。移动地表与森林覆盖独立，林内道路不自动消除林内观察影响。坦克和保障车不额外受树林减距，但仍受普通地形遮挡。森林不减伤、不挡子弹。

<a id="main-12"></a>

#### 12. 攻击、伤害与击毁

<a id="main-12-1"></a>

##### 12.1 攻击条件

坦克必须同时满足：步初存活且正能源、移动后仍正能源、未锁定接受服务、弹药≥1、冷却已到期、目标是敌方当前存活单位、目标由本方当前观察覆盖、射手自身距离和射线合法、有已采用的攻击授权。

实际移动的射手还须支付额外移动能源后仍大于0；额外费用只随成功开火扣一次。没有另设静止射击能源费用，静止射手只要求当前能源为正。

任一条件不满足则该攻击取消，不扣弹、不重置冷却。目标在视野内但被射手前方建筑挡住仍不能射击。共享观察可以提供当前可见资格，不能扩大射程或穿墙。

<a id="main-12-2"></a>

##### 12.2 冷却和选敌

实际开火记录在步末u=t＋5。首次可以在5秒边界开火，之后最早15秒，再25秒；不存在“0秒预打一发”。换任务、目标、补弹、暂停或存档恢复不重置冷却。

指定单个目标的任务只对该目标生效；指定范围选敌的任务在范围内先取最近合法目标，再取耐久最低者，仍相同则按射手固定单位标识序列的持久游标轮换。射手每次实际开火后游标推进，拒绝的攻击不推进。该轮换不用于穿越敌方实体。

失视不朝历史坐标精确命中。弹药0暂停攻击及其接近移动，执行已有补给预案或等待；不会自动寻找另一个敌人、返营或临时增加模型规划轮。

<a id="main-12-3"></a>

##### 12.3 伤害公式与同步

```text
本次伤害 = 16 × (本步实际位移>0 ? 0.6 : 1)
伤害后耐久 = max(0, 伤害前耐久－本步全部合法伤害之和)
```

对所有合法攻击先统一确定、扣弹，再同步伤害。射手本步被击毁，不取消它已经合法的攻击；双方可以互毁。多发伤害合计只产生一次死亡，超量伤害不转移、不返弹。

本版无友伤、随机命中、暴击、弹道飞行延迟、穿透、溅射、伤残降速、持续燃烧或装甲方向。命中地面和空中单位的基础伤害相同，区别仅在目标射程及资格。

<a id="main-12-4"></a>

##### 12.4 永久退场与击毁记账

耐久到0，立即取消该单位活动任务和未完成服务，剔除后续行动资格，登记一次永久退场。残骸仅显示，不阻挡、不遮挡。单位名册不删除，不复用其标识生成新单位。

本方合法攻击使敌方死亡，给本方累计该敌方单位的原始击毁价值。共同造成击毁只计一次，记到阵营而非每个射手。没有首杀、连杀、助攻、按伤害比例分账或全灭额外奖金。

空中无人机先在能源阶段退场，则不进入随后攻击候选，本步不给敌方击毁价值；仍存活后被攻击致死则正常计分。历史上受过攻击不构成当前故障损失的追溯击毁归属。

死亡资源处理先扣本步已经打出的弹药，再把该单位所有剩余能源、自用弹药及货物记为损失。没有资源掉落、掠夺、保险返还或死亡恢复。

<a id="main-13"></a>

#### 13. 五点占领与收入

<a id="main-13-1"></a>

##### 13.1 资格

坦克或保障车在步初存活且能源>0、移动后能源>0、规则中心在有效区域及对应地表内且完整占地合法，即可进入在场快照。圈盘边界按中心判断，不要求全车都在圆内，但不得悬空、跨非法地面或用未批准桥层占领。缺弹不影响资格，移动单位可以在场压制，空中或停靠无人机均不参与。

实际推进还要求至少一个本方单位在整个步内停止于有效区，且伤害后存活。占领是合格驻留产生的区域规则结果，不要求单位任务名称必须叫“占领”；待命或服务中的合法驻留同样可以贡献。

<a id="main-13-2"></a>

##### 13.2 阶段转换

中立→本方：连续6个合格步，共30秒。敌方归属→中立→本方：连续30秒中立化，再连续30秒占领；完成中立化的那一步不同时增加下一阶段进度。

进度属于阵营，可由不同单位连续贡献；每步必须至少有一名完整驻留且存活者。换班没有完整驻留重叠的那一步会中断。单位数不加速，坦克和保障车占领速度相同。

每步若双方合格在场、或当前推进方的对方合格在场，本阶段未完成进度清零，旧归属不变。已完成的中立化不回滚。无对方但无本方完整驻留存活者，也清零未完成阶段。

本方归属且无敌方时，不启动“重新占领本方点”阶段，原归属保留。中立点原推进方离开，另一方独占完整驻留时可从0开始自己的阶段，不能继承原进度。

<a id="main-13-3"></a>

##### 13.3 收入规则

本步开始已归本方、整个步没有归属转换、在场快照无合格敌方，则该点为本方累计1点步。无需本方继续驻军。

敌方单独进入原主空点也会压制收入，不要求两边都驻军。途中穿过但在快照时已离开的单位不压制。敌方在快照中合格、后被同一步伤害击毁，仍压制本步；下一步重新判断。

当步末取得新归属，下个完整步才可收入。原驻军死亡不自动丢失归属；原主全灭时本步仍完整计入合法收入，然后按全灭结果结束，不产生之后收入。

<a id="main-13-4"></a>

##### 13.4 典型状态表

| 步初归属 | 本步情况 | 阶段结果 | 收入 |
| --- | --- | --- | --- |
| 中立 | 无合格单位 | 无阶段／清零 | 无 |
| 中立 | 仅红方完整驻留 | 红占领＋5秒，满30转红 | 本步无 |
| 中立 | 红蓝合格在场 | 清零，保持中立 | 无 |
| 红 | 无合格蓝军，红也无人 | 保持红 | 红＋1点步 |
| 红 | 蓝军当步进入且移动 | 蓝无进度，保持红 | 被压制 |
| 红 | 仅蓝完整驻留 | 中立化＋5秒，满30转中立 | 被压制 |
| 红 | 红蓝合格在场 | 蓝未完成阶段清零 | 被压制 |

<a id="main-14"></a>

#### 14. 野外服务与兵营补给

<a id="main-14-1"></a>

##### 14.1 共同条件与互斥

来源与接收者本步完整停止，处于同一连续合法服务面，中心距离≤100米，连接不被墙、水、桥层、陡坎或支撑间隙阻隔，完整停驻占地局部坡度均≤10%，且已有服务请求。服务面可跨道路／草地标签但不能跨不相连地表。无人机必须从步初就处于停靠状态并满足更严格的5%停靠限制。服务提供者步初和移动后必须自身能源>0；接收者可以能源0。地形不改变合法服务吞吐，非法则本步交付0、不扣库存。

**每个单位每步至多担任一种服务角色：提供者或接收者。** 接收者仅有一个指定来源，提供者遵守自己的吞吐上限。保障车不能同一步从另一辆车接收能源并向第三辆车提供服务，不能相互循环补给；冲突请求不得采用。此条统一堵住旧稿只限制兵营转送的遗漏。

接收服务者本步不能移动或开火；提供者不能移动。服务意图在攻击前锁定，后来失去服务资格也不补发攻击。合法完整驻留服务可以占领，但兵营服务区与占点有效区不得相交。

<a id="main-14-2"></a>

##### 14.2 请求与实际交付

野外请求指定来源、接收者、资源类型，以及“累计数量”或“目标余额”之一，不同时混用。累计数量按实际交付扣剩余；目标余额每步按当前缺口计算，达到目标结束。维修目标不得超过耐久上限，弹药数量为整数。

```text
数量请求交付 = min(本步上限, 来源库存, 接收容量缺口, 尚未交付数量)
余额请求交付 = min(本步上限, 来源库存, max(0, 目标余额－当前余额))
```

库存0是等待，不伪装完成；目标已满足则以本次交付0结束，不占实际吞吐名额。每辆保障车每步1目标、1类别、最多2点；不能同时补2能源和2弹药。车载能源补对方自身能源，弹药只补坦克自用弹药，材料用于恢复耐久。

保障车可以给其他保障车补自身能源或耐久，不能野外装货物，不自我服务，不给敌方服务。不存在补给损耗，实际转出与转入同量；维修例外是材料被消耗、耐久增加，耐久不是资源。

<a id="main-14-3"></a>

##### 14.3 伤害与取消

先伤害后服务。非致命伤害不取消野外服务；来源或接收者死亡取消交付。资源只在成功交付时转账，不提前扣给“在途”账户。服务失败不扣来源库存；来源本步死亡，其仍有库存记为死亡损失。

兵营接收者当步受到正伤害，最近受伤时间记为本步边界，不能立即补给。无效攻击或0伤害不刷新计时。服务被取消，不退此前其他步已经成功交付的资源。

<a id="main-14-4"></a>

##### 14.4 兵营脱战与六类补充

在服务边界u，两项非空时间戳均须满足：u－最近开火≥15、u－最近受伤≥15。初始空值不制造等待惩罚；但仍要求本步完整停止和有效请求。单纯等待现实时间不会增加脱战。

兵营请求可指定需要补充的类别和目标余额，未选类别不处理。默认“补满”表示所有适用类别到上限。处理顺序固定为自身能源、自用弹药、耐久、货物能源、货物弹药、货物材料，使用第5节各项上限。

公共能源同时支持自身及货物能源；公共弹药同时支持自用及货物弹药；公共材料同时支持维修与材料装载。每类支出均实际扣账，不能免费维修。某类别耗尽不阻止其他有库存的类别交付。

<a id="main-14-5"></a>

##### 14.5 排队和多个兵营抢同一库存

每单位只登记一座营；完整合法停止、在范围内且有需求时进入队列。先按连续登记的仿真时刻先到先服务；同一时刻按固定单位标识的持久循环游标排序，有实际服务者推进游标。

三营候选进入同一个本方排序，逐个扣公共库存，再检查各营最多4人。某营满额跳过该营其余候选，其他营可继续。部分交付也占1名额；全满或所有需求本步都不能交付者不占名额。

移动、离开范围、改营、取消请求或死亡清除排队资历；再次进入重新计时。仍完整停止但脱战不足或库存暂缺，不占本步名额，也不清除既有登记时刻。刷新同一个等价请求不获取新优先级。任务类型改变先取消原请求再登记。

<a id="main-14-6"></a>

##### 14.6 服务后的资格

接收补弹或能源的单位最早下一步移动、攻击、观察或恢复其原先不具备的占领资格。步初已有正能源且完整驻留的接收者仍可占领。接收服务不自动取消冷却、最近开火、最近受伤或历史任务。

<a id="main-15"></a>

#### 15. 资源账本与守恒

<a id="main-15-1"></a>

##### 15.1 开局基准

每方U、T、L取其实际配置：

```text
初始能源 E0 = 100×(U＋T＋L)＋200×L＋1200
初始弹药 A0 = 60×T＋120×L＋600
初始材料 M0 = 100×L＋200
```

双方分别用自身基准计算资源比例，不把较大编制的原始余额直接判为资源表现更好。采用本版公共储备后，三类基准都大于0。自定义参数若让任一计分类别分母≤0，拒绝作为本版有效计分局，不自动重分权重。

<a id="main-15-2"></a>

##### 15.2 哪些账户计分

存活单位自身能源、存活坦克自用弹药、存活保障车三类库存、本方公共储备全部计入。能源0的存活单位仍有的货物和弹药计入；堵路或暂时不可到达不自动打折。单位耐久、兵营数量、单位存活数量、已发出的请求和历史转账额不计资源。

每份资源只存在一个账户。没有资源寄存、逆向卸货到兵营、野外货物互装、丢弃拾取、阵营转移或跨类别兑换。服务结束后同类全方总量不因转移而增加。

<a id="main-15-3"></a>

##### 15.3 逐类守恒

```text
期末余额 = 初始余额－实际消耗－永久损失
```

能源消耗包括移动、飞行维持和起降；弹药消耗只包括合法开火；材料消耗包括合法维修。死亡账户剩余记损失，已经耗掉的部分不再记一次损失。无人机断电耗尽能源记为消耗，剩余其他资源为0或实际损失，不重复记能源。

收到服务的资源增加与来源减少同时生效；失败双方都不变。外部注入、自动再生、管理员改数会使对局成为非标准或异常，不靠截到上限伪装账目平衡。

<a id="main-15-4"></a>

##### 15.4 容量检查

每账户0≤余额≤容量，全方剩余还须≤存活账户容量之和及初始基准。单位被毁后，公共储备不变，但该单位容量永久消失。不能只检查“余额没超过初始值”就认为正确。

例：初始6无人机、10坦克、3保障车，能源基准3700。若损失2无人机、3坦克和1保障车，剩13单位与2辆保障车货物能源，能源总容量最多13×100＋2×200＋1200＝2900。期末填2960即不合法，即便2960低于3700。

<a id="main-16"></a>

#### 16. 三项得分与权重

<a id="main-16-1"></a>

##### 16.1 占点分

```text
N = 本方五点累计有效控制点步
占点分 C = 70×N／3600
```

每点每5秒折合7／360分；每点每分钟7／30分；每点有效控制30分钟得7分。只累计整数点步，最后或显示时换算，不把每步先舍入再求和。

五点全程60分钟的数学上限为70，但中立开局有行军与占领时间，通常不能取得理论满分。中立和争夺导致的空缺不补给任何一方。

<a id="main-16-2"></a>

##### 16.2 击毁分

```text
敌方开局价值 V = 5×敌方无人机数量＋10×敌方坦克数量＋8×敌方保障车数量
K = 本方合法击毁的敌方单位原始价值总和
击毁分 D = 20×K／V
```

V开局冻结且>0。对方非攻击退场或本方伤亡不改变V。库存已空的保障车仍值8，残血坦克仍值10；没有按耐久折价。一个单位最多一次贡献价值，K≤V。

例：敌方6／10／3，V=154；本方击毁2／3／1，K=48，D=960／154≈6.2338分。5／10／8是原始价值，不是直接加到总分的固定5分／10分／8分。

<a id="main-16-3"></a>

##### 16.3 资源分

```text
资源分 R = 15×Eend／E0＋9×Aend／A0＋6×Mend／M0
总分 S = C＋D＋R
```

资源正式结算仅一次。过程中显示当前余额换算的预估值，会随消耗下降；保留一份库存10分钟不会每步重复赚分。信息、补给、维修、伤害和最终点归属无独立加分。

<a id="main-16-4"></a>

##### 16.4 权重后果

完全不占点、不击毁且保留全部资源可得30分；资源管理可以抵消部分占点劣势。击毁既增加己方D，也可能通过库存损失降低对方R；两项分别记账，不额外再扣一次“死亡惩罚”。

正常结束比较总分，因此不能承诺占点稍多必胜。权重已经明确为70／20／30，不在某局赛后再归一化到100，也不临时将资源只当同分判据。

<a id="main-17"></a>

#### 17. 任务、协作与冲突

<a id="main-17-1"></a>

##### 17.1 任务条件与状态

每个任务明确执行单位、动作、目的地或对象、授权范围、完成条件、前置任务以及允许的后续分支。没有任务的单位待命，但仍自动受到观察、伤害和区域驻留规则影响；不存在无任务就隐身或无敌。

任务状态为排队、等待、执行、完成、失败、取消。前置未完成为等待；前置失败／取消导致依赖失败。前置本步刚完成，后续最早下一步检查；环形依赖、不存在的单位或跨阵营控制请求拒绝。

等待不等于失败：道路暂阻、库存不足、冷却未到可等待。目标死亡使针对该目标的攻击任务结束并记录目标退场；不得自动切换未授权目标。开火范围任务可按原授权选其他合法目标。

<a id="main-17-2"></a>

##### 17.2 完成的具体含义

| 任务 | 完成条件 |
| --- | --- |
| 移动 | 到达指定合法终点及地表；不能用“距离差不多”当完成 |
| 观察一次 | 在合法观察时刻执行完成，结果可以0条；不自动满足“发现某物”的条件 |
| 占领指定点 | 指定归属已实际形成；单纯到达或中立化不算完成 |
| 持续守点／巡查 | 到明示的结束仿真时刻、取消或终局，不因短暂无人入侵自动完成 |
| 数量服务 | 实际累计交付达到请求量 |
| 目标余额服务 | 接收目标类别达到请求余额；后续再消耗不撤销已完成历史任务 |
| 等待 | 经过指定数量完整仿真步；现实等待不抵扣 |
| 起飞／降落 | 完成合法状态转换且单位仍存活 |

<a id="main-17-3"></a>

##### 17.3 互斥与兼容

| 动作组合 | 裁决 |
| --- | --- |
| 坦克移动＋开火 | 允许，伤害和移动能源按倍率 |
| 驻留占领＋开火 | 允许，依占点与攻击各自条件 |
| 驻留占领＋接受野外服务 | 允许，不移动、不射击 |
| 保障车驻留占领＋提供服务 | 允许，仍须正自身能源 |
| 移动＋提供／接受服务 | 不允许，包括当步刚到达 |
| 接收任何服务＋提供任何服务 | 不允许，同一步不能连锁转送 |
| 起降＋水平移动／侦察／服务 | 不允许 |
| 一个坦克同一步攻击两个目标 | 不允许 |
| 两个不相容的移动目的地 | 新方案须明确替换或排队，否则冲突拒绝 |

取消任务不返还过去已耗资源、已走路程和已经发射的弹药。任务刷新不重置射击冷却、脱战、排队资历或占领进度；进度是否重置只由实际驻留条件决定。

<a id="main-17-4"></a>

##### 17.4 三兵种联动边界

无人机的当前观察可以供本方坦克使用，但坦克仍独立检查距离和射线。坦克消耗弹药后可通过服务恢复，保障车自身也需要合法续航与库存。一次服务不自动派出其他车辆，一次新观察不自动生成新战略任务。

玩家或AI可在既定任务中预授权条件分支，由每5秒执行器检查；这不产生额外推理轮。三类没有强制固定队形、固定人数、免费护盾、临近加成或“侦察一次就允许永久攻击”的关系。

<a id="main-18"></a>

#### 18. 人工确认与AI对抗

开局选择并冻结一种模式。人工确认模式：AI提出方案，本方操作员采用或驳回，双方完成本轮处理后共同推进。等待期间不行动；不设静默超时自动判负。驳回后保留仍合法旧任务，未有任务者待命。操作员主动改令也只能在共同边界，不绕过60秒间隔。

AI自动模式：双方每轮从同一权威时刻的各自合法视图规划，整轮120现实秒，先返回者等待。允许一次格式修复，仍在原120秒内；120秒内完整返回可接受，超过则失败。合法独立任务部分采用，非法任务及依赖拒绝；不得把拒绝错误变成隐藏敌情提示。

任何一方失败，两方该轮均不采用，进入技术暂停。技术恢复从最后完整提交时刻开始，各自合法视图同时重试，最多2轮；失败继续暂停或由主持人终止为技术中止。成功恢复只覆盖当前待采用轮，不在同一边界多给一次普通规划。

模型、提示词、角色数、工具和预算配置冻结；公平比较配置应双方相同。不同模型可作为比较实验，但须明确记录，不能把异构能力差异称为纯规则差异。主持人的全局调试数据不得流入任何一方模型或私有检索库。

<a id="main-19"></a>

#### 19. 胜负、投降与中止

<a id="main-19-1"></a>

##### 19.1 完整步末顺序

1. 双方全部开局单位退场：比较本步末S，高者胜；同S比较N，多者胜；同N平局。
2. 仅一方全部开局单位退场：该方负，另一方胜，不按历史领先改判。
3. 双方仍有存活单位且到3600秒：比较S，再N，再平局。
4. 其他情况继续，不因占满五点、消灭全部坦克、只剩无人机、双方失能或达到某个分数自动结束。

能源0和弹药0未退场单位计存活，兵营不计。全灭包括合法攻击与空中断电造成的退场。全灭不额外加分，依实际本步K计击毁。

<a id="main-19-2"></a>

##### 19.2 提前结束的比分

提前终局仍使用控制容量3600、本局固定E0／A0／M0和敌方V。不能把20分钟结束重新按20分钟满分计算，也不补剩余时间的收入。结果区分结束原因与统计分数：全灭负方可以有较高统计分，胜负仍按全灭条件。

<a id="main-19-3"></a>

##### 19.3 投降和技术中止

投降仅由本方有权操作员明确确认，下一尚未开始的步边界处理；已开始的步先完整结束，若已经全灭或时限终局，正式结果优先。单方投降即负；同一边界双方均投降记双方投降平局，不比较临时分数。

关闭网页、断线、模型超时不是投降。主持人测试性停止、不可恢复故障、结算账目异常导致的中止，不发布竞技胜负，保留统计并说明原因。不存在静默把领先一方宣布获胜。

<a id="main-19-4"></a>

##### 19.4 僵持

双方都无弹药、无占点能力、永久堵路或全部地面失能，只要还未全灭就继续至时限，或通过明确投降结束。暂停不算僵持时间。本版不设置未定义的“若干分钟无战斗就自动平局”或消极行为扣分。

<a id="main-20"></a>

#### 20. 保存、恢复与观看

保存必须包含规则及地图版本、初始名册和分母、所有余额、消耗／损失累计、位置和层、耐久、任务、起降状态、冷却与脱战时间戳、占领阶段与进度、点步、击毁记录、排队和选敌游标、完整步标识与结束状态。

恢复从最后完整步开始，现实离线时间不补收入或能源。重复提交同一事件读原结果，不再执行；旧分支、旧轮或死亡单位的迟到命令不得改当前分支。载入旧存档另开分支时，之后的事件独立累计，不能合并不同分支成绩。

权威时间T表示已确认规则时间，播放时间P表示已经展示到的时刻，缓存B=T－P，必须0≤P≤T≤3600。开播目标B=180；仅在规划边界且B≤120时启动下一轮，正常最高180。

每个播放步起点定速：B≥120为2倍；60≤B<120为1倍；0<B<60为0.5倍；B=0停在最后确认时刻。耗尽后补到120再继续，若已终局则直接播放全部剩余。提前终局时不为凑缓存制造额外规则步。

对局画面、单位详情、日志、比分和结果通知都投影到同一个P，不提前显示权威未来事件。AI仅使用合法权威快照，不靠观看缓冲额外获取决策。播放不会回写规则，不重新产生攻击、补给或得分。

#### 21. 数值精度与规则不变量

<a id="main-21-1"></a>

##### 21.1 合法参数与输入

数量、单位标识、点标识、步数和弹药必须满足整数／唯一性约束；不接受负数、无穷大、非数值或把空值默认为合法正数。几何坐标须在地图内、地表存在。有效目标数恰为5，每方名册至少1个存活开局单位。

耐久上限、能源容量、速度、时间间隔和距离半径都必须为有限正数；货物容量和吞吐不能为负，自用弹药仅坦克非零。所有持续时间与控制时长使用5秒整数倍。计分分母严格大于0，权重非负；采用本文标识时必须使用本文基准权重及值。

自定义编制只修改数量，不自动按多配坦克降低其耐久，也不自动按少配保障车提高补给速率。任何此类平衡修改必须另有版本，不能作为隐藏参数。

<a id="main-21-2"></a>

##### 21.2 参考计算精度

本文公式按精确数值定义：例如1／6飞行能源、100／3米路程预算、9.6伤害不能在每一步粗略取整。规则资源、耐久和分数用精确十进制／有理累计或与其等价的确定性算法，显示舍入不回写状态。

规则位置以0.001米网格记录；路径累计长度精确到0.001米。低于该网格的连续运动预算余数随同一未中断路线保存，不能每步丢弃造成系统性减速。遇到停止、受阻、到达或取消时不得保存未走的整步路程为后续速度，低于网格的舍入余数也同时清除。路径网格属于计算规则，0.01米求交容差不用于扩大攻击或服务距离。

将距离输入能耗公式时，以已实际完成并记录的累计路径增量计算；内部路径切分不能重复舍入同一路程收费。正式终局以未舍入分数比较；显示并列需提供原始点步、击毁价值及资源比例解释。

<a id="main-21-3"></a>

##### 21.3 必须一直成立的关系

1. 任意账户余额介于0与该账户容量之间；死亡账户余额转损失后不再参与期末合计。
2. 每类资源初始量＝当前有效余额＋累计消耗＋累计损失。
3. 任一点任一步双方合计最多1点步；任一步五点合计最多5；全局双方点步合计≤3600。
4. 每方有效击毁价值≤敌方开局总价值；同一敌方单位最多计一次。
5. 0≤C≤70、0≤D≤20、0≤R≤30、0≤S≤120。
6. 存活数＋累计永久退场数＝本局固定名册数，兵营不参与该等式。
7. 所有阶段进度只能是0、5、10、15、20、25；达到30的边界完成阶段，不能作为未完成状态保存31秒等值。
8. 退场、正式终局、已完成得分记录不可因普通刷新撤销或重发。
9. 单个接收者每步一个来源，任一保障车每步不能既提供又接收服务。
10. 播放时间不领先权威时间，当前分支不混入其他分支的事件。

违反不变量表示规则／数据异常，应停止正式结算、保留最后完整合法步和差异；不能通过强行改成上限、补虚构消耗或删记录使结果“看起来正常”。

#### 22. 连续算例

以下为规则算例，明确假设合法路线、观察、任务和服务位置均已满足，不代表实际地图已运行这些场景。

<a id="main-22-1"></a>

##### 22.1 自定义编制如何影响开局参数

用户为一方设置6无人机、10坦克、3保障车：

| 派生量 | 计算 | 结果 |
| --- | --- | ---: |
| 单位总数 | 6＋10＋3 | 19 |
| 全部自身能源 | 19×100 | 1900 |
| 保障货物能源 | 3×200 | 600 |
| 初始全方能源E0 | 1900＋600＋1200 | 3700 |
| 初始全方弹药A0 | 10×60＋3×120＋600 | 1560 |
| 初始全方材料M0 | 3×100＋200 | 500 |
| 原始总价值V | 6×5＋10×10＋3×8 | 154 |

若赛前增加1辆坦克：自身能源基准＋100，弹药基准＋60，总价值＋10，总数＋1，材料基准不变。若增加1辆保障车：能源基准＋300，弹药基准＋120，材料基准＋100，总价值＋8。双方重新准备后才按新参数开始。

<a id="main-22-2"></a>

##### 22.2 坦克移动开火

输入：坦克能源100、弹药60、冷却就绪，位于平坦铺装道路f=s=1，拥有移动和攻击授权。该步完整路程预算100／3米，参考连续路径上实际移动该距离，目标合法可见且射线通畅。其他地表须改用地形模块分段算例。

```text
基础能耗 = (100／3)×8／1000 = 4／15
移动开火能耗 = (4／15)×1.25 = 1／3
步末能源 = 100－1／3 = 299／3≈99.6667
步末弹药 = 59
本次伤害 = 9.6
```

实际位置网格下，路程按已记录增量扣费并保留不足网格余数，不能把每步永远当成33米。上式说明连续参考预算，具体单步路径记录以0.001米规则为准。

如果该步目标失视而未开火，只扣实际路程基础能耗，弹药仍60，冷却不更新。预留的额外费用释放，不补走更多路。

<a id="main-22-3"></a>

##### 22.3 无人机能源连续变化

参考输入：合法停靠、能源100，起降位置及中间飞行航线合法。

| 区间 | 动作 | 该步参考消耗 | 步末能源 |
| --- | --- | --- | --- |
| 0～5秒 | 起飞 | 1＋1／6＝7／6 | 593／6≈98.8333 |
| 5～10秒 | 飞行200／3米 | 移动1／3＋维持1／6＝1／2 | 590／6≈98.3333 |
| 10～15秒 | 在当前合法地面上方降落 | 7／6 | 583／6≈97.1667 |
| 15～20秒 | 合法接受能源服务 | 来源足够时增加2 | 595／6≈99.1667 |

最后一行需15秒时已经停靠，15～20秒完整停止且有来源；本方全方能源因转移不增加。坐标网格的实际路程误差按累计增量结算，不将显示小数当作精确余额。

边界输入：能源恰为7／6时不能起飞，仍停靠且不扣费；飞行状态能源恰为1／6时，本步维持后变0并故障退场，不被自动补成0.01或免费降落。

<a id="main-22-4"></a>

##### 22.4 占领、中断与恢复

蓝方在5秒到达红方空点。5～35秒六个完整驻留步完成中立化，35秒变中立；35～65秒完成占领，65秒变蓝；65～70秒无人压制，70秒获得第一点步。

如果红方在30秒在场快照进入，中立化尚未完成，蓝进度清零、点仍红，本步仍争夺无收入。如果红方40秒进入，35秒已完成的中立化不回滚，清空的是蓝方新占领阶段，点保持中立。

如果蓝方25秒已有20秒阶段进度，下个步原驻留者离开、新到者在30秒才到，而且没有其他完整驻留者，阶段清零；不会仅凭两人在不同瞬间都在圈内续接30秒。

<a id="main-22-5"></a>

##### 22.5 伤害与维修同一步

坦克步初耐久20，合法请求野外维修。受到16伤害后耐久4，再消耗保障车2材料，恢复到6。保障车材料从100变98，坦克不能在同一步既接受服务又开火。

如果坦克步初耐久16，受到16后变0永久退场，野外维修取消，保障车不扣材料；不能先维修到18再留下2耐久。同样的非致命受伤若发生在兵营接收者，本步失去脱战资格，不获得兵营维修。

<a id="main-22-6"></a>

##### 22.6 库存只够一部分

保障车货物能源0.5，坦克能源99，请求补到100。实际交付min(2,0.5,1)=0.5，坦克99.5，车载0。任务未完成，等待来源库存，不透支成−0.5。

公共能源60，两辆保障车均请求补满自身和货物，排序第一辆自身缺10：先补自身10，剩50；再给其货物最多50，公共能源变0。第二辆本步能源类交付0，但如请求其他有库存类别仍可能获得交付；没有把60同时发给两个兵营。

<a id="main-22-7"></a>

##### 22.7 射击后死亡的账本

坦克步初弹药10，本步合法开火1发后也被击毁。弹药消耗记1，死亡弹药损失记9，不能消耗1又损失10。对方得到本坦克10原始击毁价值，自己的已合法射击照常造成伤害。

##### 24.2 地图验收规则

五点有效区不重叠；不与本局所有合法兵营服务范围相交；每点坦克及保障车均有合法进入、停止和离开路线。两侧对应点与中央点分别检查从双方可选部署位置出发的最快合法到达时间；建议采用协作者公平目标：差值≤max(5秒,较短时间×5%)。

对应侧近点应有至少两条独立合法地面接近路线，不能把共享同一末端瓶颈的两条线视作独立。检查桥头、坡面、墙体、敌军接触、兵营出口和服务接入；无人机另验空域、停靠面及补给接近，不以地面连通替代。

地图包不得省略导致无法判定合法性的地表层或阻挡数据。达不到目标应标记地图未通过，不声称换边几局就已证明单局公平。单位数量对称也不自动证明地理公平。

### 青岚：地形与兵种影响规则

版本：地形模块v1.0｜日期：2026年11月13日

<a id="terrain-1"></a>

#### 1. 模块范围与采用关系

地形同时影响八类判定：通行资格、移动速度、移动能源、观察、射击遮挡、占点有效地表、服务接触、无人机起降及建筑部署。它不直接加减比分，主要通过实际控制时间与资源消耗影响成绩。

本模块替换主规则旧版“不启用地形和坡度速度倍率”的条款。五点数量、自定义编制、70／20／30计分、伤害16／9.6、30秒占领、每步5秒、服务吞吐和永久退场规则保持原定义。

本版不启用冲刺、快速移动、倒车倍率、随机陷车、地形减伤、高地射程加成、天气改变地表、桥梁摧毁或地形施工。旧测试代码有快速／倒车参数，不因此自动成为本模块能力。

地表“物理允许通过”不等于任意路线都获准：仍须满足部署区或地图批准的道路／接入走廊权限。不能因为坦克可通过疏林，就默认获得全地图任意林间越野能力。

<a id="terrain-2"></a>

#### 2. 地图数据的分层与单位

<a id="terrain-2-1"></a>

##### 2.1 一处位置必须明确哪些信息

| 数据 | 作用 | 缺失时处理 |
| --- | --- | --- |
| 平面坐标x、z及地表层标识 | 判定单位实际在哪一层 | 不允许以二维位置代替分层 |
| 支撑面高度、坡度与边界 | 移动、停车、部署和射线 | 缺失区域禁止相关地面操作 |
| 地表类型 | 速度与能耗系数 | 未知类型不可通行，不默认道路 |
| 允许通行兵种与走廊 | 判断路线权限 | 没有批准走廊不自动生成捷径 |
| 实体建筑、墙、桥面厚度 | 碰撞与遮挡 | 对受影响场景拒绝正式开局，不能当透明 |
| 独立森林覆盖范围 | 无人机观察与停靠 | 不用树木贴图推算精确规则边界 |
| 空域及禁飞区 | 无人机平面航线 | 不声明空域则不能认为全图无禁飞限制 |
| 可停靠面、目标地表、服务锚点 | 起降、占点和补给 | 没有明确绑定则不能执行对应动作 |

高度与长度用地图米，时间用仿真秒。坡度g采用高度变化与水平距离的比例，10%即0.10，不是10度。距离范围包含等号；数值容差不增加可移动空间或射程。

<a id="terrain-2-2"></a>

##### 2.2 必须分开的三层含义

1. **支撑地表层**：桥面、桥下地面可能在同一x、z，但高度、连接与可行性不同。
2. **移动地表类型**：道路、开阔地、农田等，决定移动成本。
3. **观察覆盖层**：森林和建筑遮挡，不能因为脚下是道路就消除头顶森林效果。

例如森林里的合法道路可按道路速度通行，但如果无人机规则位置仍在森林覆盖范围，其观察仍按林内规则。地图制作时若确有林间空隙，应明确从森林覆盖范围裁掉，不能运行中凭道路标签猜测。

##### 3.3 无人机飞越

正常飞行速度仍800米／分钟、移动能源5／公里，另加2能源／分钟维持。地面地表和坡度不减飞行速度。飞越水域、树林和建筑仅在地图空域允许时成立，不代表可在这些位置停靠。

无人机仍受禁飞区和地图边界约束。二维航线不启用高度调节或钻桥洞指令；不能通过输入更高／更低的美术高度绕过禁飞规则或观察规则。

<a id="terrain-4"></a>

#### 4. 坡度、横坡与桥面

<a id="terrain-4-1"></a>

##### 4.1 坡度取值

将支撑面沿路线的实际三角面或明确坡面边界分段。每段纵坡g_long为绝对高度差／水平路程；横坡g_cross为该段支撑面沿路线法向的绝对坡度。用于通行与倍率的g取二者较大值。

使用横坡是本模块补充的判定：不能沿陡坡等高线行驶，因为起终点高度相同就把整段当成平地。双方使用同一坡面数据与同一算法；上坡和下坡使用相同绝对坡度，不启用下坡回能或加速。

<a id="terrain-4-2"></a>

##### 4.2 坡度系数s

| g范围 | 坦克s | 保障车s | 处理 |
| --- | ---: | ---: | --- |
| 0≤g≤0.10 | 1.00 | 1.00 | 正常 |
| 0.10<g≤0.20 | 0.85 | 0.70 | 减速、单位距离更耗能源 |
| 0.20<g≤0.35 | 0.60 | 禁行 | 仅坦克可按合法路线通过 |
| g>0.35 | 禁行 | 禁行 | 不执行该路段 |

恰为10%、20%、35%分别按表中包含等号的档位处理。全段平均坡度不能掩盖局部陡坡；任何局部完整占地跨越不合法坡面，整条候选路线不能被批准穿过该处。

<a id="terrain-4-3"></a>

##### 4.3 桥梁专门规则

桥面使用桥面自身高度、纵坡、横坡和连接关系，不采桥下河床高度，也不因为类型是bridge就将坡度强制置0。桥头上桥／下桥必须有合法坡道及层连接；不存在连接时不得从桥下直接跳到桥上。

本版不设置桥梁承重或友军排队数量上限，仍检查单位半径、1米安全余量及敌军实体阻挡。净宽要求至少容纳单位直径加两侧安全余量：坦克6米，保障车8米；达到净宽还须检查转角、坡面与完整轨迹，不保证任意姿态都能通过。

桥面完整允许区域以外不能停车；不能把中心线在桥上、轮廓悬空判为合法。桥面无毁坏状态、无掉落伤害；非法走出边缘应提前拒绝，不先走出去再制造坠落。

<a id="terrain-5"></a>

#### 5. 速度、时间和能源的统一公式

对每一同地表、同坡度档位的合法路段j：

```text
实际速度 v_j = 基础速度 × f_j × s_j              （米／仿真分钟）
经过路段时间 t_j = 路段水平长度 L_j × 60 / v_j （仿真秒）
基础移动能源 c_j = L_j / 1000 × 基础每公里能耗 / (f_j × s_j)
```

地面一条路线总时间与能源分别为各段相加，不取整条路线平均地形。任意一段不可通行，则路线不合法；不能令分母为0继续计算。

一个执行步最多使用5秒预算。前一段用去2秒，则只剩3秒进入下一地形；不能每换一类地表重获5秒或重新获得全步距离。单位在精确地表边界跨过后才切换成本，不按整步终点地表给之前路程重新收费。

移动射击保持主规则：坦克先按本步所有实际路段基础能源之和的1.25倍预留；实际开火才扣额外0.25倍，未开火释放额外预留但不补走路程。伤害仍以本步有无实际位移决定9.6或16，不按地形另增减。

无人机正常飞行能源＝实际水平路程×5／1000＋本步飞行秒数×2／60；本版每个稳定飞行步计完整5秒。起降另按主规则付7／6能源，不使用地面f和s。

<a id="terrain-5-1"></a>

##### 5.1 混合路面与完整占地

通行是否合法检查单位完整扫掠占地及1米余量：只要触及禁行静态地表或离开支撑面，就不得批准穿越。成本由中心路径在支撑层上的地表决定，以免单位半径改变造成未定义的额外混合倍率。

中心路径恰沿两种允许地表边界行驶时，取两者较小f；进入其中一侧后使用该侧。合法铺装面与周边地表重叠标注时，使用已批准的真实支撑面分类；无明确分类的冲突不按ID顺序选择，应拒绝场景。

网格相邻对角之间若两侧被禁行地表阻隔，不允许中心点斜穿格角。路段任何中间位置都要合法，不能只检查起点和终点。

<a id="terrain-5-2"></a>

##### 5.2 数值稳定

沿规则几何的边界分段，再累计时间与消耗。不得由玩家添加更多路径点反复舍入来降低能耗；相同实际路线，不同指令切段应得到相同时间与累计费用。

规则位置与累计路径采用主规则的0.001米精度；不足网格的运动预算余数仅在同一未中断路线延续。受阻、取消、到达、主动停止不积攒未走的时间用于之后瞬移。显示两位小数不回写能源或路程。

<a id="terrain-6"></a>

#### 6. 路线权限、停车与受阻

<a id="terrain-6-1"></a>

##### 6.1 部署区与区外

本方部署区内可在已批准的合法地表自由选择路径，但仍受地表兵种资格、坡度和完整占地约束。区外走地图合法道路、桥梁和任务／服务接入走廊；走廊可以包含开阔地、农田或疏林，因此地表表仍有实际作用。

敌方部署区不自动成为本方自由越野区。可见的草地不等于存在授权走廊，地图必须明确通行区域。此版不扩大为全图自由越野，不因为AI提出路线就修改通行地图。

<a id="terrain-6-2"></a>

##### 6.2 路线选择

目的地与授权范围不变时，默认在本方已知合法地形中比较真实旅行时间，选时间最短者；时间相同选预计能源较少者，再相同优先铺装道路，再按冻结路径ID序列排序。导航使用新f、s与混合路段成本，不再只按直线或路长选最短。

需要估计总费用时沿同一候选路线计算，不允许显示预计成本采用道路系数、实际执行却采用农田系数而不说明变化。未知敌军可能使路线后来受阻，预计不承诺必达。

<a id="terrain-6-3"></a>

##### 6.3 停车和能源不足

地面单位可在其完整占地合法、坡度不超过本兵种通行上限的地方停止；停止本身不扣怠速能源。尚未授权停车的位置不得作为免费躲避障碍点。

能源或本步时间不足以进入下一合法停止段时，提前停在合法位置；可以保留少量能源。不允许走到水里、悬空或敌方实体内部后再宣布失能。未执行路程不扣费。

友军不互挡；敌军阻挡检查双方完整运动轨迹。受阻后不返还此前路程，不在同一步额外绕行超过剩余时间。隐藏敌方引起阻挡，只回报“前方受阻”，不返回其属性和精确位置。

<a id="terrain-7"></a>

#### 7. 地形对观察的影响

<a id="terrain-7-1"></a>

##### 7.1 高程与建筑

观察仍从主规则的支撑面上方2米锚点到目标锚点进行几何检查。山脊、地形实体和普通建筑挡住连线，则不可见；身处高地可能因实际几何获得不同可见区域，但不额外扩大1400／900／700米基础半径。

使用完整规则三角面／阻挡体相交，不能以每50米取一个样点漏掉中间薄墙或窄山脊。非目标实体相切视为遮挡；源和目标实体不自挡。几何容差不把墙体变透明。

兵营沿用主规则例外：挡移动、不挡观察与射线、不提供观察。普通城镇建筑不是兵营，不继承透明例外。地面看似城市街区的空地不额外加隐蔽值，建筑效果按实际几何逐个判断。

<a id="terrain-7-2"></a>

##### 7.2 森林参数

| 观察情形 | 无人机规则 | 坦克规则 | 保障车规则 |
| --- | --- | --- | --- |
| 来源与目标都林外 | ≤1400米 | ≤900米 | ≤700米 |
| 来源林外、目标林内 | 总距≤1400米，森林深入段≤600米 | ≤900米 | ≤700米 |
| 来源林内 | ≤1000米，不额外叠600限制 | ≤900米 | ≤700米 |
| 来源离开林区 | 下次观察恢复1400米基础值 | 不变 | 不变 |

所有格子都另查建筑、地形实体与来源资格。密林和疏林对无人机采用相同观察规则，区别主要在地面通行。林界算林内，相接森林合并。

为消除凹形森林反复进出时的歧义：林外来源观察林内目标时，沿观察线累计其穿过“目标所在连通林区”的所有线内长度，作为600米深入段；途中离开再进入同一林区不重置计数。与目标林区不相连的其他林区不另扣减，林外到林外不增加森林吸收。这是沿用简化模型后的明确边界，不模拟真实植被光学。

不引入地面单位树林隐蔽倍率，不因“看上去有很多树”增加隐藏概率。停靠或起降中的无人机仍不能观察；森林规则不会解除这一状态限制。

<a id="terrain-7-3"></a>

##### 7.3 历史情报

来源移动过坡顶、墙角或林边后失去观察，即停止更新隐藏敌人的位置和耐久。先前观察作为带时间历史保留，不能以地形后方旧坐标继续精确攻击。多来源中仍有一个合法当前来源时，可见状态保留。

<a id="terrain-8"></a>

#### 8. 地形对射击和伤害的影响

观察与攻击各自检查射线。无人机看到目标，不代表坦克能隔建筑或山脊命中。目标当前可见、射程合法而射线被遮挡，攻击拒绝，不扣弹、不重置冷却。

桥面是有厚度的实体遮挡体：桥上与桥下目标即使平面很近，射线也可能被桥面挡住。源目标所在面不自挡，但不能把整座桥的其他部位都排除遮挡。

森林本版不挡子弹、不提供减伤；普通单位和视觉残骸不挡子弹。普通建筑或山体要么阻断射线，使本次攻击不成立，要么不阻断，伤害按16／9.6计算，不存在“挡住一半所以伤害打五折”的隐含算法。

坡度只影响路程时间与能源，不影响坦克静止伤害、攻击间隔和射程；高地不增加伤害，低地不增加被命中概率。道路上移动与农田上移动只要发生实际位移，移动伤害均9.6。

<a id="terrain-9"></a>

#### 9. 地形对占点的影响

目标有效区＝250米候选圆与本点批准地表掩码的交集。仅在该支撑层内且单位完整占地合法，才可按主规则检查占领或压制。是否进入圆盘采用规则中心，不要求整辆车全部在圆内；但整辆车必须有合法支撑，不能半悬空。

水面、实体建筑、禁行坡面及未批准层从有效地表中排除。桥面默认不自动属于桥头陆地点，只有明确把该桥面层纳入目标时才可计入；不能因为名字有“桥”就推定桥上可占。

可占领还需可完整驻留：坦克可到达的疏林点不代表保障车也可到达。正式五点场景要求两种地面单位各有合法驻留位置和接入路线，避免名义上保障车可占点而整点地表完全不适配。

地形不加快或延长30秒占领时间；只通过到达、停止资格及争夺影响进度。道路上占点与农田上占点都每合格步＋5秒。无法通过的地表不允许用“待命在地图投影内”获得进度。

#### 10. 地形对补给和维修的影响

<a id="terrain-10-1"></a>

##### 10.1 新增服务地面参数

| 参数 | 基准 | 原因与适用范围 |
| --- | ---: | --- |
| 地面服务停驻最大局部坡度 | 10% | 双方完整占地各自检查；可开过陡坡不等于可在陡坡服务 |
| 无人机停靠最大局部坡度 | 5% | 起降稳定地面要求，见第11节 |
| 服务距离 | 100米 | 沿用主规则，不因坡度／树林扩大 |
| 服务速率地形倍率 | 1 | 合法则沿用吞吐，非法则0，不新增隐含降速 |

10%与5%为本次新增的游戏设计参数，不是已验证现实性能或当前代码既有值。局部坡度检查完整停驻占地涉及的支撑面最大坡度，不能只采中心一个点。

<a id="terrain-10-2"></a>

##### 10.2 合法服务连接

同时满足：供需双方完整停止、自身资格成立、中心水平距≤100米、同一连续合法服务面、两侧停驻坡度合格、接触连线不穿水域、墙、实体障碍、层断点或支撑面间隙。

合法服务面可以跨道路／草地等移动地表边界，不要求标签完全相同；必须确属同一连续可接触支撑面。高处和低处距离很近但中间是陡坎，不构成服务连接。桥上与桥下不能互相补给，两个河岸不能隔河补给。

连接按地图明确的服务可达面及其无障碍直连关系判断，不允许绕建筑很远、因为中心直线距离≤100就服务。无需让运输方实际走过连接段，服务本身不扣移动能源；它是接触资格，不是另一个免费移动动作。

<a id="terrain-10-3"></a>

##### 10.3 兵种能力差异

保障车不能进入疏林地表，因此不能把自己画到树林内服务。若坦克位于林边的合法地面，双方各自占地与同面接触连接都成立，允许从林外服务；不能跨墙、河或无法接触的林间障碍。

现场条件合法后，野外每步2点、兵营六项吞吐、15秒脱战、库存扣账均沿用主规则。不因农田额外扣材料，也不因道路加快服务。条件变化使本步不合法，则该步交付0，不扣库存，未完成请求等待或按其取消条件结束。

地图静态不变的情况下，单位不能本来服务中突然随机陷车。未来若加入动态天气或施工，必须另行版本化。

<a id="terrain-11"></a>

#### 11. 无人机停靠、起降和兵营选址

<a id="terrain-11-1"></a>

##### 11.1 停靠资格

候选停靠地表为批准的道路、碎石、开阔地或农田上的专门合法停靠面，局部坡度≤5%，完整2米半径占地和1米安全余量合法，上方空域允许。

森林覆盖区、水域、泥地、实体建筑屋顶和桥面默认不允许停靠；即使坦克可走或无人机可飞越也不能自动停靠。主地图如需增加屋顶／桥面停靠，应作为后续场景规则明确添加，当前版本不隐式开放。

道路允许停靠不代表每一条窄路都有足够空间。敌方地面实体可使停靠位置不合法；友军仍按不互挡简化处理，但不能因此忽略静态占地。

<a id="terrain-11-2"></a>

##### 11.2 起降步的动态冲突

起降指令在步初验证位置、坡度、空域与严格大于7／6的能源；地面位置保留原地，不水平移动。该步先形成受约束起降意图，地面运动后再次检查最终停靠占地。

降落期间敌方地面单位合法进入预定停靠位置，降落不能凭空驱逐敌方；该步降落失败，仍飞行，已消耗的起降及维持能源不退，下一步重新请求。失败不能触发额外模型机会。静态几何不应赛中突变；若地图数据版本改变则暂停而非继续解释。

起飞单位从地面状态开始时，敌对地面运动仍不得先穿过其步初占地；完成起飞后，下一步空中单位不产生地面阻挡。起降期间按主规则空中目标射程受击，致命则退场、已耗能源不退。

<a id="terrain-11-3"></a>

##### 11.3 兵营部署地面

新增兵营完整占地最大坡度5%，候选地表限定合法开阔地或碎石平整面；不得压在道路／桥面、水域、树林覆盖区、实体建筑或农田上。该限制只约束兵营选址，不禁止地面单位走农田。

60米×60米完整占地及服务锚点要有同面接入路线；不能让兵营中心合法、某角悬空或服务锚点隔着墙。仍须在本方部署区、与其他兵营不重叠、避开必要通路和计分区。

为避免看似可补给但没有合法停靠区，每个正式兵营场景至少提供一处满足本节条件且在100米服务范围内的无人机停靠面。正式地图至少提供双方对等的可用起降机会；是否足够支撑用户配置规模仍须测试。

<a id="terrain-13"></a>

#### 13. 算例

<a id="terrain-13-1"></a>

##### 13.1 平地农田

坦克基础400米／分钟、8能源／公里，农田f=0.5、平坡s=1。

```text
速度 = 400×0.5 = 200米／分钟
每5秒最多走 = 200×5／60 = 50／3米
单位距离耗能 = 8／0.5 = 16能源／公里
走100米需30秒，消耗1.6能源
```

保障车相同地表速度90米／分钟，走100米需200／3秒≈66.6667秒，参考移动消耗10／3≈3.3333能源。动作只能在规则步边界宣布完成，最后不足一步的到达余下时间不移动、不额外扣地面怠速费用。

<a id="terrain-13-2"></a>

##### 13.2 农田加15%坡

坦克f=0.5、s=0.85，实际170米／分钟，能耗320／17≈18.8235能源／公里。走100米需600／17≈35.2941秒，耗32／17≈1.8824能源；不是把地形和坡度减速比例相加。

保障车f=0.3、s=0.7，实际63米／分钟，能耗1000／21≈47.6190能源／公里。走100米需2000／21≈95.2381秒，耗100／21≈4.7619能源。能耗较大是本版模型的明确后果，需在试玩中观察是否过重。

<a id="terrain-13-3"></a>

##### 13.3 同一步从道路进入农田

坦克本步先走10米平道路，用时1.5秒、耗0.08能源；剩3.5秒进入平农田，可走35／3米≈11.6667米，耗14／75≈0.1867能源。

```text
合计路程 = 65／3米≈21.6667米
合计时间 = 5秒
基础能源 = 4／15≈0.2667
若实际开火，总移动能源 = (4／15)×1.25 = 1／3≈0.3333
```

这些是连续参考值，实际位置网格及累计费用按主规则精度处理。与同时间道路移动相比，地面参考能耗可能相同而路程不同：由于本版单位距离能耗是f、s的倒数，持续移动的单位时间基础耗能恰好抵消倍率；不能因此说地形不影响同一路程成本。

<a id="terrain-13-4"></a>

##### 13.4 坡度边界与横坡

保障车坡度20%使用s=0.7；20.01%禁止。坦克35%使用s=0.6；35.01%禁止。坦克沿等高线纵坡0但横坡36%，仍禁止，不能用纵坡0绕过。

<a id="terrain-13-5"></a>

##### 13.5 补给与视野

两车相距60米但隔河：不服务；两车同面相距100米、地面坡度各10%、完整停止：可以按库存服务；相距90米但一方站在12%坡：可以合法停着，却不能开始地面服务。

无人机林外到林内目标总距1200米，目标所在连通林区累计射线内长度500米：满足森林距离条件，还须检查实体遮挡；长度601米则不可见。坦克即使通过共享观察知道目标，只要自身射线被建筑挡住，也不能攻击。

<a id="terrain-14"></a>

#### 14. 额外边界与防漏洞

- 平面坐标相同、地表层不同：分别判断，不能隔层占点或补给。
- 路线中间有一小段禁行：整段不能穿越，不因两端合法忽略中间。
- 敌军堵住窄桥：不能因友军可重叠就穿越敌军；受阻信息不暴露隐藏单位身份。
- 道路贴在河面但没有桥面实体：属于地图错误，不是水面公路。
- 主动拆分路线或连续下同一任务：不能重置时间预算、降低坡度、清除已耗能源或免费跳边界。
- 密林中存在合法道路：车辆沿真实道路可走，不因周围森林整条拒绝；离开道路则重新按密林禁行。
- 狭窄道路中心合法但完整单位不够宽：拒绝，不把碰撞半径缩小到模型轮胎宽。
- 在服务区或目标圈内移动：仍按主规则失去完整停止资格，不因“只移动一点”豁免。
- 停靠无人机不可观察，即使在高地或林外；森林变化不解除状态限制。
- 地形阻挡导致不能开火：不扣弹、不刷新冷却，不改记为命中0伤害。
- 地图某处无法提供有效层／坡度／射线信息：拒绝相关场景发布；运行时发现版本损坏则技术暂停，不默认畅通。
- 旧存档使用旧地形版本时继续使用原版本；不得用新f、s重算其历史资源并覆盖成绩。
- 地形不产生直接积分或额外兵种伤害奖励。因路线耗能减少的资源分按原公式计算，不另扣“过河分”“上坡分”。
