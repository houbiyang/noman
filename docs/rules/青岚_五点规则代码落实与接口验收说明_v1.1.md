## 1. 本次范围与交付结论

用户确认保持地图文件不变，先完成规则和接口，暂不验收正式地形通行。因此本次提供五点规则核心、任务图执行、既有 HTTP/事务系统的适配及隔离测试；不重新构建地图、不改写 Unity 地形、不把平面测试场景当作青岚地图通过验收。

**当前不是完整可玩的五点游戏发布包。** 正式入口 `enable_fivepoint` 在真实地图适配器尚未发布时返回 `409 / FIVEPOINT_MAP_NOT_RELEASED`，原对局保持不变。此限制是明确的发布阻断，不是自动回退到旧地图算法。

规则核心已有确定性测试，但规则分册的每项功能尚未全部实现。第 8 节列出剩余软件工作；其中部分工作不依赖地图修复，不能一概归因于地图延期。

## 3. 已实现的规则

### 3.1 时间、编制与账户

- 一步为 5 仿真秒，正常时限为 720 步，即 3600 秒。
- 每 12 步进入共同规划边界，双方都提交后才允许继续推进。
- 双方编制由输入名册确定，不写死无人机、坦克或保障车的数量；每方至少一单位，三类数量可以为零。
- 要求恰好五个不同目标、每方三类兵营，并显式声明容量。测试中的每方容量 60 只是测试参数，不是正式容量认证。
- 初始规则、地图身份、名册、点位、兵营和分母被冻结并计算摘要。
- 能源、弹药、材料分别记当前余额、累计消耗和永久损失。转移不会产生资源，维修会消耗材料，退场结清剩余账户。
- 分数和可分割资源采用有理数累计。返回的 `"1/2"`、`"833/60"` 等字符串表示精确数值，前端不可直接按普通十进制字符串解析。

### 3.2 得分与胜负

```text
控制分 C = 70 × 有效控制点步 N / 3600
击毁分 D = 20 × 已击毁敌方初始价值 K / 敌方初始总价值 V
资源分 R = 15 × E/E0 + 9 × A/A0 + 6 × M/M0
总分 S = C + D + R，最高 120
```

`3600` 是五个点各自最多 720 步的总容量，不是“每局有 3600 个五秒步”。提前结束不更换分母。

中立点需要连续完整驻留 30 秒；敌方所属点先中立化 30 秒，再占领 30 秒。移动进入当步不增加完整驻留进度，新归属下一步才开始取得控制收入。伤害前已形成争夺的敌人即使本步被击毁，也不会让旧归属方补拿本步控制收入。

完整步后按双方全灭、单方全灭、时间到达依次判断。只有一方全灭时该方负，即使统计分更高；双方全灭或正常到时比较精确总分，再比较累计控制点步，再判平局。投降在下一个尚未开始的边界处理，技术中止没有竞技胜者。

### 3.3 观察、交战与后勤

- 无人机执行起降和观察；无人机不占点、不攻击。起降消耗 `7/6` 能源，要求能源严格大于该值；正常飞行每步先支付 `1/6` 维持能源。
- 坦克固定目标攻击需要当前共享观察、射手自身合法射程与射线、正能源、弹药和冷却条件同时成立。
- 静止命中伤害 16，发生移动时伤害 9.6；每次射击消耗 1 发，间隔 10 秒。
- 同一步先冻结所有合法射击，再同步扣血，允许互相击毁；一个单位的击毁价值只记一次。
- 移动攻击预留 1.25 倍移动能源，只有实际射击时才额外扣除 0.25 倍基础移动能源。
- 保障车每步最多交付 2 单位选定资源；数量请求按实际累计交付，余额请求按接收方达到的余额判断。
- 同步接受和提供服务、两个来源同时服务同一接收者、服务接收者同时移动或攻击均被拒绝。
- 伤害先于服务，死亡单位不能被本步维修复活；非致死伤害允许随后维修。
- 兵营使用同阵营公共库存和持久化排队信息，每营每步最多服务 4 个接收者；刚射击或受伤的单位按 15 秒脱战条件检查。
- 本方视图只包含本方账户、任务、当前合法接触和冻结的历史观察位置、耐久。敌方移动不会更新失去观察后的历史位置；对方占领阶段进度不通过公共点位泄漏。

### 3.4 低能源保护

执行器使用 `E_trigger = max(30, C_service + 10)` 限制普通深入移动。当前服务成本未知时停止该移动；成本超过满能源时不截断阈值。移动攻击的 1.25 倍预留也包含在阈值预算内。

地图接口 `service_energy_cost` 负责当前位置成本，`movement_service_energy_cost` 负责拟执行整段路径上的最大服务成本，包含路线、飞行维持、起降和已知等待。两者只接收本方合法视图，默认返回未知。整段成本未知或不满足预留时，本步拟移动不提交，也不扣该移动能源；已经发生的飞行维持不会返还。拒绝深入移动后，静止观察、合法开火、驻留及服务仍分别检查资格。原因保存在本方单位的 `energy_guard` 中，时间戳表示最近一次移动保护检查。

这项保护已接入规则执行器。2026-11-14 增加低能源及缺弹的预授权返营分支；只有计划明确包含该分支时才执行，补给后恢复原任务。低能源返营需要地图接口证明服务成本不增加且仍保留服务费用与10点储备；成本未知仍不放行。真实地图成本估算尚待地形工作，测试专用几何不能替代该验收。

以上涉及地表、遮挡、射程空间判定的执行依赖 `RuleGeometry` 实现。当前真实地图实现尚未发布；测试覆盖的是显式测试几何下的时序与账本逻辑。

## 4. 任务执行与完成条件

任务由服务端从 `queued` 转为 `waiting` 或 `running`，最终成为 `completed`、`failed` 或明确取消的 `cancelled`。前置任务在本步完成，后继最早下一步执行。循环依赖、未知前置、跨阵营指挥、同单位未排序的多个任务，以及可能并发的服务冲突在采用前拒绝。

| 动作 | 当前完成判定 |
| --- | --- |
| `move` | 位置坐标和地表层均达到指定终点 |
| `observe` | 实际执行一个合法观察时刻，发现零个敌人也可完成 |
| `capture` | 指定点的实际归属已经成为本方，单纯到达不算完成 |
| `wait` | 实际经过 `duration_steps` 个完整执行步 |
| `hold` | 达到指定持续步数或明示截止仿真时刻 |
| `patrol` | 按授权路径点循环巡查，到持续步数或明示截止时刻结束；路径点游标随快照保存 |
| `takeoff` / `land` | 本步完成相应状态转换且单位存活 |
| `service` + `amount` | 本请求实际累计交付达到请求量 |
| `service` + `balance` | 接收方相应账户达到请求余额 |
| `camp` | 指定账户达到请求余额；省略 `balances` 时检查适用账户补满 |
| `attack` / `move_attack` | 固定目标须取得退场事实；范围任务仅在授权区域内选择当前合法目标，并按指定持续时间结束 |

等待中的任务也检查截止时刻。执行单位退场、服务目标退场、前置失败会使相应任务失败；这类失败不应卡住整局推进。任务及进度随快照保存，读档后不会重新计算已经实际交付的补给量。

人工直接提交仍以整份方案为校验单位。共同AI规划采用逐节点处理：拒绝非法节点、冲突节点及其依赖，保留合法独立任务；双方整体规划失败时均不采用。未知目标与隐藏目标返回相同的本方权限错误，拒绝反馈不包含敌方库存或隐藏名册。

## 5. 接口调用顺序

所有命令仍使用既有入口：

```http
POST /api/v1/games/{game_id}/commands
Authorization: Bearer <本方或主持人席位令牌>
Idempotency-Key: <本次逻辑请求的 UUID>
Content-Type: application/json
```

请求体包含从最新本方 `view` 取得的完整 `context`、`command_type`、`payload`。下列示例省略外层 `context`，调用时不可省略它，也不要复制其他对局或其他席位的上下文。

1. 双方在准备阶段配置编制、兵营并分别 `set_ready`。
2. 主持人提交 `enable_fivepoint`。当前真实环境预期被地图发布门禁拒绝；测试才注入独立几何。
3. 红蓝分别在相同 `expected_step` 提交 `submit_fivepoint_plan`。
4. 双方提交齐备后，主持人通过 `advance_step` 提交一个完整五秒步。
5. 到第 12、24、36……708 步重新等待双方方案。第 720 步正常结算，不再发起下一轮。

直接动作与任务图二选一，不同时提交。`orders: {}` 表示明确待命的新方案，不表示“驳回并保留旧任务”。

在同一命令中传入 `decision: "reject"`，省略 `tasks` 且不提供新动作，即驳回新方案、保留旧任务及执行进度；本方完成处理后仍须等待另一方。若同时明确提供 `cancel_task_ids`，仅取消其中列出的未结束本方任务，其他任务保留，依赖被取消任务的后继在推进时失败。未知任务、已结束任务和重复标识被拒绝。取消不撤回已经提交的移动、射击、交付或消耗。

### 5.1 任务方案示例

下面演示等待一步，然后观察一次。单位标识必须取自实际本方视图。

```json
{
  "command_type": "submit_fivepoint_plan",
  "payload": {
    "expected_step": 0,
    "tasks": [
      {
        "task_id": "wait-first",
        "unit_id": "R-G01",
        "order": {"action": "wait"},
        "duration_steps": 1
      },
      {
        "task_id": "observe-next",
        "unit_id": "R-G01",
        "order": {"action": "observe"},
        "depends_on": ["wait-first"]
      }
    ]
  }
}
```

第 5 秒第一个任务完成，第二个仍等待；第 10 秒第二个才可完成。现实中等待十秒不会自动完成这两个任务，必须提交相应仿真步。

### 5.2 服务请求示例

```json
{
  "command_type": "submit_fivepoint_plan",
  "payload": {
    "expected_step": 0,
    "orders": {
      "R-S01": {
        "action": "service",
        "target_id": "R-G01",
        "category": "energy",
        "balance": 100
      }
    }
  }
}
```

来源与目标必须满足实际服务条件。该请求不自动生成赶路动作、不自动产生资源，也不保证一定补满。若使用 `tasks` 包装同类请求，才能在任务视图中读取完成状态。

### 5.3 主要错误码

| 错误码 | 含义 |
| --- | --- |
| `FIVEPOINT_MAP_NOT_RELEASED` | 真实地图尚未发布，启用或推进被拒绝 |
| `PLAN_BOUNDARY_INVALID` | 不在共同规划边界或方案依据过期 |
| `PLAN_ALREADY_SUBMITTED` | 本方本轮已经提交 |
| `PLAN_FORMAT_CONFLICT` | 同时提交直接动作与任务图 |
| `ORDER_UNIT_INVALID` | 无权指挥该单位，或该单位已退场 |
| `TASK_CYCLE` / `TASK_DEPENDENCY_INVALID` | 依赖环或前置任务不合法 |
| `TASK_UNIT_CONFLICT` / `SERVICE_CONFLICT` | 并发动作互斥 |
| `FIVEPOINT_COMMAND_FORBIDDEN` | 在五点局执行旧演示专用命令 |
| `RESOURCE_CONSERVATION` | 账户不守恒，整步不得提交 |
| `REPLAY_FORBIDDEN` | 非主持人请求进行中的历史回放 |

## 6. 权限、幂等、存档与回放

- 主持人启用规则、控制时间、存档和恢复；红蓝只能提交本方方案或本方投降。
- HTTP 命令沿用事务锁、上下文校验和请求键幂等；同一请求重发不会再扣资源或再计分。
- 错误命令不能推进对局提交头。读档创建新的有效分支，旧上下文不能继续写入。
- 新五点快照允许 0～720 步，旧模式快照仍限制 0～60 步。命令白名单由新增迁移扩展。
- `GET /api/v1/games/{game_id}/view` 返回本方当前状态；任务位于 `fivepoint.own_tasks`。
- `GET /api/v1/games/{game_id}/replay?simulation_step=61` 读取指定时刻的只读投影。进行中只允许主持人；终局后红蓝读取各自权限内的历史帧。
- `GET /api/v1/games/{game_id}/result` 读取正式终局或技术中止的结果标识，不能把中止的统计分当胜负。
- 终局沿用既有档案链路，不以重新执行历史步骤生成成绩。

## 10. 2026-11-14 续作接口与交付记录

### 10.1 操作模式与共同规划

`enable_fivepoint` 可传 `control_mode: "manual"` 或 `"auto"`，默认人工确认。开局同时冻结本机红蓝模型配置，后续修改配置文件不改变本局。自动模式拒绝人工提交单位方案。

主持人调用 `POST /api/v1/games/{game_id}/fivepoint/planning`，正文为当前 `context` 与 `played_second`。服务端检查共同边界、缓存和双方配置，登记有来源命令的快照，再在事务外调用模型。三兵种角色并行，总指挥汇总；当前链路只使用冻结本方视图，不开放外部检索工具。各方全部角色共用120秒和一次格式修复，先完成的一方不能提前行动。

人工模式生成的候选只进入本方 `fivepoint.planning_candidate`。本方通过 `submit_fivepoint_plan` 提交 `expected_step`、`use_candidate: true` 明确采用，或以 `decision: "reject"` 保留旧任务。双方均处理后方可推进；同一边界不允许再次调用模型获得额外机会。

自动模式双方合法方案同时采用。任一模型失败或超时均技术暂停；服务重启后扫描过期运行，不重发可能计费的请求。恢复最多两轮；读档另开分支，进行中的旧规划立即失效，不得把晚到结果写入新分支。

### 10.2 自动推进与统一播放

`POST /api/v1/games/{game_id}/fivepoint/advance-round` 接收 `context`、`played_second`，最多推进当前轮剩余12个完整步。每一步沿用已有命令、快照、自动存档和终局归档事务；中途暂停、其他操作改变提交头或读档换分支时停止。只在轮起点缓存不超过120仿真秒时开始生产。

`GET /api/v1/games/{game_id}/fivepoint/frame?simulation_step=N` 返回当前分支该完整步的本方投影。不能读取权威未来帧；单位、点位、日志、任务、资源与结果共同取这一帧。进行中该观看接口可由本方使用，原历史复盘接口的主持人限制保持。

Unity新增五点规则面板、人工采用／驳回、主持人共同规划／按缓存推进当前轮／连续运行、五点状态标记、合法当前及历史接触标记，以及独立五点结果页。五点局禁用旧演示播放、单步及事件入口；旧七点标记只在五点局隐藏，地图资产不改写。观看启动要求180秒缓存；断流后补足120秒，提前终局直接排空。恢复分支从存档完整步显示，按恢复缓冲处理，避免非60秒边界读档产生启动死锁。历史帧只有在请求成功并校验后才确认观看游标，网络失败会重试同一步，不跳步。

人工候选页展示服务器保存的本方完整任务JSON，包含动作、依赖、结束条件和补给分支；确认绑定打开时的权威依据。候选全文不进入主持人投影。已确认席位不能重复确认；当前规划边界与历史播放时刻分别标注。

### 10.3 任务扩展

- 范围攻击使用 `target_area: {"center": {"xy": [x, y], "layer": "层标识"}, "radius": 米数}`，与 `target_id` 二选一。先筛选当前可见、区域内、射手射程和射线均合法的目标，再按距离、耐久、持久循环游标排序；实际开火才推进游标。
