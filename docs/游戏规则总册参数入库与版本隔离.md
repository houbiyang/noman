数据库 JSON 路径：

- `definition.parameters`：结构化参数。
- `definition.source.text`：总册完整原文。
- `definition.source.tables`：表格标题、锚点、原始行号、列名和数据。
- `definition.integration`：未激活标记、无旧局迁移标记与待接入项目。

## 3. 不可默认为已完成的事项

1. **候选占点没有覆盖当前地图。** 总册 `CAPTURE_A/C/D/E/G` 是尚待地表和道路核验的候选五点，不能直接替换现行 `P-01…P-05`。
2. **软件容量已另行声明，尚未激活。** 2026-11-14 用户确认本地测试版每方每类0～10个、每方至少1个，详见《战斗测试软件容量清单与验收》。总册基础草案保留原始 `capacity_limit=null`，独立软件容量版本引用其ID/摘要，不覆盖旧载荷，也不表示WebGL负载与完整战斗流程已验收。
3. **运行规则未切换。** 新版需要持续占领执行器、资源台账与计分、规划与播放等接入及实局验收；改一个 `availability` 标记不足以完成这些工作。现有创建对局接口拒绝此草案。
4. **禁行地表不是零速度地表。** 地表倍率为 `null` 表示禁止通行，不能当作合法的零速度路径。
5. **队列不是按营轮换。** 连续登记仿真时间优先，同刻按固定单位标识的持久循环游标；三营共用同方候选排序。

## 4. 登记与查询

在项目根目录使用现有虚拟环境：

```sh
# 只检查来源与参数，不写数据库
.local/backend-test-venv/bin/python -m backend.rulebook check

# 幂等登记独立草案，使用项目私有本机应用连接配置
.local/backend-test-venv/bin/python -m backend.rulebook register
```

`SandboxService.seed_versions()` 也会登记此草案，重复启动不会重写载荷。登记过程使用参数化 SQL、事务和事务级锁；同标签若内容不同会拒绝覆盖。来源原文摘要变化也会拒绝导入，须先人工核对参数并发布新版本。

只读 SQL 示例（使用已有授权连接，不要公开连接凭据）：

```sql
SELECT id, rule_code, version_label, availability, is_demo, payload_sha256,
       definition #> '{parameters,unit_profiles}' AS unit_profiles,
       definition #> '{parameters,score}' AS score,
       jsonb_array_length(definition #> '{source,tables}') AS source_table_count
FROM sandbox.rule_versions
WHERE id = '5c17ce10-70ed-5c54-8125-c88f1abf8daf';
```
