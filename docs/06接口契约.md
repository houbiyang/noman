> 2026-11-04 占点契约设计增量：主模式采用 [CQ-01～CQ-08](02仿真规则与参数.md#conquest-rules)。以下字段尚未在当前 HTTP 服务接入；旧四任务、加权评分、20 条指令预算及条数确认阈值只适用于 legacy_task_v1 历史设计，不可用于新主局。

## 占点模式字段与兼容边界

- 创建时绑定不可变 `rule_mode=conquest`、规则版本与场景版本。公共点几何来源于场景，客户端不能直接提交 owner、进度或胜利分。候选点几何未验证时不能发布可用占点场景；现有演示接口不能悄悄改称正式占点。
- `GameView` 增加公开 `control_points` 列表，每项含 `point_id`、几何引用、`owner=null/red/blue`、`status=neutral/owned/capturing/neutralizing/contested`、`candidate_side`、`progress_kind=null/capture/neutralize`、`progress_steps` 与所需步数。只公开比赛点态，不附带隐藏敌方单位或计算证据。状态和计分来自同一快照。
- `scores` 含 `victory_points={red,blue}`、`all_control_streaks={red,blue}`、`target_victory_points`、`all_control_steps`、`last_scored_step`。胜利分、连续步数均为非负整数；不沿用旧权重或资源扣分字段表示新模式。
- 本方分工允许引用 `point_id` 并指定 `capture/hold/recon/support` 意图；实际主动作由资格与规则校验生成。首次、单位改派、攻守点改变及资源额度重大变化需本方人工确认，持续原方案无需每步确认。新动作枚举必须随格式版本实现，不能只靠模型输出自由文本。
- 运行快照使用新的占点格式版本，保存完整点态、双方积分、连续全控步和最近结算步。格式兼容由迁移／加载器显式处理；不把旧四任务快照缺字段时默认补零再继续运行，也不重算其冻结结果。
- 逐点占领、争夺、中立化、计分、全控计数及终局形成可复盘事实；同一步重复提交返回已有回执。先完整结算所有点和双方再判断结束，结果不能因阵营处理顺序改变。

## 2. 通用传输约定

### 2.1 编码、标识与值

| 项目 | 本阶段建议契约 |
| --- | --- |
| 编码 | JSON 使用 UTF-8，正常请求 `Content-Type: application/json` |
| 稳定标识 | 数据库 UUID 在 JSON 中为字符串；单位和地图对象使用不透明稳定字符串，不靠中文名称或列表序号关联 |
| 内部大整数 | 若接口确需传递 BIGINT，使用十进制字符串；内部控制修订不直接作为对方活动明细公开 |
| 仿真步与数量 | JSON 整数，当前步与已发生事件步为零至六十；数量需为可安全表示的有限整数，传输限制不等于产品兵力上限 |
| 位置与连续量 | 世界坐标、能源等精确十进制值采用字符串，缺失或未知为 `null`，具体量纲与精度由场景规则定义 |
| 单位与地图坐标 | 明确 `coordinate_system_id`，不使用屏幕像素、CSS 平移、Unity 显示 Transform 或图片尺寸充当权威位置 |
| 时间 | 现实时间为带 `Z` 的 UTC ISO 8601 字符串；页面按 Asia/Shanghai 显示；不与仿真步混用 |
| 空值与集合 | 明确无值用 `null`，已知空集合用 `[]`，未知与零不同；无权字段从响应结构中省略 |
| 演示 | 对局及历史摘要保留 `is_demo`；正式服务失败不返回演示数据替代成功 |
| 请求结构 | 拒绝未知写入字段、非有限数值及未经支持的枚举，不接受客户端提交权威得分或观察结果 |
| 缓存 | 含角色或私有对局的响应使用 `Cache-Control: no-store`，不放入共享静态缓存 |

成功响应直接返回本文资源结构或分页结构，不统一增加另一套 `data` 包装。错误统一使用第十节格式。十进制字符串只表达值，不要求所有数固定两位小数；前端渲染需要数值时进行有限性检查和显示转换，不将转换后的近似值回写为权威状态。

固定持续事件的预计恢复步可以超过六十，用于说明本局结束前仍未恢复；该值不授权推进到第六十一分钟或在结束后补执行恢复。当前仿真步、截止步和预计恢复步是不同字段。

### 2.2 会话与受控引导

对局请求使用 `Authorization: Bearer <不透明会话令牌>`，会话绑定一局及一个 `host/red/blue` 席位，数据库只保存摘要。角色来自服务端，不接受 URL、`side` 参数或客户端成员标识授权。令牌不放入 URL、Vite 公开变量、共享 `localStorage` 或普通日志。

首版没有新登录页面。建议由本机受控启动／签发入口建立三席位并分别向对应窗口交付会话；主持人页面不能读取红蓝令牌。本文建议对局请求采用 Bearer 方式，仍属 D-09 待确认设计，具体签发工具、交付渠道、有效期与终端安全存放在部署和实施规格确定，未完成前不能把原型角色切换视为正式权限实现。

创建对局前尚无本局会话，因此创建入口使用单独的受控引导凭据，作用域为 `create_game`；本机历史目录读取使用 `read_catalogue` 作用域。它们由服务端配置和启动签发流程管理，不是任意浏览器可自行申请的权限，不用于确认方案或修改已有对局。目录凭据只开放结束记录的共同复盘摘要；主持人的目录凭据可额外查看未结束存档摘要，不能替代本局主持人会话执行读档。

`GET /session` 返回当前会话可访问的对局及角色；目录凭据不返回任何游戏操作许可。跨局切换需先取得该局相应会话，不能用某局令牌访问另一局。引导接口不返回红蓝会话或密钥；正式网络环境不得只以“请求来自本机地址”当作授权。

### 2.3 上下文与副作用

游戏操作携带服务端刚返回的 `StateContext`，其中令牌绑定本局、有效分支、快照、调用角色及内部控制版本。建议令牌由服务端签发为不可读的不透明校验值，不能把包含内部计数的明文 JSON 简单编码当作隐藏。

变更使用 `Idempotency-Key` 请求头，值为调用方生成并保留的 UUID。相同逻辑操作重试使用同键、同请求体和原上下文；用户修改输入或在重新读取后发起新操作使用新键。预览是无游戏副作用的 POST，不保存快照、扣资源或触发事件，允许安全重复请求。

## 3. 主要资源结构

### 3.1 `StateContext` 与版本

```json
{
  "game_id": "11111111-1111-4111-8111-111111111111",
  "branch_id": "22222222-2222-4222-8222-222222222222",
  "snapshot_id": "33333333-3333-4333-8333-333333333333",
  "context_token": "opaque-context-token-example"
}
```

`snapshot_id` 只是上下文标识，不授权下载原始快照。服务端验证令牌与当前会话及上下文，内部映射到数据库 `control_revision` 等字段；API 不提供任意原始快照读取入口。读档后 `branch_id` 必须变化，仿真步可以减小，不能只比较步数判断响应新旧。

### 3.2 `GameView`：当前角色快照

| 字段 | 类型 | 口径 |
| --- | --- | --- |
| `schema_version` | 字符串 | 建议固定首版为 `game-view-v1` |
| `context` | `StateContext` | 本响应的一致状态上下文 |
| `role` | 枚举 | 本会话 `host/red/blue` |
| `game` | 对象 | `game_id`、`game_no`、`title`、`is_demo`、场景和规则版本 |
| `clock` | 对象 | `simulation_step`、`deadline_step`、`step_minutes`、`phase`、`pause_reasons`；首版截止六十、每步一分钟 |
| `capabilities` | 对象 | 角色与阶段决定的可执行命令、预览和读取能力；禁用项附本方可知原因 |
| `map` | 对象 | 公共资源清单、坐标系、可展示静态元素、本方探索与允许路线，结构不包含隐藏动态对象 |
| `tasks` | `TaskView[]` | 操作员只有本方任务，主持人可见双方；不返回对方私有进度占位对象 |
| `camps` | 对象数组 | 本方兵营完整可见字段、允许观察到的对方建筑信息或主持人全局 |
| `units` | `UnitView[]` | 本方单位；主持人可含双方完整状态，操作员已发现对方另放 `contacts` |
| `contacts` | 对象数组 | 当前发现的对方对象，只含允许观察的属性 |
| `last_seen_records` | 对象数组 | 带最后有效时间的历史标记，不实时更新 |
| `agents` | `AgentView[]` | 操作员本方四角色，主持人可见双方管理状态但不代处理建议 |
| `decisions` | 对象 | 允许看到的待分析状态、待确认摘要与操作阻塞，不伪造尚未生成的建议 |
| `resources` | 对象数组 | 本方预算、已执行与剩余；主持人可见双方，不由页面自行减额度 |
| `save_status` | 对象 | 本版本是否已持久化、当前方可见保存反馈，详细整局存档仅主持人 |
| `service_status` | 对象 | 当前可用的建议、索引与核心服务能力，不暴露内部配置 |
| `observed_at` | UTC 字符串 | 本次成功读取现实时间，不代表所有历史报告在此时更新 |

HUD、地图、任务、单位与信息面板使用同一响应上下文。字段数量、列表总数及禁用原因也要过滤权限；无权内容不能先返回完整对象再由前端隐藏。当前快照内部 JSON 和数据库表结构不是 `GameView` 的直接序列化来源契约。

`phase` 使用 `preparing/running/paused/awaiting_confirmation/finished`；没有对局由目录或当前入口返回明确空状态，不虚构一个 UUID 对局。待确认方摘要在主持人视图可见，另一操作员只获知推进受阻所必需的公共状态，不收到对方方案内容。

### 3.3 `UnitView` 与观察记录

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `unit_id`、`display_code` | 字符串 | 稳定标识与展示编号分开，例如内部标识与 `R-01` |
| `side`、`unit_type` | 枚举 | 阵营和 `recon/ground/support` |
| `camp_id`、`formation_id`、`task_id` | 字符串或空 | 当前归属与主任务 |
| `position` | 对象或空 | `x`、`y` 十进制字符串和 `coordinate_system_id`；待命未上图可为空 |
| `availability` | 对象 | 由规则定义的可用状态、原因、必要恢复步，不用“在线”覆盖所有业务状态 |
| `current_action` | 对象或空 | 动作类型、开始步、关联任务与进度；每单位一个主要动作 |
| `durability`、`energy`、`supply` | 量值对象或空 | 每项含 `value` 与 `unit_code`；不适用或未配置为空，不伪填参数 |
| `route_id`、`observed_step` | 字符串或空、整数 | 当前路线与状态有效步 |
| `role_details` | 判别联合对象 | 无人机报告与停靠状态、陆兵节点与补给、保障库存和唯一携带对象 |

`contacts` 和 `last_seen_records` 不直接复用完整 `UnitView`。其字段为 `object_id`、`object_kind`、`side`、已识别类型或空、`position`、`observation_step`、`source_report_ids` 和可观察状态；最后发现记录另有 `record_kind = last_seen`。对方真实耐久、库存、任务、管理智能体及未观察到的属性不得自动公开。

失视当步移除该对象的实时标记，必要时创建历史标记；历史记录的坐标与观察步保持不变。重新发现后使用新报告。通信未知不把最后位置改成当前精确位置，前端不以动画补算对方移动。

### 3.4 `AgentView` 与 `AgentRunView`

`AgentView` 是服务端根据四角色定义、当前单位和运行记录生成的管理摘要，不要求新增 `agents` 数据库表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `agent_key` | 稳定字符串 | 本局某方某角色，不能只用易变展示名称 |
| `side`、`agent_role` | 枚举 | `red/blue`，以及 `commander/recon/ground/support` |
| `display_name` | 字符串 | 中文展示名称 |
| `managed_unit_ids`、`assigned_task_ids` | 字符串数组 | 管理关系，不复制另一份可写单位状态 |
| `status_summary` | 对象 | 由运行与任务派生的状态、原因与有效步，不把它当单位动作状态 |
| `latest_run_id` | UUID 或空 | 最近可见分析运行 |
| `pending_proposal_ids` | UUID 数组 | 真实已存在且允许读取的建议；主持人只见待处理元信息 |
| `last_observation_step` | 整数或空 | 最近有效输入时间，未知不写零 |
| `role_details` | 对象 | 总指挥的下属、计划与未知项；侦察的报告与探索引用；陆兵的节点、编队与异常；保障的请求、服务及运输引用 |

配置中的允许工具、资料范围由后端强制执行，不作为客户端可修改字段。API 可展示模型和提示的版本名称，但不返回密钥、完整内部系统提示、检查点内容或隐藏输入。

`AgentRunView` 包含 `run_id`、`agent_key`、`side`、`agent_role`、`based_on_context` 的标识部分、`status`、可读摘要、`proposal_ids`、可见引用、实际 `usage` 或空、`started_at/finished_at`、已脱敏错误。状态沿用数据库 `queued/running/waiting_human/succeeded/failed/stale/cancelled`。不返回 `ai_runs.input_view` 全量内部副本、供应商原始响应或工作流检查点。

### 3.5 `TaskView`、路线和报告

| 资源 | 主要字段 | 约束 |
| --- | --- | --- |
| `TaskView` | `task_id`、`side`、`task_type`、`target_ids`、`target_revision`、`deadline_step`、`status`、`nodes`、`failure_reason` | 类型为 `patrol/escort/protect/evacuate`，映射四类中文任务；三个节点与既定完成条件不变 |
| 节点 | `node_id`、`label`、`status`、`completed_step`、能力需求与允许参与单位引用 | 未完成时间为空，不靠数组位置引用单位 |
| `RouteView` | `route_id`、`movement_type`、单位引用、道路段或途经点、`eligibility`、原因、预计完成时间与未知项 | `movement_type` 为 `ground/air`；`eligibility` 为 `executable/needs_verification/unavailable` |
| `ObservationReport` | `report_id`、来源、对象、获取步、最后有效步、`certainty` 与可见内容 | 来源与不确定项明确；未知不构造概率或实时坐标 |

对象标识由场景和对局提供，`A/B/C`、`设施01` 等是当前原型展示编码，不能假设所有内部对象就叫这些值。道路是静态地图连接，`RouteView` 是已确认路线或当前查看的方案候选，二者不混用。

### 3.6 `ProposalView` 与人工修改

`ProposalView` 包含 `proposal_id`、`side`、`proposal_kind`、`status`、`requires_confirmation`、`created_step`、`based_on_snapshot_id`、建议摘要、`assignments`、`task_priorities`、`resource_limit`、预计影响、`uncertainties`、`evidence`、`validation` 和已有处理记录。建议内容与人工修改分别保存，不接受客户端覆盖原建议。

`assignments` 每项用 `unit_id/task_id/node_id` 和规则允许的职责表达分工；具体动作代码来自场景规则，不接受任意脚本或 SQL。资源变化指实际规则计算的新增指令数，当前剩余预算来自快照。

人工修改只允许 `assignments`、`task_priorities`、`resource_limit`。不允许传回坐标、耐久、能源、视野、得分、模型配置或其他阵营单位作为写入字段。字段类型明确，分工可提交完整替换列表，优先级引用稳定任务标识，资源额度为非负整数且不超过当前剩余预算；最终仍由后端校验单位、期限和规则。

### 3.7 `CommandReceipt`：执行收据

```json
{
  "command_id": "66666666-6666-4666-8666-666666666666",
  "request_key": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa",
  "command_type": "advance_step",
  "status": "succeeded",
  "origin_branch_id": "22222222-2222-4222-8222-222222222222",
  "result": {
    "branch_id": "22222222-2222-4222-8222-222222222222",
    "snapshot_id": "44444444-4444-4444-8444-444444444444",
    "simulation_step": 19,
    "save_id": null
  },
  "error": null,
  "replayed": false,
  "completed_at": "2026-10-25T08:00:00.000Z"
}
```

收据说明该命令发生了什么，不保证它仍是当前头。成功后重新读取 `GameView`；前端不只凭收据局部增加分钟或扣资源。重复请求的 `replayed = true` 表示返回已有处理结果，不表示再次执行。

`accepted/running` 收据的 `result` 与完成时间可为空。业务拒绝或失败若已持久化命令记录，可带 `command_id` 供查询；请求未进入命令入口时可以没有命令标识。不得伪造一个成功收据掩盖保存失败。

## 4. 接口清单

## 5. 创建、准备与任务设置契约

### 5.1 创建与幂等结果

`POST /games` 需要创建作用域和 `Idempotency-Key`，提交 `title`、`scenario_version_id`、`rule_version_id`、`task_type` 与明确的 `is_demo`。不接受单位总量、资源、分数或对方视野作为创建结果。版本必须可用且匹配，任务类型必须为该场景支持的四类之一。

`GameCreated` 返回 `game_id`、`game_no`、版本、`phase = preparing`、`is_demo` 和创建请求键，不返回三方会话令牌。同键不同输入返回冲突。创建响应丢失后通过 `/game-creations/{request_key}` 查询，不能重新生成请求键盲目建局；进入沙盘前通过受控引导取得本局席位会话。

### 5.2 准备预览与完整替换

准备请求包含 `context`、客户端 `input_revision` 和本方 `preparation`。`preparation` 为以下结构，示例仅说明格式：

```json
{
  "camp": {
    "position": { "x": "153", "y": "219", "coordinate_system_id": "demo-grid-v1" },
    "placement_variant": "default"
  },
  "troop_counts": { "recon": 1, "ground": 1, "support": 1 }
}
```

位置合法性检查完整占地、道路出入口与停靠点。首版保留每类一个初始单位，各类型数量不低于一；新增免费且不设产品数量上限。`camp = null` 可用于准备中撤销兵营，但不能标为准备完成。`placement_variant` 只能从场景提供值中选择，不允许客户端提交任意建筑轮廓绕过占地检查。

`PreparationPreview` 返回相同 `input_revision`、校验错误、匹配连接点、占地展示、`preview_token` 或空。无效预览仍为 `200` 资源且 `valid = false`，不执行任何游戏变更。提交 `set_preparation` 时携带同一准备对象和有效预览令牌，整体替换本方配置；遗漏某类型不是默认为零，而是字段错误。

原型任意点放置单位不作为正式提交方式。预览中使用的临时标记可带 `client_ref`，但正式单位由服务端生成稳定标识；客户端不提交可信位置、能源或耐久。若需要在开始前重建准备单位，返回更新后的完整本方视图并清理不适用选择，不能把临时标识当成执行期身份。

### 5.3 主持人任务格式

保留原型输入方式，每方一行 `任务类型|目标|截止步数`。格式校验请求如下：

```json
{
  "context": {
    "game_id": "11111111-1111-4111-8111-111111111111",
    "branch_id": "22222222-2222-4222-8222-222222222222",
    "snapshot_id": "33333333-3333-4333-8333-333333333333",
    "context_token": "opaque-context-token-example"
  },
  "input_revision": "3",
  "raw_tasks": {
    "red": "区域巡查|A-B-C|60",
    "blue": "区域巡查|C-B-A|60"
  }
}
```

解析保留中文输入习惯，服务端转换为稳定 `task_type/target_ids`。检查三个非空字段、四种类型、场景目标存在性、截止六十步、双方同模板与对称条件。当前原型的目标编码通过场景映射，不硬编码成所有未来地图的数据库主键。

`TaskConfigurationPreview` 返回 `valid`、原 `input_revision`、双方解析结果、字段和共享错误、`preview_token` 或空。`set_tasks` 携带原始输入和预览令牌，准备阶段原子应用双方任务；失败不保存一方成功另一方失败的配置。

本版 `set_tasks` 只用于准备阶段。运行中目标替换走第七节任务变化事件及人工确认，不复用一个无副作用校验接口直接重置当前任务。输入修改或上下文变化使旧预览失效。

### 5.4 准备完成与开始

`set_ready` 仅接受 `{ "ready": true }` 或 `false`，本方配置和任务必须合法；准备内容变更后重新核对本方准备状态。`start_game` 仅主持人，检查双方准备及场景参数，关闭新增配置并进入首次方案待处理流程。

开始后没有真实 AI 建议时返回分析排队或服务不可用状态，不伪造建议并自动推进。部队从兵营出发仍以已采用方案和后续规则为准，前端开局动画不改变仿真步。

## 6. 统一命令与智能体决策契约

### 6.1 命令请求

`POST /games/{game_id}/commands` 使用以下统一结构，`payload` 按 `command_type` 进行判别联合校验：

```json
{
  "context": {
    "game_id": "11111111-1111-4111-8111-111111111111",
    "branch_id": "22222222-2222-4222-8222-222222222222",
    "snapshot_id": "33333333-3333-4333-8333-333333333333",
    "context_token": "opaque-context-token-example"
  },
  "command_type": "advance_step",
  "payload": {}
}
```

角色由会话读取，命令体不提供可覆盖的 `role/actor_member_id`。路径与上下文中的对局必须一致，未知字段拒绝。请求键取自头部，不在多个位置提供不同副本。

| `command_type` | 允许角色与阶段 | `payload` |
| --- | --- | --- |
| `set_preparation` | 本方操作员，准备 | `preparation`、`preview_token` |
| `set_ready` | 本方操作员，准备 | `ready` 布尔 |
| `set_tasks` | 主持人，准备 | `raw_tasks`、`preview_token` |
| `start_game` | 主持人，双方准备合法 | 空对象 |
| `pause` | 主持人，未结束运行上下文 | 空对象 |
| `continue` | 主持人，允许继续且无待确认 | 空对象 |
| `advance_step` | 主持人，允许推进且无待确认 | 空对象 |
| `review_proposal` | 建议所属方，未结束 | `proposal_id`、`decision`、`changes` |
| `trigger_condition` | 主持人，未结束且事件可执行 | `condition`、`preview_token` |
| `create_save` | 主持人，允许保存 | `display_name` 字符串或空，不覆盖已有手动记录 |
| `restore_save` | 主持人，未结束可继续对局 | `save_id` |
| `begin_exit` | 主持人，未结束对局 | 空对象，先暂停并返回最近成功自动存档摘要 |
| `complete_exit` | 主持人，已暂停退出上下文 | `choice` 为 `save_and_exit` 或 `without_save`，可带 `display_name` |

关闭退出弹窗的“取消”是本地 UI 操作，整局已经暂停且保持暂停，不自动调用 `continue`。关闭建议抽屉也不等于驳回或确认。批量操作仍使用一个命令事务，不为每个子对象单独提交一半结果。

短操作成功返回 `200`；已写入持久化执行记录且需要继续处理时返回 `202`，前端查询收据，不能将接受等同成功。最终资源创建如手动存档通过收据 `result.save_id` 表达，不用改变统一命令返回形态。

### 6.2 AI 运行与建议读取

首次分配和既定事件触发的分析由后端工作流组织，不提供让任意页面直接执行某个模型、查询向量表或指定系统提示的接口。前端读取管理摘要、运行进度和实际已生成建议。一个兵种智能体可管理多个单位；首版不建立每单位独立 LLM 请求协议，未来单位 Agent 按 PRD-29 单列授权与会话契约。

本方可读取完整可见建议和来源。以下“主持人只见等待摘要”为 D-08 的当前草案，尚非新增已确认决策；主持人不能代确认则为既有要求。主持人对局中只通过 `GameView.decisions` 看到待处理方与阻塞摘要，没有代确认入口，也不借运行查询获取另一套可操作建议。服务不可用、证据不足、排队和失败分别显示；不存在建议时不返回空内容伪装成成功方案。

读档恢复的建议保留 `source_proposal_id` 和旧依据时间，创建本分支记录；过去模型结果不因为刚返回就获得新分支执行许可。已结束复盘按冻结记录读取，不调用运行接口重新生成历史方案。

### 6.3 人工处理与采用

`decision` 为 `approve/modify_approve/reject`。未修改批准与驳回使用 `changes = {}`；修改后批准提交允许字段，例如：

```json
{
  "proposal_id": "55555555-5555-4555-8555-555555555555",
  "decision": "modify_approve",
  "changes": {
    "assignments": [
      {
        "unit_id": "unit-red-ground-01",
        "task_id": "task-red-01",
        "node_id": "node-red-b",
        "duty_code": "onsite_execution"
      }
    ],
    "task_priorities": ["task-red-01"],
    "resource_limit": 2
  }
}
```

`duty_code` 属于场景允许职责，示例值不是对所有任务都合法。分工变更按完整列表替换该建议分工，前端先展示前后差异，服务端检查未重复占用单位、所属方、可用性、截止步、当前预算与动作规则。

采用时核对当前有效分支、建议、依据与实际游戏状态。仅登记建议、暂停等未改变依据的修订不应令建议因自身登记失效，但必须由服务端核对输入指纹及最新规则；实际依据变化返回冲突。一个建议只产生一次最终人工处理，首次、重大调整不能绕过确认。

### 6.4 幂等与结果核对

服务端在有权的上下文内先查相同请求键，再判断新执行的版本前置条件。已经成功的原请求即使其分支不再是当前分支，也可向原提交者返回已有收据，但绝不重新执行。相同键与不同类型、输入或原上下文返回 `409 IDEMPOTENCY_KEY_REUSED`。

`GET /command-results` 使用 `origin_branch_id` 和 `request_key` 查询本席位命令。查询 `404` 只能说明当前未查到已持久化记录，不证明另一个未提交事务已经停止；应保持待核对，必要时以相同键和原请求重试。若收到明确过期拒绝，再重新读取、展示变化并发起新逻辑操作。

请求取消、断网或超时都不能当作服务端回滚证明。命令已成功而响应丢失时依赖幂等结果，不能换键再次推进、保存或恢复。

## 7. 事件预览与时间推进契约

### 7.1 事件格式

`POST /conditions/preview` 提交 `context`、`input_revision` 与 `condition`：

```json
{
  "condition_type": "equipment_fault",
  "target_side": "red",
  "target_unit_id": "unit-red-ground-01",
  "trigger_step": 18,
  "replacement_target_ids": null
}
```

| `condition_type` | 参数与固定效果 | 权限和展示 |
| --- | --- | --- |
| `equipment_fault` | 指定本局单位暂停五步 | 受影响方与主持人可见私有故障 |
| `communication_outage` | 使用 `target_unit_id` 指定来源单位，其受影响共享报告按场景规则未知五步 | 保留最后有效时间，不能继续伪实时共享 |
| `weather_change` | `target_side = both`，不指定单位，进度延迟五步 | 天气公开，相关私有报告不随之公开 |
| `task_change` | 指定一方当前任务的新目标集合，保持任务类型与截止口径 | 旧进度留痕，新目标从零，进入本方关键方案处理 |

首版手动触发要求 `trigger_step` 等于当前步，不接受任意过去步补写或把未来输入伪装成已排程。预设脚本使用场景版本提供的配置，尚未锁定脚本编辑 API，不新增页面写入接口。通信影响范围的具体对象资格由场景契约锁定，未配置时不自行扩展为全方失联。

`condition` 按类型校验：故障和通信事件的 `target_side` 为 `red/blue`，必须有该方合法的 `target_unit_id`，`replacement_target_ids = null`；天气为 `target_side = both`，两个对象参数均为空；任务变化指定 `red/blue`，`target_unit_id = null`，新目标数组必填且与当前任务模板匹配。未知额外字段拒绝，不接受任意报告筛选表达式。

预览返回 `valid`、原输入修订、可公开影响摘要、固定效果、可见范围、预计恢复步或结束条件和 `preview_token`。客户端不能直接设置持续时长、扣分或恢复结果。提交 `trigger_condition` 时带相同 `condition` 和预览令牌，服务端再检查；取消预览不生成事件。

### 7.2 令牌失效与单步

预览令牌绑定输入、会话、对局上下文和规则版本。输入或相关依据改变后重新预览；令牌校验与触发同事务复核，不只依赖前端按钮禁用。事件重叠规则尚未锁定的场景返回明确不可执行原因，不临时猜测叠加方式。

`advance_step` 成功只增加一分钟，范围最多六十；处理中禁止并发多推进。`continue` 只解除允许解除的主持人暂停，不能解除待人工确认。后端自动运行节奏待实施参数验证，不由页面轮询驱动，不在接口中增加尚未确认的倍速选择。

事件持续按仿真步，暂停与停机现实时间不直接消耗事件。推进、结果、任务、损失和快照保持统一；交战或行进动画不提交“命中”“到达”或“扣分”请求。

## 8. 存档、退出与恢复契约

### 8.1 存档资源

`SaveSummary` 包含 `save_id`、`save_kind`、`display_name` 或空、`game_id`、来源分支与快照、`simulation_step`、`phase`、`saved_at`、`is_demo`、`can_restore`、不能恢复的可读原因。类型为 `auto/manual/final`，摘要不包含双方私有单位与待确认内容。

详细存档列表由本局主持人读取；红蓝仅获知当前对局最近持久化状态，不拥有整局保存或读档命令。手动存档支持多条，本版不设槽数、覆盖或自动删除协议。数据库保存原始整局快照，接口不返回可由页面任意修改的存档文件。

### 8.2 自动保存与退出

每步、人工处理和事件触发后的自动保存及结束固化沿用现有规则。成功状态只能在持久化后返回。`save_status` 至少区分保存中、已保存、失败与待核对，并标明对应快照或当前角色允许获知的版本信息，不能把浏览器缓存等同保存成功。

主持人点击退出先提交 `begin_exit`，成功后在已暂停状态展示最近成功自动存档。`complete_exit` 的 `save_and_exit` 先创建成功手动存档，再返回 `exit_ready = true`；保存失败保留当前局和退出选择。`without_save` 不创建新手动记录，保留最近成功自动存档，不删除既有数据。取消只关闭弹窗，返回已暂停对局。

前端跳转由 `exit_ready` 结果驱动，不以关闭页面模拟退出成功。浏览器直接关闭不保证完成网络命令，重新进入只能使用实际成功记录。

### 8.3 读档

`restore_save` 需要当前最新上下文与原存档 `save_id`。后端核对存档同局、未结束可继续、格式与规则兼容后，在事务内建立新有效分支并暂停恢复。成功收据的结果分支可以不同于请求分支，随后重新读取视图并清除旧分支表单、选择、动画和请求。

```json
{
  "command_id": "bbbbbbbb-bbbb-4bbb-8bbb-bbbbbbbbbbbb",
  "request_key": "cccccccc-cccc-4ccc-8ccc-cccccccccccc",
  "command_type": "restore_save",
  "status": "succeeded",
  "origin_branch_id": "22222222-2222-4222-8222-222222222222",
  "result": {
    "branch_id": "dddddddd-dddd-4ddd-8ddd-dddddddddddd",
    "snapshot_id": "eeeeeeee-eeee-4eee-8eee-eeeeeeeeeeee",
    "simulation_step": 12,
    "save_id": "88888888-8888-4888-8888-888888888888",
    "phase": "paused"
  },
  "error": null,
  "replayed": false,
  "completed_at": "2026-10-25T08:00:00.000Z"
}
```

读档失败不替换当前有效对局，旧模型、旧命令和工作流不能因此重放。已经完成的交接、消耗和损失从快照恢复，不再次计算。已结束游戏仍只读复盘，不用较早手动存档绕过结束限制。

## 9. 历史、结果、复盘与原文

### 9.1 分页与目录

历史及存档建议使用 `page/page_size`，默认第一页、每页二十条，建议每页最多一百条；这是列表传输限制，不是部队或存档总数上限。排序为保存或创建时间倒序，再用稳定标识消除同时间顺序歧义。

```json
{
  "items": [],
  "page": 1,
  "page_size": 20,
  "total": 0
}
```

`total` 只统计凭据可见记录。历史目录按 `state = unfinished/finished`、任务类型和演示标记筛选；红蓝目录不读取未结束整局私有存档，主持人目录只提供可进入记录摘要，真正读档仍需对应本局会话。

事件采用不透明游标，参数为 `cursor`、`limit`，建议默认二十、最多一百；响应包含 `context`、`items`、`next_cursor`。游标绑定调用席位、分支与读取锚点，不能改为另一方游标。首次查询固定锚点后继续翻页不混入新状态，重新同步另取新锚点。事件按快照修订与事件内顺序排序，不公开内部全局事件计数。

### 9.2 结果与评分

`GameResult` 在占点模式含结束上下文、`rule_mode=conquest`、规则／场景版本、结束步、`winner=red/blue/draw`、双方整数 `victory_points`、`all_control_streaks`、终局点态与计分事件引用。`reason=all_points_held/score_target/time_limit`，按 CQ-05 优先级确定。资源消耗、损失和单位数单列为统计，不参与胜负，也不提供旧权重／加权总分。历史 legacy_task_v1 结果按原模式、原格式读取。

结果仅在结束后可读，未结束返回 `409 GAME_NOT_FINISHED`，不临时预判胜负。逐点得分按分支和转换结束步去重；结果冻结后不因读取、暂停、离线或读档重算。客户端不能提交新的评分或用当前规则覆盖历史。

### 9.3 复盘帧

`GET /replay` 接受 `branch_id` 与二选一的 `snapshot_id` 或 `step`。`snapshot_id` 是精确帧；只给 `step` 时返回该步在所选允许历史中的最后提交修订，并在响应回传实际 `snapshot_id`。所选分支的历史可包含来源快照以前的祖先前缀，必须截止到实际分叉修订；前缀帧回传其真实来源标识。同时传两种定位值或越出历史范围返回字段错误。

`ReplayFrame` 包含 `game_id/branch_id/snapshot_id`、`simulation_step`、`read_only = true`、冻结地图与单位、双方任务、事件、当时建议与人工处理、分数变化及原文引用。结束记录三角色可读，进行中不借此取得双方完整信息。

快速拖动时前端仅应用最后请求对应帧，不将目标时间标题和旧地图混成新状态。复盘跳转没有执行副作用，不再次生成 AI 输出、扣资源或触发事件；分支历史截止到实际分叉修订，不能混入父分支后续过程。

### 9.4 证据与原文内容

`EvidenceView` 区分 `document/report/rule`，返回允许的资料名称、版本、片段／报告标识、原文位置、冻结引用、有效仿真时间、可访问内容入口或不可读原因。不返回数据库存储键、服务器路径、检查点或任意 URL 执行入口。

资料与模型文本按普通内容展示；Unity 富文本与网页 HTML 分别按允许格式处理，不能执行返回的脚本、链接动作或工具指令。引用只提供证据，不提供让客户端或后端执行文档内任意指令的通用接口。

`/document-versions/{version_id}/content` 需要与对应对局、资料权限匹配的凭据；引导创建权限本身不能读私有资料。文本使用 UTF-8，原始 PDF 等按实际媒体类型响应，具体格式由资料样例确定。没有可用原文时明确错误，不返回空成功文件。

浏览器内嵌资源不能靠 URL 拼接令牌绕过授权。建议通过授权 `fetch` 获取内容，文本直接展示，必要时创建临时 Blob URL 预览并及时释放；目标终端是否支持 PDF 原生预览单独验证。Unity 独立客户端通过所选网络适配器进行同等授权读取，不要求复用网页 Blob URL 机制。下载或预览的大小、Range 支持与媒体白名单在资料实施规格锁定，不借用其他项目限制。

## 10. 响应码与统一错误

| HTTP 状态 | 用途 | 建议业务码 |
| --- | --- | --- |
| `400` | 无法解析的 JSON 或参数组合 | `INVALID_REQUEST` |
| `401` | 凭据缺失、过期或无效 | `SESSION_REQUIRED`、`SESSION_EXPIRED` |
| `403` | 已知自身资源上的操作不允许 | `ACTION_FORBIDDEN` |
| `404` | 资源不存在或不允许获知其存在 | `RESOURCE_NOT_FOUND`、命令查询 `COMMAND_NOT_FOUND` |
| `409` | 阶段、上下文或业务冲突 | `STATE_CONTEXT_STALE`、`BRANCH_CHANGED`、`PREVIEW_EXPIRED`、`PROPOSAL_ALREADY_REVIEWED`、`IDEMPOTENCY_KEY_REUSED`、`PENDING_CONFIRMATION`、`GAME_NOT_FINISHED` |
| `413` | 超出已配置传输体积 | `REQUEST_TOO_LARGE`，不等同产品部队数量上限 |
| `415` | 不支持的内容媒体类型 | `UNSUPPORTED_MEDIA_TYPE` |
| `422` | 字段或执行条件不满足 | `VALIDATION_FAILED`、`SCENARIO_NOT_READY`、`RULE_PRECONDITION_FAILED`、`SAVE_INCOMPATIBLE` |
| `429` | 已配置的请求或调用额度暂不可用 | `RATE_LIMITED`，具体额度不在本文虚构 |
| `500` | 内部服务错误 | `INTERNAL_ERROR`，不返回堆栈 |
| `503` | 核心依赖不可用或能力不可提供 | `CORE_UNAVAILABLE`、`MODEL_UNAVAILABLE`、`INDEX_UNAVAILABLE` |

错误格式建议如下：

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "请修正任务输入后重新校验",
    "fields": [
      {
        "object_type": "task_configuration",
        "object_id": null,
        "client_ref": "red-task-input",
        "path": "/raw_tasks/red",
        "code": "TASK_FORMAT_INVALID",
        "message": "请按任务类型、目标和截止步数填写三项内容"
      }
    ],
    "request_id": "ffffffff-ffff-4fff-8fff-ffffffffffff",
    "command_id": null,
    "retry_action": "edit_and_resubmit",
    "outcome": "not_applied"
  }
}
```

`path` 采用相对本请求体的 JSON Pointer；数组可用下标定位本次提交项，但必须同时给稳定 `object_id` 或本地 `client_ref`，前端不能将下标当作跨次修改的主键。没有字段级错误时 `fields = []`。

`retry_action` 为 `none/edit_and_resubmit/refresh_context/query_command/retry_read`；它是前端处理提示，不授权绕过权限。`outcome` 为 `not_applied/applied/unknown/not_applicable`，只在可核实时声明未应用或已应用；网络错误没有业务响应时也按待核对处理。

错误可带本方有权读取的当前上下文，不返回另一方进度或隐藏对象作为失败解释。数据库错误、原始模型输出和 FastAPI 默认请求错误均转换到同一外层结构。建议服务失败可在 `GameView` 中作为能力状态正常读取，不能因此把整个已保存对局返回成不存在。

## 11. 状态、权限与兼容性

`GameView` 是同一状态版本的角色投影，`CommandReceipt` 是一次执行事实，`AgentRunView` 是一次工作流进度，三者不合并成一个模糊的 `status`。建议沿用数据库生命周期值，显示层统一映射中文，不在多个组件分别推断。

首次和重大建议等待期间，关闭面板、重连、轮询成功或服务健康都不解除确认。正式建议不可用时明确不可用；历史已采用建议可只读查看，不能当作当前新建议再次确认。

`/api/v1` 是应用协议版本，`game-view-v1` 等是资源结构版本，规则版本、场景版本、存档格式和向量模型版本另行携带，不混为一个版本号。兼容新增的可选读取字段可维持 v1；改变权限、单位、含义或写入结构必须评估协议升级及数据迁移。

内部数据库序号与列名不要求逐一暴露。上下文令牌、引导凭据、预览令牌和游标都不是 LangGraph 检查点编号；令牌刷新或过期不自动改变游戏状态。前端类型、后端请求／响应模型和契约样例应同步更新。

既有 Vue 原型的本地缓存和跨窗口同步仅作为演示参考，不能替代正式 API。正式模式使用后端角色快照；Unity 与业务面板若组合部署，只通过明确的客户端桥接同步导航、选择与版本，不互相授予权限。页面交互以 [交互与视觉设计及线框](04交互与视觉设计.md#wireframes) 为准，承载方式待 D-15。

## 14. 前后端契约衔接与验收

### 14.1 数据映射与现有文档关系

| 本文接口概念 | 数据库／现有模块对应 | 同步要求 |
| --- | --- | --- |
| `StateContext.context_token` | `games.control_revision`、有效分支与快照、当前会话 | 不新增可变游戏副本，服务端校验并映射内部版本 |
| 创建请求键 | `games.creation_request_key` 与创建摘要 | 同键同输入返回原对局，不重新创建角色权限 |
| 命令头幂等键 | `game_commands.request_key`、原分支、提交席位和输入摘要 | 重试保留原上下文，查询结果重新做权限投影 |
| 预览令牌 | 原输入、依据状态与规则的服务端校验值 | 预览不写游戏快照，不为令牌伪造成功业务记录 |
| `AgentView` | 四角色定义、快照管理关系和 `ai_runs` | 只读派生，不建立第二份单位或库存状态 |
| 人工处理 | `proposals`、`proposal_reviews`、命令与结果快照 | 原建议冻结，修改与采用同事务，唯一最终处理 |
| 存档与读档 | `game_saves`、`game_branches`、`game_snapshots` | 收据支持结果分支不同，旧运行不能写入新分支 |
| 引用内容 | `proposal_evidence`、原文版本与片段 | 精确版本访问与冻结引用，不直接返回存储键 |
| 目录与引导 | 后端受控启动配置及本局 `access_sessions` | 目录权限不能用于游戏变更，具体签发实施单独完成 |

系统架构中的外部版本依据通过本文上下文表达，数据库内部仍保留控制修订。接口报文、内部快照与 Unity 显示对象分别建模；角色详情和融合新增结构随 D-07、D-09 完善，不能把模块职责当作已冻结 JSON Schema。

### 14.2 验收情景

| 编号 | 情景 | 应取得的结果 |
| --- | --- | --- |
| API-01 | 使用 URL 或请求体伪装主持人 | 会话权限不变，不能推进、触发或读档 |
| API-02 | 主持人尝试处理红蓝建议或读取对局中详细建议 | 无代确认能力，仅返回允许等待摘要 |
| API-03 | 角色视图、单位和智能体摘要同屏读取 | 同一上下文，隐藏对象与对方私有字段不返回 |
| API-04 | 当前观察变为历史或通信未知 | 坐标、来源、时间与样式语义一致，旧标记不继续实时移动 |
| API-05 | 任务格式、目标、双方模板或截止不合法 | 预览失败且错误可定位，不部分应用任务 |
| API-06 | 准备或事件预览后修改输入／状态 | 旧令牌不可用于触发，重新校验 |
| API-07 | 首次分配无真实 AI 结果 | 保持待处理，明确不可用或排队，不执行演示建议 |
| API-08 | 人工修改越权字段、不可用单位或超预算 | 拒绝采用，原建议与草稿不被伪标为已执行 |
| API-09 | 重复命令、同键不同输入或响应丢失 | 不重复执行，冲突明确，可按原请求查询 |
| API-10 | 超时后查询暂未找到命令 | 不把未找到当作已回滚证明，不换键盲目重发 |
| API-11 | 单步与继续遇到待确认 | 保持阻塞，轮询和关闭抽屉不能绕过 |
| API-12 | 存档退出失败或不存档退出 | 前者保留当前局，后者保留最近自动存档，不伪造保存成功 |
| API-13 | 读档命令返回新分支且更早步数 | 正确接受新上下文、暂停恢复，旧响应不覆盖 |
| API-14 | 复盘快速跳转与同一步多修订 | 返回实际快照定位，不混帧，不产生执行副作用 |
| API-15 | 私有引用、跨局令牌或无效媒体内容请求 | 无权资源不泄露，失败不返回空成功文件或内部路径 |
| API-16 | 目录凭据尝试游戏命令 | 作用域拒绝，必须使用对应本局席位会话 |
| API-17 | BigInt、十进制、空值与分页游标 | 类型和精度保留，未知不转零，游标不能跨方复用 |
| API-18 | 正式后端不可用但浏览器仍有演示缓存 | 明确错误，不切换为演示成功或伪完整存档 |

后续实施需同时落实 FastAPI 模型、统一错误、前端共享类型、请求适配层、数据库映射和契约样例。本文 JSON 仅验证结构可读，不替代接口测试；未同步实现、真实事务与权限场景不能标记为契约验收通过。

本轮只更新本文，未创建 API、OpenAPI、数据库迁移或新依赖。接口、数据样例与实施任务依照已存在的详细文档继续对齐，运行验收须另附实际证据。

## 15. 三项目融合契约

### 15.1 范围与兼容策略

本节承接 [系统架构融合流程](05系统架构.md#fusion)。场景版本、统一命令校验、基础回执、原 PRD-23 资料证据与数据完整性属于核心边界；完整资产编辑、单位 Agent、高级模型配置、完整导入导出为后续候选，反事实分析为后续 P2。源项目存在某个接口不代表本项目已支持同名动作。

本节字段均为拟议补充，落地前须与数据库、样例及请求响应类型共同审阅。原 `/api/v1` 和 `game-view-v1` 是协议草案标识；权限、必填字段、动作含义或数值单位变化不能冒充兼容可选字段。发布前明确资源 Schema 版本与兼容政策，客户端遇到不支持版本应报告原因，不能用演示数据补齐。

### 15.2 核心资源的融合补充

| 资源 | 拟补充的结构与关联 | 禁止混用 |
| --- | --- | --- |
| `GameView.game` 与 `map` | 已绑定场景、规则、资产映射与公开资源清单版本；坐标系及表现映射引用 | 清单不能包含隐藏动态单位、对方私有库存或内部文件路径 |
| `UnitView` | 可展示的模板版本、组织归属与模型映射引用；规则能力仍来自后端定义 | 编制父节点、人数、装备数量与实际参战单位数量分别表达；不按显示名称推导权限 |
| `CommandReceipt` | 继续表达应用命令处理结果，关联请求、来源上下文及实际结果快照 | `review_proposal` 成功仅证明处理及采用事实，不证明单位已完成其后续任务 |
| 执行事实视图 `CommandExecutionView` | 来源命令、方案、单位、实际动作、前后快照、已提交事件与可公开失败原因 | 持续动作可跨多个仿真步；按实际事实查询，不能每次读取生成新扣费 |
| `ProposalView` 与运行 | 来源类型、逻辑 Agent 或未来绑定引用、冻结依据、资料证据与实际处理关联 | 来源由后端核验，模型或客户端不能自行声明主持人身份、采用资格或执行成功 |
| 错误与能力 | 延续统一错误、`capabilities` 和字段定位；未支持资源或动作明确报告 | 不把未知、未支持、失败、无权和空集合统一返回空成功 |

`CommandExecutionView` 是拟议只读投影，可由现有命令、快照、事件及采用计划关联生成，未要求新增一张执行表。请求受理、计划采用、实际动作和持久化结果分别表达；“收到命令”不能成为扣资源、计损失或宣告完成的依据。

角色令牌只交付当前发布形态对应的受控客户端。相机位置、跟随距离、模型动画及帧率不进入业务命令；部署选点提交转换后的业务坐标，由后端校验。切换 Unity 总览与跟随无需发出推进或采用命令。

### 15.3 候选资源与路径草案

下表不扩展第四节的首版承诺；路径、权限及报文均待相应功能立项与 D-07、D-09 确认，未启用时不能返回伪造成功。

| 候选资源或路径 | 用途与最小内容 | 权限及副作用边界 |
| --- | --- | --- |
| `GET /asset-releases/{release_id}` | `AssetReleaseView`：源格式、映射版本、模板与资源版本、校验结果、公开资源引用 | 制作权限另定；对局中只读已绑定发布版本，不随编辑变更运行局 |
| `POST /asset-imports/preview` | 解析资产暂存内容，返回对象问题、依赖、源目标身份映射与预览依据 | 受控制作流程；预览不发布场景、不生成单位、不覆盖现有资产 |
| `GET /games/{game_id}/executions` | 查询允许读取的实际执行事实与关联回执 | 当前角色、分支与游标共同过滤；基础事实首版保留，完整检索界面后续完善 |
| `POST /games/{game_id}/imports/preview` | `ImportPreviewView`：输入格式、来源、版本兼容、身份冲突、资源依赖及恢复摘要 | 主持人；预览不切换分支，不能将全局私有内容返回红蓝 |
| `GET /games/{game_id}/unit-agent-bindings` | 授权单位、独立会话引用、绑定版本及有效状态 | 后续候选；仅本方授权内容，绑定不赋予直接写世界能力 |
| 模型配置、测试与取消资源 | `ModelProfileSummary`、运行标识、能力、配置版本、预算与脱敏失败 | 后续候选；具体路径待定，摘要不返回可复用密钥；取消不撤销已提交事实 |
| `GET /games/{game_id}/analyses/{analysis_id}` | `AnalysisView`：冻结来源、干预项、方法版本、假设、结果及证据状态 | 后续 P2；只能读取授权分析，不改变主局有效头、评分或胜负 |

资产发布、导入确认和单位绑定若获准实现，须另定义有身份与幂等保护的变更协议。涉及有效游戏世界的操作仍走统一命令入口；不因新增候选路径开放任意单位编辑、SQL、脚本或底层检查点写入。

### 15.4 预览、取消与分析语义

1. 预览绑定原始内容的规范摘要、格式版本、调用资格、依赖资源、目标上下文与输入修订；具体指纹和有效期待确认。修改输入、依赖或目标状态后重新检查，不能用旧令牌提交另一份内容。
2. 导入最终确认再次核对兼容性与身份冲突。只有完整校验及事务成功才切换恢复分支并暂停；失败保留原局、最近成功存档和明确错误。
3. 同一已成功导入请求的重试返回原分支结果，不能再次建分支；旧分支异步结果不能被改标签后应用到新局。
4. 模型取消须区分已请求、实际终态和结果待核对。供应商可能仍返回输出或计费；晚到输出须重新检查写资格，已提交动作不回滚。
5. 只读复盘读取已发生事实；分析结果明确标注假设。分析身份与可继续游戏的恢复分支分开，不允许分析调用主战局变更入口。

### 15.5 融合接口验收（未运行）

| 编号 | 情景 | 独立预期 |
| --- | --- | --- |
| API-MERGE-01 | 资源版本或映射缺失、不兼容 | 明确错误，不能加载另一版本伪装成功或从显示对象反推规则 |
| API-MERGE-02 | 当前角色获取资源、回执与执行列表 | 版本一致且字段、总数和游标均按权限过滤，无隐藏动态对象 |
| API-MERGE-03 | 已受理或已采用计划，但动作尚未完成 | 状态与实际事实可区分，不提前扣分或宣告任务成功 |
| API-MERGE-04 | 自然语言输入或导入内容在预览后变化 | 旧预览不可提交；当前合法资产与游戏不变 |
| API-MERGE-05 | 人工与单位 Agent 提交越权或未支持动作 | 同一规则入口拒绝，不因来源不同获得直接写世界能力 |
| API-MERGE-06 | 取消、超时、重复请求及晚到输出并发 | 原结果可核对；无重复采用、扣费、推进或虚构停止成功 |
| API-MERGE-07 | 导入成功响应丢失后使用原请求重试 | 返回同一恢复结果，保持暂停，不建立第二个分支 |
| API-MERGE-08 | 用分析 ID 访问恢复、执行或当前状态写入口 | 权限及资源类型检查拒绝，主局状态与正式结果不变 |

这些条目补充 API-01 至 API-18，与 RULE-22 至 RULE-36、ARCH-MERGE-01 至 ARCH-MERGE-12 配套；实际执行结果统一登记在 [测试与验收](11测试与验收.md#fusion-tests)。
