## 一、规则来源与适用关系

### 1.1 从《断箭》借鉴什么

《断箭》官方手册区分利用道路尽快到达的快速移动、遇敌停下交战的攻击移动，以及保留车辆朝向的倒车；官方指南介绍了高地、洼地、树林、城区及视线对行动的影响。依据分别为[官方手册第 19 页](https://ftp.matrixgames.com/pub/BrokenArrow/BrokenArrowManualEBOOK.pdf)和[Slitherine 官方玩法指南](https://www6.slitherine.com/news/mission-accomplished-how-to-win-in-broken-arrow)。手册为发行时资料，具体游戏细节可能随版本改变。

本项目借鉴指令意图、道路效率、兵种通行差异和路线可解释性。本文提出的寻路、通行矩阵、速度、能源、占用和冲突算法属于本项目设计，不声称为《断箭》的内部实现。

### 1.2 与现有规格的关系

| 内容 | 本文处理 |
| --- | --- |
| 一步一分钟、最多六十步、主持人控制推进 | 沿用，不改为按现实时间结算 |
| 一单位一步一个主动作、移动与占领／服务／交战互斥 | 沿用；到达当步不赠送第二个主动作 |
| 首次方案和重大调整人工确认、红蓝角色隔离 | 沿用；手动测试命令不绕过对局资格 |
| 现有地面仅沿道路网移动 | 新规则拟扩展为“道路＋合法接入段＋兵种限定越野”；仅新测试规则生效，旧规则保持原语义 |
| 现有无人机二维航线 | 首轮继续采用二维可飞区域；飞行高度作为表现参数，不启用高低空战术或三维飞行物理 |
| 当前测试的道路最短距离寻路 | 拟增加通行、宽度、坡度和完整接入段检查，并按移动时间选路 |
| 当前直接采用后端坐标的地图显示 | 后续可沿已提交路线插值播放；动画速度不成为规则速度 |
| 占点与保障能力 | 沿用现行目标规则；本文不实现积分、战斗、自动出兵或补给结算 |

正文与旧文档冲突时，不能把本文直接用于旧对局。启用新测试规则前，需在主规则、接口、快照和验收中同步登记新版本；旧存档继续引用其原地图与规则。当前 `s2-spatial-test-v1` 不能原地改名或替换参数冒充新规则。

## 二、共同移动原则

### MOV-01 时间、坐标与权限

1. 地面和空中距离一律用世界米制计算。现有业务坐标换算为 `world_x = business_x × 100`、`world_z = business_y × 150`；不能直接用 120×80 业务坐标计算欧氏距离。
2. `simulation_step = k` 为第 k 分钟的已提交状态。路线命令只改变计划；只有一次成功的 `k → k+1` 推进才消耗移动时间和资源。
3. 准备阶段只能配置与部署，拒绝行进命令。首次建议未确认或存在阻塞性待确认时拒绝新增移动且不能推进；对局结束后不能提交移动。
4. 暂停且无阻塞性待确认时可以安排路线；运行时的新命令在后端串行边界生效，不修改已经冻结或提交的步骤。
5. 红蓝操作员只能操作本方单位。主持人沿用既有命令权限；旁观、镜头跟随、拖动地图、选择单位均不移动部队。
6. 耐久失效、故障或互斥主动作占用时不执行移动。能源为零只停止依赖能源的移动，不直接判定单位被毁，也不自动扣除安全分。
7. 移动不能同时完成占领、补给、装卸或交战。无人机随行产生的被动观察仍按观察规则处理，不因此获得攻击或占点资格。

### MOV-02 路线的三种检查结论

| 结论 | 使用条件 | 是否允许执行 |
| --- | --- | --- |
| `executable` 可执行 | 所需静态数据有效，全部经过区域合法，单位和资源资格满足 | 可以提交；每步仍检查动态条件 |
| `needs_verification` 待核验 | 桥头连接、地表类别、必要尺寸或可飞数据缺失 | 不执行；不得自动补成平地、畅通道路或可飞区域 |
| `unavailable` 不可执行 | 已确认越界、阻挡、路网断开、坡度过大、能源不足或资格不满足 | 拒绝并保留原路线／位置；返回允许公开的原因 |

动态友军占用不直接把长期路线判为永久不可达；可以提交路线并说明可能等待。后端知道但本方未知的动态障碍，不得通过预览绕路或错误文本泄漏身份和位置；行动接触后按允许信息报告受阻。

### MOV-03 完整路线检查

检查对象包括全部线段及单位通行占地，不能只检查目标点、道路节点或线段中心。建筑边角、河岸、桥头、导航层转换和终点接入段都属于检查范围。

路口只有存在显式连接才能转入另一条路；桥上道路与桥下地面不能因二维投影相交而连接。建筑外观损坏不自动取消阻挡，地图纹理、阴影、树模数量和碰撞特效不直接改变通行政策。

## 三、移动指令

### MOV-04 指令及兵种资格

| 指令 | 侦察无人机 | 履带地面单元 | 六轮保障车 | 执行语义 |
| --- | --- | --- | --- | --- |
| 普通移动 `move` | 可用 | 可用 | 可用 | 在本兵种允许通行的区域中选择预计耗时最少的合法路线 |
| 快速移动 `fast_move` | 快速转场 | 道路快速行进 | 道路快速行进 | 无人机应用快速转场参数；地面优先使用完整道路通路，合法接入段使用普通速度 |
| 倒车 `reverse_move` | 不提供 | 可用 | 可用 | 最长 100 米的合法直线后退，保持车头朝向，不自动绕障碍 |
| 停止 `stop_move` | 可用 | 可用 | 可用 | 取消未执行的剩余路线，保持最近一次已提交位置与朝向 |
| 途经点 | 可用 | 可用 | 可用 | 按序经过最多 8 个途经点，最后一个为目的地；检查每段，不允许跨越禁区 |
| 返回兵营 `return_to_barracks` | 到合法停靠点 | 到合法地面集结点 | 到合法服务／库存接近点 | 使用对应移动方式寻路；不自动补给、不出售单位、不退款、不移除模型 |

返回目标为所属本方兵营的有效接近点；所属兵营无效时，按普通路线预计耗时选择具备所需接入能力的本方兵营，平局按稳定 ID。没有合法目标则拒绝，不能返回敌方或装饰性设施。

首次测试不提供“攻击移动”、步兵冲刺、战斗机加力、烟幕、自动追击或高低空切换。履带地面单元不是徒步步兵；保留倒车朝向也不自动产生装甲方向加成。以后接入攻击移动时，必须同时定义发现、停止、交战主动作及恢复路线，不能用普通移动按钮替代。

### MOV-05 途经点与改令

1. 单位同时只有一条活动路线。普通改令从当前位置替换未执行部分，不从兵营或旧路线起点重新出发。
2. 途经点是同一移动主动作的连续路径。通过途经点不额外停留一整步，也不获得服务或占领机会。
3. 无效改令不能清空原有效路线。有效改令提交成功后，旧剩余路线和旧途经点一起失效。
4. 停止不返还已经消耗的能源或时间。恢复行进需要新命令或重新采用原目的地；不能因刷新页面自动恢复。
5. 重大目标或任务改派继续进入既有人工确认流程；同一已采用目标下的局部避障不改变任务归属。
6. 倒车只接受一个终点，不接受折线途经点；不能通过连续短段绕过 100 米单次倒车上限。

## 四、地图通行矩阵

### MOV-06 地表通行与普通速度系数

以下系数为新测试规则建议值。`禁止` 表示明确不可通行；`待核验` 不允许当作系数 1。普通道路为通用道路类别，不预设为沥青或赋予未核实的材质属性。

| 规则区域／地表 | 侦察无人机 | 履带地面单元 | 六轮保障车 |
| --- | --- | --- | --- |
| 合法通用道路 | 按可飞区，不受道路系数影响 | 允许，1.00 | 允许，1.00 |
| 已标记碎石道路 | 同上 | 允许，0.80 | 允许，0.70 |
| 干燥坚实开阔地 | 同上 | 允许，0.65 | 允许，0.45 |
| 已标记干燥农田 | 同上 | 允许，0.50 | 允许，0.30 |
| 已标记可穿行疏林 | 同上 | 允许，0.40 | 禁止；只能使用林中合法道路 |
| 密林、沼泽、深沟、不可通行废墟 | 空中是否可飞单独配置 | 禁止 | 禁止 |
| 建筑、墙体、兵营封闭占地 | 不自动禁飞，由可飞区标记决定 | 禁止 | 禁止 |
| 河流、水塘等水域 | 可飞标记允许时通过 | 禁止，不具备涉水能力 | 禁止，不具备涉水能力 |
| 已验证可用桥面 | 按可飞区 | 允许，1.00，必须连接桥头 | 允许，1.00，必须连接桥头 |
| 地表、桥头或通行政策未知 | 必要空域信息缺失则待核验 | 待核验 | 待核验 |

林中有道路时按道路类别计算，不把树林减速再叠加到道路上；道路外才按林区政策。桥面只在其合法宽度、导航层和入口连接内覆盖下方水域限制，不能取消建筑阻挡或生成任意跨河路径。

区域选择优先级：地图边界 → 明确禁行／实体阻挡 → 已验证桥面层 → 水域 → 显式道路走廊 → 其他地表区域。其他区域重叠时使用场景冻结的唯一优先级；优先级缺失或冲突则阻止发布，不把同类地表系数连乘。

### MOV-07 坡度、宽度与占地

坡度使用无量纲比例 `grade = abs(高差) / 水平距离`，不是角度。上下坡首轮使用同一限制，陡下坡不额外加速。沿整条路径及规则采样间距检查，不能只比较路段两端高差。

| 最大局部坡度 | 履带速度系数 | 六轮保障车速度系数 |
| --- | --- | --- |
| `0 ≤ grade ≤ 0.10` | 1.00 | 1.00 |
| `0.10 < grade ≤ 0.20` | 0.85 | 0.70 |
| `0.20 < grade ≤ 0.35` | 0.60 | 禁止 |
| `grade > 0.35` | 禁止 | 禁止 |

建议首轮地面占地半径为履带 2 米、保障车 3 米；单侧安全余量为 1 米。因此最小通行净宽分别为 6 米、8 米。数值仅为规则测试包络，启用前必须校验与当前模型的显示占地是否相容；不得直接使用为观察而放大的模型尺寸，也不得让模型穿楼却声称规则已通过。尺寸未核验则相关用例标记待核验。

桥面和道路都检查净宽。拐角按占地膨胀后的可通行走廊检查，不能以中心线不碰撞代替整车通过。首轮不模拟车轴、悬挂或真实最小转弯半径；原地转向由表现层呈现，不额外计费。倒车路线必须位于当前车头反方向，允许方向误差 15 度，并保持原朝向；超出时提示重新选择目标，不自动转身再当作倒车。

### MOV-08 道路接入、桥梁与合法终点

1. 地面快速移动须由“起点接入段＋连通道路／桥面段＋终点接入段”组成。起终点应接入可见公开道路的合法边投影或显式入口，不强制连接最近路口节点。
2. 单侧接入段长度建议不超过 150 米。接入段只允许本兵种可通行的地表，按普通速度和能耗计算；不能直线穿水、穿楼或跳过桥头。
3. 150 米内无合法道路接入时，快速移动拒绝并提示可改用普通移动；不能静默执行一整条越野路线再标为快速移动。
4. 桥梁必须包含桥面、两端连接、宽度、高度、导航层和可用状态。任一关键项未知，不能仅凭 `isBridge=true` 标记可执行。
5. 地面目标落在建筑、水中或禁行区时明确拒绝。普通地表目标与道路接入可以分别预览，但不能悄悄把用户目标移到另一侧河岸或另一条路。
6. 首轮不提供任意终点自动吸附。返回兵营等对象指令使用预定义合法接近点，并在确认前显示实际落点。
7. UAV 目的地为合法可飞坐标或合法停靠点；飞过仓库或停靠点不自动停靠和补能。进入停靠、补给或起飞仍遵守各自的动作与服务资格。

## 五、各兵种移动参数

### MOV-09 基础量与模式修正

| 参数 | 侦察无人机 | 履带地面单元 | 六轮保障车 | 来源 |
| --- | --- | --- | --- | --- |
| 普通基础移动量 | 800 米／步 | 400 米／步 | 300 米／步 | 沿用现有 S2 测试值 |
| 初始测试能源 | 100 | 100 | 100 | 沿用现有 S2 测试值；不重置已有单位 |
| 基础移动能耗 | 5 能源／公里 | 8 能源／公里 | 10 能源／公里 | 沿用现有 S2 测试值 |
| 快速模式速度倍率 | 1.25 | 1.25，仅道路／桥面段 | 1.25，仅道路／桥面段 | 新建议 |
| 快速模式每米能耗倍率 | 1.25 | 1.20，仅道路／桥面段 | 1.20，仅道路／桥面段 | 新建议 |
| 倒车速度倍率 | 不适用 | 0.40 | 0.35 | 新建议 |
| 倒车每米能耗倍率 | 不适用 | 1.10 | 1.10 | 新建议 |

普通无人机每步 800 米，快速转场每步 1,000 米。平直通用道路上，履带普通／快速分别为每步 400／500 米，保障车为每步 300／375 米。快速移动减少行进步数，但增加单位距离能耗，不保证比普通移动更省能源。

首轮只计算实际行进距离的移动能源，不新增悬停、原地转向、载重、怠速、风力或天气燃料模型。该简化不是现实能耗结论；能源不能因暂停、动画播放或现实离线时间扣减。补给库存与移动能源分开，保障车开车不直接扣除服务库存。

### MOV-10 分段计算与单步预算

将路线切分为地表、坡度、移动模式和导航层均一致的区间。设第 i 段实际距离为 `L_i` 米：

```text
有效移动量_i = 基础移动量 × 模式速度倍率_i × 地表速度系数_i × 坡度速度系数_i
耗时_i = L_i / 有效移动量_i                         单位：仿真步
能耗_i = L_i / 1000 × 基础每公里能耗
         × 模式能耗倍率_i / (地表速度系数_i × 坡度速度系数_i)
```

无人机的地表和坡度系数均为 1；首轮航程按二维米制距离，不把地面道路或山坡系数套到空中。空中合法性由显式可飞／禁飞区域决定，不能由地面山峰外观推断。

1. 每步分配 1.0 步时间预算，沿路线逐段扣减。不能给每一段分别发放一次完整移动量。
2. 经过一段后，剩余时间可继续用于下一段；剩余预算不足时停在当前段内的准确位置。
3. 能源不足时按剩余能源限制实际前进距离，不扣成负数。预览已知整程能源不足则拒绝新路线；途中因其他已生效规则导致资源不足时，停止在最后合法位置并记录进度。
4. 途中到达终点则记为已到达，剩余时间不转成占领、服务或交战。抵达兵营也不能在同一步补满并重新出发。
5. 单位本步发生过移动，即使步末已到达占点区，也不能算作一个完整占领步。下一步才可选择 `capture/hold` 等主动作。
6. 地面距离取规则路径的表面长度；空中首轮取二维航段长度。长路线预览的预计步数为总耗时向上取整；动态等待另行说明。
7. 规则数值使用规范十进制。计算至少保留 9 位小数，快照中的米制位置和能源保留 6 位小数，统一四舍五入；以累计精确路程与累计能耗推导当前值，不按每个采样点累计舍入。恢复需保存累计量及算法版本，分支继续不能产生舍入漂移。
8. 地表和坡度系数只各选一次。禁止、未知和零有效速度在计算前处理，不能出现除零或用极小速度代替不可通行。

### MOV-11 三个独立预期示例

以下均假设不受占用、坡度或其他事件影响，且单位能源足够。

| 示例 | 独立计算 | 预期 |
| --- | --- | --- |
| 履带在平直通用道路移动 1,000 米 | 普通 `1000/400=2.5` 步，能耗 8；快速 `1000/500=2` 步，能耗 9.6 | 普通第 3 步到达；快速第 2 步到达 |
| 保障车依次经过 300 米道路和 135 米坚实开阔地 | 道路 1 步；开阔地速度 `300×0.45=135` 米／步，需要 1 步；能耗 `3+1.35/0.45=6` | 共 2 步到达，库存不因行进下降 |
| 无人机跨河飞行 1,600 米 | 普通 2 步、能耗 8；快速 1.6 步、能耗 10 | 二者第 2 步到达，但快速在该步更早抵达；不赠送额外动作 |

按步结算可能出现普通与快速到达步数相同的短途情景。这是固定一分钟步长的结果，不靠加速动画伪造额外规则收益。

## 六、选路、占用与受阻

### MOV-12 路线选择标准

1. 先排除不可通行或必需参数未知的路线，再计算时间和能源。
2. 普通移动在全部本兵种允许区域中选择预计耗时最少的路线；快速移动只比较合法的道路接入与道路通路；倒车不进行绕路搜索。
3. 预计耗时相同，优先能耗更少；再相同时，优先更短；仍相同则按稳定道路／导航单元 ID 序列排序。相同输入必须得到相同结果。
4. 首轮不把隐蔽、掩护或隐藏敌人加入自动选路成本，也不声称普通移动会自动选择最安全路线。途经点可表达用户的绕行意图。
5. 后续若加入谨慎移动，应使用本方有效已知信息和独立风险政策；不能读取主持人全局敌情来替玩家绕开未发现单位。
6. 十二公里地图建议采用道路级选路与局部导航结合。规则要求完整路径合法，不限定必须使用某个引擎或新增第三方寻路依赖。

### MOV-13 动态占用的首轮简化

1. 地面使用规则占地包络，不能相互穿过或把两个中心写到同一位置；桥面可用通行带独立于桥下地面。
2. 每步先冻结所有单位的行动意图，再共同处理时空占用，不能完整结算红方后才计算蓝方。
3. 移动执行器内采用固定的 1 仿真秒占用片段，每步 60 片段。它仅用于同时移动与碰撞检查，不新增交战、占领或服务次数；每片段仍检查扫掠占地，不能因离散采样穿透对象。
4. 桥面首轮按单向通行批次处理，即使外观足够宽，也不默认支持两车对穿。批次内部保持安全间距；桥已占用时优先让已上桥单位驶离，不把桥下单位算作占用桥面。
5. 同时到达空闲冲突入口时，先等候更久者先行；等待相同则使用冻结的单位稳定 ID 排序。该规则与阵营无关，且需在后续公平性测试中检查固定 ID 偏差，不能据此宣称平衡已通过。
6. 冲突失败者保留最后合法位置并累计等待，不扣未走距离的能源。本步等待后通路释放，可使用本步尚未消耗的时间；不能补回上一步的时间。
7. 连续 2 个完整步无进展则尝试重算同目标路线；仍不可达时进入受阻状态，不持续无提示抖动。无绕行空间的对向拥堵可以要求人工改令，不把“会等待”宣称为完整交通调度。
8. 首轮不实现空中单位相互碰撞；无人机可以共享二维航段或坐标。此简化必须在测试信息中说明，不向地面单位扩展。

1 秒片段是新测试规则的确定性执行精度，并非当前后端已经存在的机制；如果实施时选择其他精度，必须更换算法版本并重跑同时移动验收。

### MOV-14 中断、重新检查与信息边界

| 变化 | 处理 |
| --- | --- |
| 用户成功提交新目标 | 从当前已提交位置替换剩余路线 |
| 用户停止 | 清空活动目标和未执行队列，保留历史路线事实 |
| 友军暂时占路 | 等待，按动态占用规则处理 |
| 已启用事件使道路不可通行 | 停在受影响连接之前；对本方可知条件重新寻路 |
| 故障或移动能源耗尽 | 保留位置、路段游标和目的地，标记资源／状态受阻，不瞬移返营 |
| 故障恢复或完成补能 | 重新检查剩余路线；通过后才可恢复原已采用移动意图，不能刷新页面就清除受阻 |
| 新观察报告出现 | 不擅自追击或修改目标；如影响重大方案，按原人工确认流程处理 |
| 摄像机、显示层、帧率变化 | 不重新选路、不消耗资源、不推进仿真 |
| 读取旧存档 | 恢复对应规则、路线进度、累计能耗、朝向和占用／等待状态，暂停等待操作 |

桥梁破坏、道路临时关闭等事件只有在相应规则已启用时才存在；本文定义移动如何响应通行变化，不新增破坏武器或事件入口。未知敌方阻挡只能返回本方允许知道的“前方受阻／条件待核验”，不能返回隐藏单位坐标、阵营或数量。

## 七、表现、数据与回执

### MOV-15 单位状态与地图显示

建议移动状态为：待命 `idle`、路线已排队 `queued`、移动中 `moving`、等待通行 `waiting`、受阻 `blocked`、已到达 `arrived`。停止成功后回到待命；命令拒绝是命令结果，不能顺带覆盖原路线状态。

选中单位时显示：移动模式、实际目的地、已确认路线、预计剩余步数、当前能源、预计到达能源、等待／受阻原因。路线预览与已确认路线分开，待核验和不可执行不能使用可执行颜色。

后端保存规则位置、导航层、路段进度、运动朝向及资源事实。Unity 只能沿本次已提交的路径轨迹补间，不能自行换路或预先进入下一仿真步。暂停期间可播完已经发生的表现，但不能继续生成行进事实；补间未结束时位置相关命令仍按后端最新位置预览，并明确显示真实命令起点。

桥面高度使用桥面规则几何，桥头通过显式连接过渡；不得把桥上单位贴到河床。无人机首轮仍以二维合法航线为规则依据；当前 48 米相对地表的显示高度不是三维飞行能力证据。若显示高度与建筑相交，应修正表现或可飞区域数据，不擅自增加或绕过空中能力。
