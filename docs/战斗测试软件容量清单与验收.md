# 战斗测试软件容量清单与验收

## 1. 确认范围与当前状态

2026-11-14 用户确认本地测试版容量：每方每类 **0～10** 个，**每方至少1个**，每方最多30个、双方最多60个。允许非对称编制；超过容量须完整拒绝，不能截断到10个。单类0合法，不允许三类都为0。

这是《青岚游戏规则总册》4.1 所要求的**软件发布容量声明**，不是总册的固定兵力、平衡规则或“正式性能已通过”的认证。编制增减不得改变单位能力、复活已经退场的单位或重置开局资源/击毁价值分母。

本次实现以下基础：

- `backend/battle-capacity-v1.json`：独立、版本化的软件容量清单。
- `backend/battle_capacity.py`：清单一致性、严格数量与完整名册校验；独立草案登记。
- `backend/battle_contracts.py`：未来总册战斗模式的严格输入契约 `BattleArmyQuantities`、`ConfigureBattleArmy`。
- `SandboxService.seed_versions()`：登记软件容量草案，不绑定场景或对局。

**未激活总册战斗执行器，也未给旧API放宽数量限制。** 新契约尚未加入既有 `PAYLOAD_MODELS`，不能通过提交一个新命令名绕过对局规则版本。旧 `ArmyQuantities` 仍保留1～10边界。总册基础草案的 `capacity_limit=null` 保留原始内容，通过独立容量版本引用补齐软件声明，不覆盖已经入库的同标签载荷。

其余战斗任务仍待接入：模式选择和依赖检查、双方草稿与主持人60秒统一结算、持续占点、精确资源台账、有限公共补给、总册计分和不泄漏未来信息的动画播放。**这些不能从容量校验测试通过推断已经完成。**

## 2. 校验与失败处理

- 数量必须是严格整数，拒绝布尔值、字符串、浮点数、负数、空值及大于10。
- 必须完整提供 `recon`、`ground`、`support`，不接受额外兵种或额外字段。
- 完整名册必须同时有红蓝双方，单位身份非空、全局唯一，兵种/阵营合法。
- 分别校验每方每类，不能只用“双方合计≤60”放过单类11个。
- 输出包含非对称标记，不隐式补齐或归一化编制。
- 校验不修改输入，不部分部署，不扣资源，不推进仿真。
- 清单与代码约束不一致立即拒绝加载，不将空值解释为无限。
- 登记采用参数化SQL、事务级锁和幂等检查；同名不同内容拒绝并回滚。所引用的总册版本必须已经登记且摘要一致。

## 3. 数据库影响、备份与登记

使用既有 `sandbox.rule_versions` 表，没有新增表、字段、索引或约束，没有DDL迁移。新增独立行：

- `rule_code = qinglan-software-capacity`
- `version_label = qinglan-local-test-capacity-2026-11-14-v1`
- `availability = draft`
- `is_demo = true`
- `definition.integration.status = declared_not_activated`
- 无 `scenario_versions` / `games` 绑定。

登记前记录旧规则摘要、场景摘要、对局绑定/头快照/控制版本，以及快照/指令/事件/存档数量；登记后核验不变。只保存摘要/计数，不导出席位令牌或数据库凭据。完整项目常规备份仍由既有备份流程负责，本次不重置账号、不重建业务库。

项目根目录命令：

```sh
.local/backend-test-venv/bin/python -m backend.battle_capacity check
.local/backend-test-venv/bin/python -m backend.battle_capacity register
.local/backend-test-venv/bin/python -m unittest backend.tests.test_battle_capacity -v
.local/backend-test-venv/bin/python -m backend.portable test
```

真实登记仅使用既有本机应用连接；规则总册原文SHA漂移、数据库不可用、来源摘要不符或标签冲突时不发布新内容，保留原版本并报告失败。

只读核验SQL：

```sql
SELECT id, version_label, availability, is_demo, payload_sha256,
       definition->'capacity' AS capacity,
       definition->'rulebook' AS source_rulebook,
       definition->'integration' AS integration
FROM sandbox.rule_versions
WHERE rule_code = 'qinglan-software-capacity';
```

## 4. 验收、风险及监控

### 已提供的自动化用例

1. 单兵种1、其余0合法；三类10、双边60合法且不截断。
2. 全0、11、负数、布尔值、浮点数、字符串、缺少/额外字段拒绝。
3. 红蓝非对称如1对30合法并显式标记。
4. 一方空名册、重复身份、未知兵种/阵营拒绝。
5. 清单与代码不符拒绝加载；旧输入契约未被放宽。
6. 隔离PG登记、幂等、同名冲突回滚；总册基础草案、场景、对局及快照不变。

### 尚待验收

- 最大60单位下的真实WebGL帧率、内存、路径计算时延和60秒结算性能。
- 总册执行器使用此容量校验后，单位创建/修改/删除与开局固定名册的统一权限、事务和并发保护。
- 新模式完整流程与逐轮播放实测。

因此容量清单保持 `formal_release_certified=false`、草案未激活。声明一个边界不代表已经完成正式负载测试。

| 风险 | 影响 | 处理 |
|---|---|---|
| 把独立清单误认为旧API已支持0 | 旧页面配置被拒绝 | 新旧契约隔离，文档明确未接入 |
| 只校验双方总数 | 单类超限 | 每方每类和每方合计分别校验 |
| 用存活数重新冻结名册 | 分母漂移或单位复活 | 名册校验仅用于开局，不作为期中重算接口 |
| 将容量声明误作正式性能认证 | 大编制卡顿 | 保留未认证状态，完成WebGL负载测试后另发版本 |
| 同名容量被改写 | 不同客户端约束不一致 | 摘要、确定性ID、标签冲突拒绝并回滚 |

日志/审计记录存于 `.local/battle-capacity-20261114/`，不包含密码、Bearer或模型原始输出。登记结果显示规则ID、摘要、是否首次插入；测试日志区分接口校验和WebGL负载验收。

## 5. 回滚

1. 代码回滚仅撤销本次新增的容量模块、独立契约、测试和 `seed_versions` / 测试列表中的对应新增行；不要恢复整个已有大量未提交修改的文件。
2. 通常无需删除数据库行：独立草案不绑定场景/对局，不影响旧执行器。
3. 若确需移除本次新登记且无引用的草案，先核对ID/摘要并在事务中执行下列SQL；若未来已绑定，拒绝删除而不是级联删除对局。应用账号若没有删除权限，须使用既有授权管理流程，不能临时提权。

```sql
BEGIN;
DELETE FROM sandbox.rule_versions r
WHERE r.rule_code = 'qinglan-software-capacity'
  AND r.version_label = 'qinglan-local-test-capacity-2026-11-14-v1'
  AND r.availability = 'draft'
  AND NOT EXISTS (SELECT 1 FROM sandbox.scenario_versions s WHERE s.rule_version_id = r.id)
  AND NOT EXISTS (SELECT 1 FROM sandbox.games g WHERE g.rule_version_id = r.id);
COMMIT;
```

失败时回滚整个登记事务，保留既有总册草案、所有旧局与版本；不通过修改 `availability` 冒充规则接入成功。
