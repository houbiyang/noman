# 多智能体模型配置与连接测试

更新：2026-11-11。本文描述已实现的 1 / 2 / 7：Embedding 配置、Reranker 配置、独立真实协议连接测试，不代表已通过某个付费供应商的实测验收。

## 1. 入口与配置归属

沙盘右上角齿轮 → **服务连接 → 多智能体协同工作台**。本机默认入口为 <http://127.0.0.1:18766/agents>。

1. 选择红方或蓝方并连接当前对局；主持人不能读取、配置或测试双方私有模型。
2. 填写建议生成模型，展开“向量检索模型配置与连接测试”“重排序模型配置与连接测试”。三类模型可以分别启用。
3. 每类都有独立测试按钮。测试读取**这一类模型的当前草稿**，不要求先保存，不受另外两类未填字段影响；禁用状态也可测试。
4. 测试前有费用确认，只发合成短文本，不发对局或私有文档。成功显示耗时、向量维度；失败显示明确错误。测试不保存、不隐式启用、不自动重试，超时不代表未计费。
5. 点击“保存本方配置”才保存三类模型及原有四角色策略；红蓝独立。保存成功不代表远端可用。
6. “规则检索验证”使用**已保存**的本方配置，返回可展开的原文、来源和版本。建立向量缓存、检索和规划都可能产生模型费用。

旧设置中的红方 AI / 蓝方 AI 重复入口已移除；原本机草稿存储结构保留，**不会自动迁移或覆盖工作台配置**。刷新运行状态不覆盖未保存的表单；主动重新连接会重新加载已保存配置。

## 2. 字段与协议

| 类型 | 请求地址（拼接接口根地址） | 主要参数与校验 |
| --- | --- | --- |
| 建议生成 | `/chat/completions` | 保留已有模型、温度、超时、输出 token 字段、推理强度和四角色策略；独立测试最多请求 256 输出 token，拒绝空响应或截断响应 |
| Embedding | `/embeddings` | OpenAI 兼容协议，`encoding_format=float`；维度 1–8192、召回条数 1–20、冻结规则版本、超时 1–120 秒 |
| Reranker | `/rerank` | `model/query/documents/top_n`；响应 `results: [{index, relevance_score}]`，保留条数 1–20、超时 1–120 秒 |

接口根地址应包含服务要求的版本前缀，例如 `https://your-provider.example/v1`；不是把完整 `/embeddings` 写入根地址。仅允许 HTTPS 或本机回环 HTTP；禁止 URL 中的账户密码、查询参数、片段以及明文密钥字段。

Embedding 当前**不发送降维参数**；模型默认返回维度必须与表单完全一致。向量条数、索引、维度、有限数值及非零向量都验证。Reranker 索引必须唯一且不越界，结果条数与请求匹配、分数有限；供应商返回的文档文本不采信，只重排已校验的原文。需要其他供应商协议时应增加明确适配器，不以 HTTP 200 直接判成功。

## 3. 密钥与持久化

页面只填写**后端进程的环境变量名**，不填写密钥值。默认：

- 红方：`RED_AI_API_KEY`、`RED_EMBEDDING_API_KEY`、`RED_RERANK_API_KEY`
- 蓝方：`BLUE_AI_API_KEY`、`BLUE_EMBEDDING_API_KEY`、`BLUE_RERANK_API_KEY`

也可使用现有 `MOONSHOT_API_KEY` 等变量名。先在启动后端的环境中设置实际密钥，再启动/重启后端；工作台不会替用户创建供应商账户、配置额度或修改系统环境。仅本机回环模型允许不填写密钥变量名。不要把实际密钥提交到仓库、URL 或配置 JSON。

配置复用现有每方独立 JSON 存储，包含 `model`、新增 `embedding` / `rerank` 及角色策略；不需要数据库迁移。旧配置缺少新增字段时按禁用默认值兼容。数据库运行记录保存冻结配置与检索检查点，密钥值不会写入其中。

## 4. 真正进入规划的检索流程

- **两者禁用**：保持既有规划行为；既有知识查询仍走原 LightRAG 网关。
- **仅 Reranker 启用**：先由本方已就绪的 LightRAG 检索并验证原文，再调用本方重排序模型。LightRAG 尚未发布时明确失败，不伪造命中。
- **Embedding 启用**：对 `knowledge/<冻结版本>/manifest.json` 白名单和哈希校验通过的规则原文分片，调用本方 Embedding，按余弦相似度召回并按文档去重；如启用 Reranker，再做真实重排。
- 该轻量路径不连接、重建或覆盖已有 LightRAG 图索引。最多 128 个片段、每片 800 字符、每批最多 16 条；大语料应使用已有 LightRAG 部署。
- 进程内最多 8 份向量缓存，30 分钟有效；按阵营、完整向量配置、凭据摘要和语料摘要隔离。配置/凭据/语料变化后不错误复用旧向量；重启会重新嵌入。
- 规划冻结本方配置、局势与规则版本，检索证据进入侦察、陆兵、保障、总指挥四角色输入。检查点持久化本次原文证据，失败后恢复不重复检索已完成的证据。
- 工作台运行详情可展开本次检索来源、规则版本及原文。对方席位不可读。

检索结果始终为 `planning_only=true` / `execution_authorized=false`。规则版本与当前局不一致会明确标记；候选证据不等于已评估支持，不授予行动权限，不替换比赛规则或计分器。最终仍经规则工具校验及本方人工采用，检索不会移动单位。

## 5. 接口

均沿用 `Authorization: Bearer <本方席位令牌>`：

- `GET /api/v1/games/{game_id}/agents/configuration`
- `POST /api/v1/games/{game_id}/agents/configuration`：完整本方配置。
- `POST /api/v1/games/{game_id}/agents/models/test`：新增独立测试接口。`configuration` 是**指定的一类模型**，不是完整 `AgentConfiguration`。
- `POST /api/v1/games/{game_id}/knowledge/query`：沿用接口，按已保存本方配置选择检索路径。

向量测试示例（此处仅示例，无有效供应商或密钥）：

```json
{
  "kind": "embedding",
  "configuration": {
    "enabled": false,
    "base_url": "https://your-provider.example/v1",
    "model": "your-embedding-model",
    "credential_ref": "RED_EMBEDDING_API_KEY",
    "dimensions": 1536,
    "top_k": 8,
    "timeout_seconds": 30,
    "knowledge_version": "conquest-v1-20261110"
  },
  "acknowledge_cost": true
}
```

`kind` 支持 `model` / `embedding` / `rerank`。返回 `success/side/kind/model/elapsed_ms/details/saved:false/notice`。未确认费用、伪造方位、未知字段或参数超界返回校验错误；主持人 403；凭据未就绪 503；远端认证、限流、重定向或协议异常转为脱敏错误；超时 504。相同配置域和阵营已有测试时返回 409，避免连点重复计费。

请求不使用系统代理、不跟随重定向、不自动重试；响应限制 4 MB，每次请求有总超时，向量检索整体限制 60 秒。错误不回显供应商响应正文、认证头或密钥。

## 6. 验证边界

自动测试使用本机模拟供应商协议和隔离 PostgreSQL 测试库，覆盖三类请求、真实向量排序/缓存隔离、坏响应和超时、红蓝权限与保存、无游戏修改、四角色证据传递及恢复复用。浏览器通过真实 HTTP 访问本机模拟服务验证三个独立测试按钮；未将模拟配置保存到用户配置。

尚未使用用户真实密钥请求付费供应商，因此**不声称真实账户额度、厂商兼容性、检索质量或正式对战策略已经验收**。启用实际模型前请填入已开通的模型与对应维度，先分别测试，再保存，并用“规则检索验证”检查命中质量。
