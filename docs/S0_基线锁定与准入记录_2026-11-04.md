## 3. 范围冻结

### 3.1 当前 P0 目标

以下内容作为首版正式仿真的目标范围，进入后续开发计划：

- 三角色：主持人、红方操作员、蓝方操作员。
- 一张固定虚构地图和固定场景版本。
- 每方一个兵营、三类初始单位和准备阶段配置。
- 一分钟一个仿真步、最多 60 步。
- 区域巡查、物资护送、关键设施保护、受损设备撤离四类任务。
- 侦察、地面、保障三类单位职责。
- 地形通行、路线、视野、通信和发现。
- 设备故障、通信中断、天气变化、任务变化四类事件。
- 陆兵抽象交战、战损、任务状态和统一结算。
- 资源、安全、任务和总分结果。
- 自动存档、多个手动存档、恢复分支、历史和只读复盘。

### 3.2 当前 P1 目标

- AI 总指挥、侦察、陆兵和保障四类逻辑智能体。
- 结构化报告、候选方案、工具调用、取消、超时和检查点。
- 资料导入、解析、审核、版本、混合检索、重排序和原文引用。
- 建议与状态版本、模型运行、资料证据和未知项绑定。

### 3.3 当前 P2 候选

- 编制资产编辑、地图资产编辑、导入预览和导出。
- 单位级 Agent、开放推演和反事实分析。
- 多地图、战役目录、自然语言想定和高级配置。
- 鲲鹏服务端、OpenHarmony 终端和目标设备实机适配。

没有经过变更评审，不新增兵种、地图、正式页面、数据库表、第三方依赖、模型服务或公网发布范围。

## 4. 已锁定的技术决策

这些决策描述当前实现和 S0 技术基线；涉及正式玩法的部分仍需产品或规则负责人确认后才成为正式规则。

| 编号 | S0 技术结论 | 后续限制 |
| --- | --- | --- |
| T-01 | Unity 负责三维地图、单位模型、相机、HUD 和页面交互；后端负责权威状态 | Unity 动画、视觉寻路和相机不能直接修改权威状态 |
| T-02 | FastAPI 作为本机 HTTP 服务入口 | 当前不承诺公网部署、集群和高可用 |
| T-03 | PostgreSQL 保存游戏、成员、会话、命令、快照、事件、建议、存档和分支事实 | 完整规则字段需随正式运行态 Schema 冻结 |
| T-04 | pgvector 仅作为已建数据库能力 | 没有真实模型、真实资料和正式向量空间前，不宣称 RAG 完成 |
| T-05 | 每次写入使用 Bearer 会话、状态上下文和 UUID 幂等键 | 页面不能通过修改 URL、角色字段或正文取得权限 |
| T-06 | 成功命令、快照、事件和自动存档在同一事务中提交 | 数据库失败时不得显示成功状态 |
| T-07 | 读档创建新分支，旧分支的执行资格不能继续写入当前分支 | 完整运行态恢复字段在 S2/S5 继续冻结 |
| T-08 | WebGL 使用浏览器 `fetch` 桥接，桌面使用系统 HTTP | 仍需完成页面内三席位连接的最终浏览器验收 |
| T-09 | 当前后台节奏为本机单进程 | 多实例节奏租约属于后续工程范围 |
| T-10 | 页面和后端明确标识 `fixed_demo`、`record_only`、`not_adjudicated` 和 `visual_target_only` | 不能将演示状态写成正式 AI、战斗、寻路或评分结果 |

在不等待所有正式战斗参数的情况下，S1 可以先执行以下工作：

1. 完成 Unity 页面内填写席位令牌并连接后端的浏览器验收。
