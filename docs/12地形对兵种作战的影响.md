# 地形对兵种作战的影响与参数设计

版本：v0.1  
编写日期：2026-11-03  
适用项目：鲲鹏鸿蒙无人智能作战地图沙盘  
文档性质：虚构数字沙盘的规则设计稿与参数清单

本文说明地图如何参与侦察无人机、陆兵和保障单位的移动、观察、交战与任务执行。文中的新增机制、字段及计算方式均为设计建议，尚未表示后端已实现或验收通过；具体数值保留为 **[待确认]**。

## 一、设计目标与适用范围

地图需要回答七个问题：单位能否到达、移动需要多久、资源是否足够、能否发现目标、当前动作路径是否成立、地形是否改变合法交战的结果，以及能否完成现场操作和保障。

相同兵种、相同任务和相同初始资源，在不同道路、遮挡和设施条件下，应得到能够解释、复现和复盘的结果。地图影响由后端规则计算，Unity 根据已提交状态呈现。

### 1.1 既有规则与新增建议

| 类别 | 内容 | 使用要求 |
| --- | --- | --- |
| 已确认规则 | 地面沿道路网移动；无人机按二维可飞区检查整条航线；发现需要范围、遮挡和共享条件满足；保障需要合法位置及库存 | 沿用现行规则，实际实现与验收另记 |
| 已确认规则 | 每步一分钟、单局最多六十步、每单位每步一个主要动作、同一步统一结算 | 地形判定不额外增加仿真分钟或赠送动作 |
| 已确认规则 | 首版陆兵对陆兵进行确定性抽象交战；无人机不攻击；保障单位不自动获得攻击能力；兵营不参与伤害 | 参数配置不得扩大对象资格和兵种能力 |
| 本文建议 | 地形移动成本、规则高程、独立动作射线、隐蔽、确定性掩护、地形影响回执 | 参数与政策确认后逐项启用 |
| 后续扩展 | 自由越野、建筑驻扎和楼层、动态建筑／桥梁破坏、烟幕、复杂弹道、飞行高度层 | 单独定义动作、状态、事件和验收用例 |

天气继续按既有五步延迟规则设计，具体作用阶段仍需锁定。画面的雾、雨、阴影和云层不自动产生视野、禁飞、伤害或移动惩罚。

### 1.2 《断箭》的参考方式

《断箭》官方指南介绍了地形与视线、建筑及废墟保护、单位观察能力和补给位置之间的联系，可作为地图与兵种交互的游戏设计参考。[官方生存指南](https://brokenarrow_backend.slitherine.com/news/broken-arrows-survival-guide)、[官方玩法指南](https://www6.slitherine.com/news/mission-accomplished-how-to-win-in-broken-arrow)

本文据此提出本项目的数据与规则组织方式。本文不复现《断箭》的隐藏公式，不将其秒级反应、真实装备名称、补丁数值或完整兵种体系转为本项目默认参数。以下矩阵及示例均属于本项目设计建议。

## 二、地形影响的七个维度

| 维度 | 要回答的问题 | 建议输出 | 与其他维度的区别 |
| --- | --- | --- | --- |
| 通行 | 当前兵种是否能沿这段路径到达 | 允许、禁止、条件待核验及原因 | 不可通行必须显式表达，不能只设置极高成本 |
| 移动成本 | 合法路径消耗多少行动距离、时间和资源 | 分段成本、预计步数、所需资源 | 能通过不等于能够按期限和现有资源完成 |
| 观察 | 能否取得目标的当前有效信息 | 当前可见、历史已知、未知及来源 | 作用范围内也可能因遮挡无法发现 |
| 隐蔽 | 地形是否改变被发现条件 | 已启用政策下的发现条件修正 | 隐蔽不直接等于减伤 |
| 动作路径 | 执行者到目标之间是否满足该动作的几何条件 | 合法、受阻及规则原因 | 共享观察有效也不保证自身动作路径成立 |
| 掩护 | 已经合法的交战是否受到保护效果影响 | 确定性的抽象作用修正 | 掩护只在合法交战之后计算，不替代观察和路径检查 |
| 任务与保障 | 是否到达要求的操作、接近、停靠或交接位置 | 可操作、等待、受阻及依赖 | 屏幕上接近不代表满足服务和任务条件 |

建议坚持以下判断关系：

```text
合法场景与规则版本
        ↓
兵种能力、当前状态、已采用方案
        ↓
路径与资源检查
        ↓
当前有效信息与观察检查
        ↓
动作资格、作用范围与动作路径检查
        ↓
已启用的隐蔽／掩护等政策
        ↓
统一结算、回执、快照与复盘
```

上图描述检查职责，具体同一步执行阶段须与规则文档锁定；不能据此允许单位在同一步先移动、再免费交战或补给。

## 三、地形与三兵种影响矩阵

下表中的通行和服务边界沿用现有设计；移动修正、隐蔽及掩护效果只有在对应政策启用后生效。所有倍率、阈值和距离均为 **[待确认]**。

| 地形／对象 | 陆兵 | 侦察无人机 | 保障单位 | 需要配置的重点 |
| --- | --- | --- | --- | --- |
| 开阔地 | 仍按合法道路行动；可作为观察与掩护比较的基准场景 | 按可飞区与能源行动 | 按道路及合法服务点行动 | 地表边界、道路、观察政策、明确的无附加效果政策 |
| 主干路 | 通过道路边连接，按路段政策计算成本 | 地面道路不限定航线 | 通过道路网运输和接近服务点 | 连接、方向、路面、宽度、通行与成本政策 |
| 支路与路口 | 检查连接是否真实存在，不能从视觉交叉直接转入另一条路 | 按独立航线判断 | 检查服务入口与支路是否连通 | 路口节点、转接关系、导航层、边界容差 |
| 林地 | 沿合法道路经过；减速、隐蔽和掩护分别配置 | 地面减速不作用于飞行；林冠观察影响另定 | 不自动获得穿林越野能力 | 林区范围、密度等级、林冠高度、兵种适用政策 |
| 灌木与草地 | 可作为独立观察或地表成本类别，但不自动提供建筑式保护 | 按传感器政策处理 | 保持地面通路与交接限制 | 地表分类、适用能力、效果启用状态 |
| 农田 | 不能因看起来平坦就离开道路自由移动；附加成本待确认 | 依据可飞区与观察政策 | 沿配置道路运输 | 农田区域、道路覆盖、移动响应政策 |
| 城市街区 | 道路决定到达，建筑和墙体分别影响观察及动作路径 | 不自动获得对建筑背面的全知观察 | 街区服务点必须有合法接近路径 | 街巷拓扑、建筑占地、遮挡体、服务接入 |
| 建筑与墙体 | 检查占地阻挡；驻楼尚未启用；掩护属于独立建议 | 按自身观察政策检查遮挡 | 隔墙相邻不能直接完成交接 | 底部与顶部高程、通行／观察／动作阻挡政策 |
| 废墟与战损外观 | 仅在独立规则配置存在时影响通行、观察或掩护 | 采用已配置几何，不根据贴图推断 | 通路与服务状态分别判断 | 规则占地及高度、状态映射、适用政策 |
| 丘陵与坡地 | 规则高程可参与视线；道路坡度成本待确认 | 二维飞行保留；观察几何另定 | 道路合法性和成本决定到达 | 高程来源、采样精度、插值与坡度政策 |
| 洼地与沟谷 | 几何可能改变观察关系；不默认增加防御或伤害 | 按观察政策计算 | 不因地表外观连续就判定道路连通 | 地形采样、遮挡算法、道路与导航层 |
| 河流与水域 | 默认按场景明确的地面通行政策判断，过河使用合法连接 | 可飞与地面通行分开检查 | 使用桥梁等已配置地面连接 | 水域范围、通行政策、合法跨越连接 |
| 桥梁 | 使用桥面道路边；桥面和桥下分层 | 采用独立飞行及观察政策 | 检查桥梁连接与服务目的地通路 | 桥面几何、高度、导航层、连接点、可用状态 |
| 仓库／机场／加油站 | 只执行模板明确允许的现场任务 | 合法停靠点才支持对应能源服务 | 有服务定义与接入位置的设施才支持交接 | 设施身份、能力、接近点、停靠点、库存归属 |

高地不会默认提供伤害或作用范围加成；森林不会默认同时具备隐蔽、减速和减伤；外观为加油站的模型也不会自动生成资源。这些效果必须逐项由规则和数据明确。

## 四、三兵种的具体判定职责

### 4.1 侦察无人机

1. 航线检查覆盖所有途经点及线段，不能只确认起终点合法。
2. 水域、道路、树林和建筑的地面通行限制，不直接转为空中禁行限制。
3. 观察范围与观察遮挡分别判断；启用林冠或规则高程影响前，必须固定传感器政策和几何算法。
4. 报告保存来源、对象、位置、状态和仿真步。失视后停止实时更新，保留带时间的历史记录。
5. 无人机提供的信息只能满足允许的信息前置条件，不能代替陆兵到场、保障交接或自动授予交战动作。
6. 恢复能源需要合法停靠与服务条件；航行中不能因经过补给设施上空直接恢复能源。

### 4.2 陆兵

1. 首版通过道路图计算合法路径，不因地表成本字段存在而开放自由越野。
2. 经过墙体、河流、桥面或不同导航层时，使用显式连接和阻挡数据。
3. 交战对象、当前信息、作用范围、资源、间隔、主动作占用和已采用方案均须满足。
4. 独立动作射线启用后，友军共享信息与自身动作路径分别检查。
5. 掩护启用后，在合法交战内计算确定性效果，不能绕过对象资格或制造随机命中。
6. 巡查、保护和现场确认仍须满足任务位置与能力条件；有观察报告不等于已经完成现场节点。

### 4.3 保障单位

1. 通过合法道路和接近点到达对象或服务设施。
2. 服务双方满足位置、停靠、库存与可用状态后，才能建立服务占用。
3. 服务占用一步，一次服务一个对象；同一步不能同时完成服务和出发。
4. 运输对象的唯一持有者在成功交接后变化，不能因单位靠近或图标重叠复制物资。
5. 库存不足时按既有规则返回具备补充功能的本方兵营，不自动从任意仓库或加油站取资源。
6. 补给恢复能源或补给余量，不自动恢复陆兵耐久。

## 五、建议保存的参数

### 5.1 地图参数

| 参数组 | 建议字段 | 校验与用途 |
| --- | --- | --- |
| 身份与坐标 | `map_id`、`coordinate_system_id`、`horizontal_unit`、`vertical_unit`、`axis_definition`、`playable_boundary` | 同局统一坐标、距离、轴向与边界 |
| 规则高程 | `elevation_source_id`、`storage_key`、`sha256`、`sample_spacing`、`vertical_datum`、`interpolation_policy_id` | 明确规则使用哪份高度数据；缺失值不得补零伪造平地 |
| 地表区域 | `region_id`、`terrain_type`、`polygon`、`navigation_layer_id` | 区域合法、稳定身份、边界和重叠政策明确 |
| 道路与桥梁 | `edge_id`、`from_node_id`、`to_node_id`、`polyline`、`width`、`surface_type`、`connectors`、`initial_availability` | 连接完整、长度可重算、桥面与水面不混层 |
| 规则阻挡体 | `obstacle_id`、`footprint`、`base_elevation`、`top_elevation` | 通行、观察及动作阻挡分别引用政策 |
| 植被区 | `vegetation_region_id`、`density_class`、`canopy_height` | 使用规则区域，避免按实时显示的树木数量改变结果 |
| 水域与空中区域 | `water_id`、`air_region_id`、`polygon`、`ground_passage_policy_id`、`flight_policy_id` | 地面与空中政策分别定义，检查完整路径 |
| 设施与部署 | `facility_id`、`deployment_zone_id`、`interaction_area`、`approach_connector_ids`、`service_anchor_ids` | 完整占地合法、任务可到达、服务有明确接入 |

当前米制地图与旧演示坐标之间有显示转换。正式参数必须绑定坐标和转换版本，不能把旧样例中的距离直接解释为米；本文件不指定新的正式坐标默认值。

### 5.2 兵种能力参数

| 属性组 | 建议字段 | 状态 |
| --- | --- | --- |
| 移动能力 | `movement_class`、`traversal_mode`、`base_distance_per_step` | 道路／二维航线范围沿用现有规则；基础数值 [待确认] |
| 观察能力 | `sensor_profile_id`、`observation_range`、`occlusion_policy_id` | 范围与遮挡要求已确认；距离、算法 [待确认] |
| 地形响应 | `terrain_response_profile_id` | 本文建议；按兵种匹配地形政策 |
| 抽象交战 | `target_eligibility_policy_id`、`effect_range`、`effect_strength`、`action_interval_steps` | 陆兵间确定性对抗已确认；数值与公式 [待确认] |
| 动作路径 | `line_of_fire_policy_id` | 本文建议；首版具体检查方式 [待确认] |
| 保障能力 | `allowed_service_types`、`service_location_policy_id`、`service_range_policy_id`、`inventory_capacity` | 服务职责与占用沿用规则；范围和容量 [待确认] |

### 5.3 地形与兵种交互政策

| 政策 | 最小参数 | 建议约束 |
| --- | --- | --- |
| 通行政策 | `allowed_movement_classes`、`requires_road` | 禁止与未知分开，不默认放行 |
| 移动成本 | `cost_factor`、`resource_factor` | 量纲、适用路段、取整明确；具体值 [待确认] |
| 观察阻挡 | `blocking_mode`、`applicable_sensor_profiles`、`sampling_policy_id` | 不直接使用 Unity 相机视锥或显示碰撞体 |
| 隐蔽政策 | `concealment_class`、`detection_adjustment_policy_id` | 显式启用，不能同时冒充掩护减伤 |
| 动作阻挡 | `blocking_mode`、`applicable_action_types` | 不同动作可有独立条件，不能将发现结果直接当执行许可 |
| 掩护政策 | `cover_class`、`applicable_target_profiles`、`incoming_effect_policy_id` | 使用确定性抽象效果，系数及方向性 [待确认] |
| 重叠与优先级 | `terrain_selection_policy_id`、`cover_selection_policy_id`、`overlay_priority` | 明确路面覆盖林区、桥面覆盖水面及多区域重叠的取值方式 |
| 精度与取整 | `geometry_tolerance`、`rounding_policy_id` | 几何边界、端点和跨段累计使用同一版本政策 |

参数采用“未启用、已启用且完整、必需参数缺失”三种不同状态。明确未启用时按规则声明的无附加效果处理；必需参数缺失时阻止对应政策启用，不能自动把未知倍率补成零或一。

## 六、计算与结算建议

### 6.1 移动成本

建议先判定路径合法，再将路径分为实际适用政策的路段。可采用以下抽象成本形式作为待确认方案：

```text
路径行动成本 = 各合法分段（分段长度 × 本兵种在该分段的成本系数）之和
```

如果该政策被采用，单位每步用自身行动预算消耗上述成本，未完成部分保存为路径进度。资源消耗另由资源政策计算，不直接等同于行动成本。分段完成后再按固定规则累计与取整，避免切分得越细反而消耗越大的异常。

该形式不指定任何正式移动速度或倍率，也不改变每步一个主要动作。地形成本对道路移动生效，不授权离开道路穿越地表。

### 6.2 发现与动作路径

发现至少检查：观察来源有效、对象处于观察范围、规则遮挡通过、信息共享条件满足。若启用隐蔽政策，再应用其确定的发现条件修正。

交战另检查：对象资格、当前有效信息、作用范围、执行者状态与资源、动作占用、方案授权，以及已启用的动作路径政策。历史位置和过期报告不能作为当前可见信息。

观察与动作射线可以引用不同政策。具体二维遮挡或规则高程采样、观察点高度、目标判定点、端点和容差均需确认，不在本文假定已经存在完整三维算法。

### 6.3 掩护与统一结果

掩护启用后，只对已经合法的交战产生明确的确定性修正。规则必须写清适用目标、适用动作、选择方法、边界和取整；多个掩护区域不能默认无界叠乘。

同一步先形成双方合法动作和结果，再按统一规则提交。不能因先处理红方或蓝方而给予额外行动，也不能把动画播放完毕当作结算时刻。

## 七、场景示例

以下是虚构规则情景，用于开发和验收；不构成《断箭》实测结果或本项目已实现功能。

| 情景 | 输入条件 | 应检查的结果 |
| --- | --- | --- |
| 道路与水域 | 地面路径起终点合法，中段直接穿过水域 | 没有允许连接时拒绝，不能只比较起终点 |
| 桥面定位 | 单位位于桥面道路边，与水域平面重叠 | 使用桥面导航层和连接关系，不将其判为落水或允许跳到桥下 |
| 建筑遮挡 | 目标在名义观察范围内，但规则墙体遮挡 | 不产生当前可见报告；最后发现保留原时间 |
| 共享观察与直射 | 无人机报告有效，但陆兵自身动作路径被墙体阻挡 | 在启用直射检查的场景中拒绝动作，报告仍可保持有效 |
| 森林中的不同兵种 | 陆兵沿林中道路移动，无人机航线经过上方 | 陆兵应用适用道路成本，无人机不继承地面减速；观察另算 |
| 设施外观与服务 | 保障单位经过装饰性加油站，但无服务定义 | 不增加库存；任务和界面提示不得宣称补给完成 |
| 存档与地形事件 | 某已启用地图覆盖状态生效期间保存，之后恢复 | 恢复相同对象、开始／结束步和状态，不重复触发事件 |

## 八、数据库、存档与角色信息

### 8.1 数据归属

沿用当前二十张应用逻辑表，建议按以下位置保存：

| 数据 | 建议位置 | 保存边界 |
| --- | --- | --- |
| 静态地形、道路、水域、阻挡与设施 | `scenario_versions.definition.map` | 随场景版本发布，不随对局改写 |
| 通行、观察、掩护及叠加政策 | `rule_versions.definition.map_policies` | 随规则版本冻结 |
| 兵种能力和地形响应配置 | `rule_versions.definition.unit_profiles` | 模板与运行实例分开 |
| Unity 模型与规则几何的资源关联 | `scenario_versions.asset_manifest` | 存受控键、版本与摘要，保持显示和规则可追溯 |
| 当前地图变化 | `game_snapshots.state_payload.conditions.map_overrides` | 只记录已启用规则产生的覆盖状态 |
| 单位与路径进度 | 快照 `units/routes` | 保存当前合法位置、道路／航段和导航层 |
| 本方发现和最后发现记录 | 快照 `observations` | 红蓝分别保存，原始完整快照仅供后端使用 |
| 已发生影响与原因 | `game_events.payload` 及命令回执 | 记录引用与前后状态，不建立第二套可写结果 |

以上 JSON 路径仍需按快照契约锁定。静态几何包较大时，数据库记录受控存储键、版本和摘要，不把整张静态地图重复写入每份快照，也不按每棵树或三角形拆成数据库行。

### 8.2 动态覆盖与保存恢复

地图运行变化建议包含 `override_id`、`target_object_id`、`policy_id`、`start_step`、`end_step`、`source_event_id` 和有效状态。

只允许既定规则和已启用事件产生变化。桥梁关闭、建筑破坏等机制若未启用，不能因字段存在就允许触发。恢复时同时恢复单位位置、路线、观察、设施状态和有效步区间，继续使用原场景与规则版本。

### 8.3 信息隔离

后端可以持有完整状态，但路线建议、地图、列表、AI 输入和回执只能使用本方允许的信息。隐藏动态条件应按规则显示待核验，不通过路线错误原因泄露未知单位的位置或数量。

公开静态地图与动态发现状态分别管理；哪些地形信息开局公开按场景定义。相机转到某处、模型处于屏幕内、切换显示图层，都不直接产生发现结果。

## 九、界面解释与回执

建议在单位、路线和动作结果中显示可解释的地形影响：

| 界面位置 | 建议说明 |
| --- | --- |
| 路线预览 | 使用的道路／航段、可通行结论、预计成本、资源是否满足、待核验条件 |
| 单位详情 | 当前导航层、适用地表政策及已启用效果；不显示未知敌军信息 |
| 观察记录 | 来源、观察步、当前／历史／未知、已知遮挡原因 |
| 交战回执 | 当前信息、作用范围、动作路径、资源与掩护检查的允许摘要 |
| 保障回执 | 合法接入位置、停靠状态、库存、服务占用及成功交接事实 |
| 复盘 | 当时场景与规则版本、实际路线、有效报告、地图变化及合法结果 |

内部记录可保留 `map_object_ids`、`map_policy_version`、`reason_code` 和几何／状态引用。输出前按角色投影，不能直接公开完整调试记录。

## 十、待确认参数与实施优先级

### 10.1 待确认事项

| 编号 | 待确认项 | 本文建议的处理 |
| --- | --- | --- |
| T-01 | 正式坐标、单位与旧演示映射 | 固定一套业务坐标与版本化显示转换 |
| T-02 | 规则高程精度、采样与边界容差 | 用可重复场景验证后确定，不直接沿用显示网格精度 |
| T-03 | 各兵种移动预算及地形／道路成本 | 先保留道路移动范围，参数按模板配置 |
| T-04 | 观察范围、遮挡算法和传感器差异 | 先完成范围与显式阻挡，再评估规则高程 |
| T-05 | 独立动作路径是否纳入首版 | 建议评审直接作用类动作的独立路径检查 |
| T-06 | 隐蔽与掩护的启用范围及系数 | 分开设计，保持确定性，暂不填写正式数值 |
| T-07 | 多区域重叠、桥面优先级和取整 | 在场景发布前固定政策并覆盖边界用例 |
| T-08 | 合法服务接入、距离和容量 | 按现有停靠、库存和一步服务规则补全 |
| T-09 | 天气五步延迟的作用对象和阶段 | 继续在既有事件规则内锁定，不追加隐式效果 |
| T-10 | 驻楼、越野、动态破坏等扩展 | 独立立项，不通过地图字段默认启用 |

### 10.2 实施顺序

1. **通行与到达**：坐标、道路、桥梁、水域、可飞区、部署区及服务接近点。
2. **观察与动作条件**：显式遮挡、本方报告、失视、路径过程检查及经确认的独立动作路径。
3. **差异化地形效果**：经确认的移动成本、隐蔽和掩护政策，提供明确回执。
4. **扩展机制**：驻楼、越野、动态破坏、烟幕和飞行高度层，另行补充规则与存档变体。

## 十一、验收情景

下列用例均为待执行设计要求，不表示已通过测试。

| 编号 | 情景 | 独立预期 |
| --- | --- | --- |
| TERRAIN-01 | 地面路径中段穿越不允许通行的水域 | 拒绝路径，原位置及资源不被伪成功更新 |
| TERRAIN-02 | 道路在画面上相交，但没有合法连接节点 | 不允许直接转入另一条道路 |
| TERRAIN-03 | 无人机起终点合法，中间线段穿过禁飞区 | 整条航线检查拒绝 |
| TERRAIN-04 | 单位处于桥面并与水域平面重叠 | 导航层与连接正确，不跳层或错误落水 |
| TERRAIN-05 | 目标在观察范围内但被规则墙体遮挡 | 不产生当前可见报告 |
| TERRAIN-06 | 失视后目标移动 | 本方最后发现保留旧时间和位置，不收到实时更新 |
| TERRAIN-07 | 共享观察有效，自身直射路径受阻 | 在已启用对应政策时拒绝动作，不取消真实有效的共享报告 |
| TERRAIN-08 | 同一地形影响不同兵种 | 只使用适用政策，地面减速不作用于飞行 |
| TERRAIN-09 | 掩护未启用与启用后的相同合法交战 | 前者无隐藏加成，后者按冻结规则确定性结算 |
| TERRAIN-10 | 保障隔墙接近对象或经过无服务定义的设施 | 不伪造服务、库存恢复或对象交接 |
| TERRAIN-11 | 更改相机、纹理、树模数量、战损外观或 LOD | 权威移动、观察和交战结果不变 |
| TERRAIN-12 | 高程缺失、政策缺失或区域叠加未定义 | 阻止相关规则启用或场景发布，不静默放行 |
| TERRAIN-13 | 地图覆盖状态生效时存档、读档及分叉 | 恢复版本、位置和有效步区间，不重复触发事实 |
| TERRAIN-14 | 地形检查与双方交战发生于同一步 | 统一结算，无处理顺序优势，无额外主动作 |
