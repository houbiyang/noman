# B-G01 试走受阻与重复提交修复

- 对局处于 `preparing`，正式时钟仍为第 0 步，不需要开局就能部署试走。
- B-G01 路线状态为 `waiting`，单位提示“前方受阻，等待通行”。首次读取试走步已达 369，路线前一段已经重复等待 368 次。

## 根因与修复

1. **整步碰撞否决**：之前会对整分钟位移做碰撞检测，只要远处有单位挡在路径上，整段位移被取消。改为沿移动方向计算最早的扫掠圆接触点，先走到安全间距之前，再设为 `waiting`。按实际已走距离结算能源与轨迹；不会穿过阻挡单位，也不会自动挪动对方。
2. **自动无限重试**：页面之前把 `waiting` 也当成自动推进条件。现在单车受阻后暂停自动试走；纵队领车受阻时也暂停，避免仍排队的跟车维持重试。提示可改选路线或等待让行后手动继续。
3. **保留显式恢复**：“继续试走”允许重试一次。如果仍然受阻，立即重新暂停；前方已让行则正常继续。

## 使用边界

- 不自动绕过其他单位，不取消碰撞规则。要完全到达被占道路后方的目标，需要调整路线，或让前方单位先让行。
- 修改不会追补已保存的旧试走步，也不会直接改写当前单位位置。
- WebGL 需要重建并刷新后生效；旧标签页保存的是旧脚本时仍会重复提交，刷新可清除旧的自动试走状态。
