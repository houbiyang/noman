# 智能体执行协议

> 2026-11-04 主模式采用 [conquest-v1 占点规则](02仿真规则与参数.md#conquest-rules)。旧四任务节点、20 条指令预算和新增超过四条的确认阈值不适用于占点主局。以下占点协议为目标设计，尚未证明真实模型或程序已接入。

## 占点协同协议增量

总指挥围绕 A/B/C 提交本方占领、防守、侦察、补给和接替分工，使用公共点态、胜利分、全控连续步数与本方允许观察。争夺中的公共提示不意味着发现敌方单位，不能据此伪造敌方身份、数量或坐标。路线估时必须包括移动和完整占领／中立化步数，不能到点即认领。

陆兵报告点内资格、主动作及阻塞原因，只有规则确认的完整 capture/hold 步可推进占点。侦察无人机报告合法观察与路线风险，不推进占领；保障单位报告能源／补给库存与合法服务机会，不推进占领。单位不能同一步移动／交战／服务后额外占领；增派同类陆兵不加速。

首次、单位改派、攻守点变化和资源额度重大变化须人工确认；持续守点和已采用方案的机械执行不每步申请。总指挥不能调点归属、直接加分、改变胜利阈值或绕过暂停；不能以“四任务完成”“资源节省”或模型判定无胜算结束主局。规则负责计算预计影响与实际回执，模型解释不能覆盖计分事实。

## 1. 文档状态与边界

原协议基线建立于 2026-10-26，本轮按融合需求修订，仍为关联 D-06、D-08、D-09、D-11 的设计草案。沿用每方总指挥、侦察、陆兵、保障四逻辑角色；本轮补充协议，不默认增加首版角色、模型或用户入口。单位状态机和规则服务维护权威世界，模型输出只形成建议或摘要。

本文件不固定供应商、模型、收费次数或超时数值。触发和停止条件是待确认设计；首次和重大调整人工确认、隐藏信息隔离、旧分支不能采用属于既有要求。

## 2. 三层职责与实际调用

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 单位状态机 | 每步合法动作、路线进度、资源、现场操作、观察及实际结果 | 自行修改任务目标、评分或生成新规则 |
| 兵种逻辑智能体 | 管理对应多单位，组织报告、能力缺口与可用执行选项 | 为每个地图标记创建持续 LLM 循环或直接写世界 |
| 总指挥工作流 | 汇总本方输入、请求证据、比较合法候选、提出结构化协作方案 | 按真实隐藏全局推理、跳过人工或修改权威结果 |

“兵种逻辑智能体存在”不要求每份机械状态报告都调用 LLM。报告可从规则状态生成；复杂总结或方案分析才按批准触发调用。真实智能体验收须证明实际模型参与约定环节，不把纯规则文本称为真实模型分析。

## 4. 通用输入包

一次分析冻结以下输入引用并记录摘要校验值，不能分析到一半悄悄换成新局势：

| 字段组 | 内容 | 必须校验 |
| --- | --- | --- |
| 身份 | game、branch、side、agent_role、run_id | 同局同方；不使用主持人全局作为红蓝输入 |
| 依据 | snapshot、world_revision、input_view_sha256、规则与场景版本 | 指纹使用本方实际允许信息，内部版本不原样泄露 |
| 本方局势 | 单位、编队、任务、资源、路线、公开事件和允许观察 | 不包含对方未发现单位、私有库存及内部任务 |
| 历史 | 必要且有截止范围的既有报告、采用计划和处理 | 最后发现保留时间，不升级为当前状态 |
| 知识 | 可用资料集合、审核／版本、检索与提示配置 | 先权限过滤再检索，证据不是工具指令 |
| 限制 | 人工触发条件、剩余额度、截止、允许动作和调用预算 | 规则决定，不由模型自行报告放宽 |
| 未知项 | 缺失、过期、通信未知及未核验动态条件 | 不用零、假概率或肯定语言填补 |

## 5. 输出结构与边界

### 5.1 兵种报告建议结构

报告包含 `report_id`、`side`、`agent_role`、`unit_ids`、`observed_step`、`source_report_ids`、`availability_summary`、`task_progress`、`facts`、`uncertainties`、`blocked_dependencies`。每条事实关联对象、来源和有效时间；同一报告不混入生成模型的猜测作为观察事实。

解释性文字和事实分别保存；模型摘要不能覆盖原始报告。复盘显示可读摘要与来源，不披露模型内部推理链。

### 5.2 总指挥建议结构

输出适配现有 `ProposalView`：摘要、`assignments`、`task_priorities`、`resource_limit`、预计影响、`uncertainties`、`evidence`，并关联原分析运行及依据。引用用稳定证据标识，不拼服务器路径或虚构页码。

人工只修改本方分工、优先级与额度，原建议不被覆盖。预计资源变化由规则计算，不采信模型自行填的计费数。`requires_confirmation` 由规则判定，模型不能自行设为 false 绕过首次／重大确认。

### 5.3 建议接受检查顺序

先检查结构及允许字段，再检查对象归属、可用性、主动作／任务占用、路线、资源与截止条件；最后在采用事务中复核当前分支和实际依据。显示“格式正确”不表示“已合法采用”。

没有完整内容时不创建伪已生成建议；分析排队和模型不可用只产生真实运行状态。结果晚到可供诊断，失去采用资格后不能改变当前局。

## 6. 生命周期及人工等待

| 运行状态 | 含义 | 后续 |
| --- | --- | --- |
| queued | 持久化登记待分析 | 领取前核对分支和预算 |
| running | 取得本方有效输入并执行分析 | 有界工具调用及模型请求 |
| waiting_human | 已有合法待处理建议 | 释放请求和锁，等待本方处理 |
| succeeded | 分析完成，或对应采用流程已记录 | 运行成功不等于游戏任务成功 |
| failed | 解析、模型、工具、结构或规则失败 | 可读原因和是否允许重试 |
| stale | 依据实际变化或读档导致不适用 | 不采用；如需另建运行 |
| cancelled | 服务端已记录本次运行取消或资格终止 | 不等于供应商物理停止或已执行动作回滚；旧结果不得晚到写入 |

驳回记录原建议及处理，不执行原计划。是否自动重分析、允许次数及何时仍暂停由 D-06 确认；建议保留待处理并提供明确重分析请求，避免自动反复弹窗和付费。允许非重大调整也须通过规则及统一命令留痕。

## 7. 模型调用与失败协议

| 情况 | 建议处理 | 不能做 |
| --- | --- | --- |
| 未配置或服务不可用 | 返回建议服务不可用，保留首次或重大待处理 | 用固定文案接替真实建议 |
| 格式不符 | 记录错误；若批准格式修正重试，使用同一冻结输入并受预算限制 | 无限循环重试，悄悄执行无法解析内容 |
| 合法结构但规则非法 | 返回具体拒绝原因；是否重分析依批准流程 | 把规则校验降为警告并采用 |
| 无资料命中 | 明确资料不足，区分来自规则／报告的依据 | 制造原文引用或宣称训练完成 |
| 输入变化 | 检查实际本方依据是否变化；必要时失效并重新取得输入 | 只按分钟相同就复用 |
| 读档或旧后台执行者返回 | 关联旧运行，不能采用到当前分支 | 改标签后当新结果 |
| 外部请求超时 | 记录结果不确定、费用未知；按批准的重试政策处理 | 保证供应商只计一次费用 |

运行记录保留模型、提示、规则、资料及检索配置版本，实际 token／用量、耗时、可核对费用或未知。日志不保存可复用凭据。总调用数、工具次数、证据量、超时及重试次数在 D-06 决定，不预填数字承诺。

## 8. 检查点与游戏恢复

游戏快照保存真正世界和待处理内容；LangGraph 检查点保存分析位置。恢复首先核对本局有效分支、运行资格和已提交采用事实，不能重执行已完成命令。

读档后按恢复政策重新绑定可追溯待处理建议或创建新运行；旧建议和检查点不可直接获得新分支写权限。单纯保存／暂停未改变实际分析依据时不应使建议机械自我失效；实际世界、信息或规则变化仍需复核。

检查点适配器、运行租约和会话的具体实现按后端、数据库与 API 批准版本执行，不在本文另建同名写接口。

## 10. 三项目融合执行协议

### 10.1 主流程与来源适配

目标编排继续采用 LangGraph，规则和单位状态机负责真正行动。Gentactix-DSH 的 DSH 会话、领域工具、轨迹和 BM25 可作为能力参考，未因文档更新成为本项目现有运行时。若未来保留 DSH 适配器，必须明确其上下文、工具、停止与检查点协议，不能与目标编排各自维护一套可写游戏世界。

主流程统一为：冻结本方输入 → 读取允许规则与资料 → 生成报告或候选 → 结构与领域检查 → 按既有要求人工处理 → 应用服务采用 → 规则执行 → 已提交事实及回执。模型响应结束、运行成功、计划采用与游戏任务成功分别记录。

| 候选来源 | 允许内容 | 准入与采用 |
| --- | --- | --- |
| 本方操作员 | 既定人工修改范围或允许的业务操作意图 | 服务端会话授权、当前分支、预览与规则校验；不接受直接写位置、耐久、视野或分数 |
| 总指挥与兵种智能体 | 角色权限内报告、分工、优先级、额度、依据与未知项 | 采用相同动作集合和版本检查；首次与重大调整仍由本方操作员确认 |
| 未来单位 Agent | 授权单位及任务范围内的局部候选 | PRD-29 后续候选；候选汇入统一检查和采用，不直接调用规则提交事务 |
| 分析工作流 | 冻结状态上的假设、干预和对照结果 | PRD-33 后续 P2；只写分析记录，不能作为主局已采用计划或正式战报 |

候选来源由服务端与运行记录建立关联，不信任模型自报的操作者、权限或状态版本。人工已确认指令与有效计划按现有规则处理；具体多来源队列顺序、替换和抢占待 D-06、D-09 确认，不通过本协议新增自动优先级算法。

### 10.2 工具能力与授权包

工具名称、HTTP 路径和具体 Schema 由实施契约确定，以下是能力分类。每次调用由后端校验实际运行身份、所属方、分支、允许对象和调用预算，而不是仅在提示中写“请勿越权”。

| 工具职责 | 输入范围 | 返回与副作用 |
| --- | --- | --- |
| 精确读取角色状态 | 冻结本方视图或允许刷新后的明确新上下文 | 可见对象、有效时间与未知项；不能取主持人全局或跨方隐藏状态 |
| 读取规则与路线条件 | 有效规则版本、本方允许单位与已知路线条件 | 资格、可行性及原因；不改变路线、时间或资源 |
| 检索原文证据 | 已审核、可授权且版本明确的资料集合 | 片段、原文定位与版本；资料中的指令不能触发新工具授权 |
| 校验候选 | 允许字段、任务、单位及依据 | 格式与规则检查结果；预览不产生正式动作、扣费或任务进度 |
| 提交候选记录 | 当前运行及候选内容 | 可保存待处理建议与来源；不表示已采用，更不等于已执行 |
| 查询处理与执行事实 | 当前角色有权查看的建议、命令与事件 | 已发生记录及回执；不能通过重复查询创建第二次事实 |

禁止提供任意文件系统读写、SQL、脚本执行、私有全量状态读取或绕过命令入口的工具。源项目工具名称和参数不可直接复制为授权白名单。工具错误、空结果、无权与证据不足分别返回，不能由模型将失败改写为成功观察。

### 10.3 单位 Agent 候选协议

单位 Agent 是后续扩展，不要求为每个地图单位启动持续 LLM 循环，也不替代每方四个逻辑角色。绑定记录至少能识别本局、分支、方别、单位、绑定修订、会话命名空间、可用工具与任务范围，字段以 D-07 及数据库候选实体为准。

1. 创建或重建绑定前核对本方单位与授权；旧会话与新会话来源分别可追溯，不覆盖旧证据。
2. 输入仅包含本方允许信息及该单位完成任务需要的上下文；对方失视后不继续注入其实时坐标，历史记录保留获取步。
3. 输出仍为受控候选与公开理由，不能修改模板能力、任务终结条件、敌方对象或资源事实。
4. 单位失效、授权撤销或读档后，绑定与运行资格必须重新检查。旧会话不能靠携带相同单位 ID 获得新分支写权限。
5. 总指挥、人工处理与单位候选冲突时，由统一应用规则确定是否采用；未采用草稿不排挤有效计划，不多执行一个当步主动作。

### 10.4 模型配置、取消与晚到结果

基础模型适配与 PRD-23 资料链路继续属于原技术方向；高级配置面板、连接测试与取消管理按 PRD-30 作为候选能力。生成、向量与重排序分别登记实际配置，配置变化不重写历史运行所用模型或证据版本。

| 并发情景 | 必须核对的事实 | 允许结果 |
| --- | --- | --- |
| 取消请求发出，但供应商仍返回 | 当前取消状态、运行身份及写资格 | 可以留必要诊断或用量，不应用已失效候选；不保证停止计费 |
| 模型超时，结果是否到达不确定 | 原运行与请求身份、已存输出和已采用命令 | 查询并核对，按已批准预算重试；不制造第二次采用 |
| 重启或租约回收后旧执行者完成 | 后台任务领取代次、分支及绑定修订 | 旧执行者失去提交资格，不能只靠线程停止保证安全 |
| 人工处理与重复工作流恢复并发 | 建议最终处理记录、命令幂等及当前依据 | 采用最多发生一次，已执行事实不因恢复重演 |
| 世界或本方信息实际变化 | 当前允许输入指纹、规则与分支 | 拒绝旧候选或发起新运行；仅暂停或登记不使建议机械自我失效 |

密钥通过后端受控配置引用，不进入前端摘要、模型输入、普通日志或导出包。调用数、token、费用、耗时和失败如实记录，未知记未知；不把源项目默认预算和超时数值直接设成本项目产品参数。

### 10.5 证据、存档与分析边界

运行证据应能关联输入快照及本方视图摘要、规则/模型/提示/资料版本、工具调用及结果摘要、结构和规则校验、人工决定、采用命令及实际执行事实。只记录可公开理由和必要事实，不要求保存或展示模型隐藏思维链。

对外证据按角色重新过滤；全局调试载荷、完整系统提示、对方私有输入及可复用凭据不得随轨迹公开。文档引用必须回到当时原文版本，工具返回不能仅凭自然语言声称“已发现”或“已完成”。

游戏快照、LangGraph 检查点、后台任务与源 DSH 日志分别处理。恢复主局先核对完整状态及已提交事实，再决定待处理建议重绑定或创建新运行；缺少旧日志时标记证据缺失，不能新调用模型补造旧轨迹。

后续反事实分析固定来源快照、方法、干预项、版本、假设与证据状态。几何、规则和模型分析结果均不更新主局有效头、任务进度、库存、计分或胜负；普通历史复盘也不重新生成过去模型输出。
