# 多智能体本机交付与验收

日期：2026-11-10。目标环境：当前 Windows 电脑。本次交付范围为既有数字沙盘中的 LangGraph 四角色编排、模型接入、运行恢复与操作工作台。

## 1. 交付判定

软件运行检查、模型配置检查、真实模型推理验收分别记录。仅有测试替身通过或页面能够打开，不判定为真实模型验收通过。

本次交付入口为项目根目录 `start-agents.ps1`；工作台为 `http://127.0.0.1:18766/agents`。默认复用本机现有数据库、已有网页构建和端口，不安装依赖、不重置数据库、不替换地图、不自动终止已有服务。

| 检查 | 标准 |
| --- | --- |
| 软件运行条件 | 依赖版本、必需文件、数据库业务表、九次迁移、pgvector 均通过 |
| 已启动服务 | HTTP 健康检查成功，`agent_orchestration.runtime_revision` 为 `coordination-20261110.1`，工作台占位符已替换 |
| 模型配置条件 | 红蓝均启用，接口和模型名明确，后端启动环境包含各自配置引用的密钥变量 |
| 真实模型验收 | 两方四角色均产生真实模型结果，工具续轮、用量、结构化方案与人工处理均有实际运行记录 |

真实模型验收需要用户账户中可用的官方 API 密钥、余额与具体模型权限；这些条件尚未具备时，交付状态保留为“软件可运行，真实模型待验收”。完整产品 SOW 中的正式交战、精确导航、事件效果、真实资料检索及目标设备验收不因本模块交付而自动完成。

## 2. 本机操作

在项目根目录的 PowerShell 中运行：

```powershell
# 只读检查，不启动服务、不调用模型
& .\start-agents.ps1 -CheckOnly

# 启动或复用现有服务，并打开工作台
& .\start-agents.ps1

# 仅启动或核对，不自动打开浏览器
& .\start-agents.ps1 -NoBrowser

# 检查实际服务是否加载了当前代码
python -X utf8 -m backend.delivery_check --services --json
```

检查失败时查看 `checks` 中失败项。`dependencies` 表示当前解释器与版本清单不同；`files` 表示本机文件或私有配置缺失；`database` 表示现有数据库结构、连接或迁移不完整；`services` 表示服务不可达、工作台生成失败或后端仍加载旧代码。失败仅返回异常类型，避免泄漏连接或供应商响应原文。

软件已经运行时不要重复启动后端。需要加载更新或新的密钥环境变量时，先确认当前无执行中的智能体任务和播放中的对局，再结束本项目后端进程；保留 PostgreSQL 与网页服务。从准备好密钥的同一终端重新运行 `start-agents.ps1`，已有网页启动器会启动缺失的后端。

如无法确认端口占用进程归属，应停止重启操作并核对现有进程。入口不会替用户终止任意占用端口的进程。

## 3. Kimi 与 DeepSeek 官方配置

在本机 PowerShell 运行隐藏输入脚本，实际密钥不会写进聊天、脚本、命令参数或交付包：

```powershell
& .\set-agent-keys.ps1 -Provider Both
```

脚本只设置当前 PowerShell 进程的 `MOONSHOT_API_KEY`、`DEEPSEEK_API_KEY`，新启动的后端子进程可以继承。关闭该终端后不会持久保留这些变量；已有后端进程也不会自动取得后来设置的变量。因此须从同一终端启动后端，或由接收方使用其现有凭据管理方式提供同名变量。

在工作台连接本方席位，使用“官方服务快速填写”，核对模型权限、预算、超时，然后启用并保存。红蓝均可独立选择任一家服务，不预设两方必须使用不同供应商。

| 配置 | Kimi 官方示例 | DeepSeek 官方示例 |
| --- | --- | --- |
| 接口根地址 | `https://api.moonshot.cn/v1` | `https://api.deepseek.com` |
| 模型标识 | `kimi-k3.1-pro` | `deepseek-flash` |
| 密钥变量名 | `MOONSHOT_API_KEY` | `DEEPSEEK_API_KEY` |
| 采样温度 | 留空，省略该请求字段 | 留空，使用服务默认 |
| 输出上限参数 | `max_completion_tokens` | `max_tokens` |
| 推理强度 | `low` | `low` |

以上为 2026-11-10 核对官方文档的接口示例，不表示当前账户已经开通这些模型。可按账户实际可用模型修改；不使用已退役模型名称作为验收依据。思考输出也会占用输出预算，预算偏小时可能返回明确的 `MODEL_OUTPUT_TRUNCATED`，应调整配置后新建规划，不反复恢复同一冻结配置。

既有自定义兼容接口继续默认发送 `max_tokens`、采样温度 `0.2`，推理强度留空时不发送该字段。工具续轮保留供应商返回的 `reasoning_content`，仅在本次请求上下文中回传，不写入公开报告或工具跟踪结果。

参考：[Kimi 官方快速开始](https://platform.kimi.com/docs/get-api-key)、[Kimi K3.1 Pro 参数限制](https://platform.kimi.com/docs/guide/kimi-k3-1-pro-quickstart)、[DeepSeek 官方模型说明](https://api-docs.deepseek.com/quick_start/pricing/)、[DeepSeek 思考模式与工具续轮](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 4. 真实模型验收步骤

使用专用验收对局，避免在用户原有对局直接启用新规则。按既有工作台操作流程完成部署和协同测试启用后，分别验证：

1. 红蓝配置能够独立保存，另一方和主持人不能读取本方配置与私有运行。
2. 一次四角色规划完成，三类角色并行、汇总等待全部报告；记录运行标识、模型标识、实际用量与工具结果。配置成功或端口可达不算此项通过。
3. 未批准前不改变单位任务；批准、驳回与重复请求符合既有幂等命令规则。
4. 根据实际供应商行为检查工具续轮与结构化输出，确认没有固定测试文案冒充真实结果。
5. 取消后不发布晚到结果；失败时有明确原因，人工恢复复用已保存结果。未确认落库的请求仍可能重新调用供应商，不能保证计费请求恰好一次。
6. 分支或本方依据变化后旧结果不能采用；保留模型来源、运行标识和实际验收记录。

真实模型测试产生供应商正常费用。未取得实际密钥和模型权限前，不执行这些付费步骤，不将协议替身测试记作真实模型验收。
