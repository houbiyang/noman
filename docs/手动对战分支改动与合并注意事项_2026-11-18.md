## 合并前优先核对

1. **先更新引用，再判断冲突。** 在独立集成分支或干净检出执行 `git fetch upstream main codex/ditu`，以 `git merge-base upstream/main upstream/codex/ditu` 找共同基线。当前工作区与本机缓存的 `upstream/main`（`7be85a5`）涉及若干相同文件，这表示需要逐项对照，不等于已发生 Git 冲突。
2. **先对协议，再合页面。** 重点对照 `backend/database.py`、`backend/main.py`、`backend/service.py` 与 Unity 的 `SandboxServerContracts.cs`、`SandboxServerClient.cs`。对照 `SandboxHudController.cs`、`SandboxArmyPanel.cs`、`SandboxWorld.cs` 时，同时走查目标分支已有入口；不要整文件选择一侧而丢掉另一侧的功能。
3. **数据库先在副本上升级。** 对照迁移编号、内容摘要、命令约束及回滚脚本；分别测试空库和带历史命令的旧库。已用过的迁移不要覆盖或重编号。校验旧快照和回放仍可读、失败事务不留半条记录、同一结算请求重试不多推进一轮。
4. **不要整体覆盖地图或构建产物。** 逐项核对场景、地图摘要、部署与地表数据及其引用。保留目标分支原地图，缺少桥头连接仍按未验证处理。Unity 源码和资源配对后重新构建，避免页面使用缓存的旧 WebGL 包。
5. **检查交付完整性与隐私。** 验收本次交付时，应在干净检出核对未跟踪模块、测试、资源和 `.meta`；运行所需测试包应有可复现的生成说明。不要提交 `.local/`、数据库连接配置、席位令牌、真实存档或 Unity 缓存。不要在开发机当前对局上试迁移或回滚。
