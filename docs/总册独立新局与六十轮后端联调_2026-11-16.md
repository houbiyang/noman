# 总册独立新局与六十轮后端联调

日期：2026-11-16。分支：`codex/ditu`。

## 1. 本次范围与规则依据

继续总册手动演示的后端链路，不合并main、不改地图、不迁移旧战局、不提交推送。
规则来源：`docs/rules/青岚_游戏规则总册_分类目录完整版_v1.1.md`。

- 6.1：用户分别填写双方三兵种数量，单类可为0、双方可不对称、每方总量至少1；仅无人机阵营明确警告缺乏占点能力，不自动判负。
- 6.2：满耐久、自用能源和适用弹药，保障车满货物；无人机停靠、地面单位停止、任务为空、首发就绪；五点中立、进度0、资源分30。
- 6.3、6.4及24.3：显式逐单位预部署位置与地表、六座兵营及服务锚点；冻结名册、规则/场景/容量摘要、五点、库存和计分分母、控制配置。
- 11.3：赛中敌方能源、弹药、货物及规划不公开；双方占点分公开，本方击毁/资源/总分预估只对本方公开，终局公开完整结算。
- 使用此前已确认的本地测试配置：**每轮60仿真秒、最多60轮、3600秒时限**。内部子步不是独立数据库提交，不新增5秒操作入口。
- 软件容量沿用已存在的版本清单：每方每类0～10、每方1～30、全场最多60；这是本地软件上限，不是总册规定的固定兵力，不是性能认证，超限拒绝而非截断。

## 2. 已实现的接口

均沿用当前服务鉴权和错误信封，不返回bootstrap密钥或席位令牌。

| 接口 | 权限 | 行为 |
| --- | --- | --- |
| `GET /api/v1/battle/setup` | bootstrap | 只读读取规则、场景、容量版本及SHA-256、地图、五点和验收目录；不登记或发布版本 |
| `POST /api/v1/battle/games` | bootstrap及`Idempotency-Key` | 创建独立总册手动新局；新建201，同键同参重放200，同键异参409 |
| `GET /api/v1/game-creations/{creation_key}` | bootstrap | 复用现有恢复接口；创建响应丢失时查询，不重复创建 |
| `GET /api/v1/games/{game_id}/result` | 本局席位 | 识别总册手动局，不走旧演示结果分支；区分进行中/已结算，遵守席位可见性 |

### 新局请求约束

必填`title`、`mode=manual`、三个版本UUID与三个SHA-256，以及`blue`/`red`配置。每方包括：

- `quantities`：`recon`、`ground`、`support`严格整数。
- `units`：完整名册；每项`unit_type`、`ordinal`（1起连续）、毫米坐标`position`及`surface_id`。
- `camps`：三种兵种各一营；每项位置、地表、`service_anchor`和`service_surface_id`。

无默认兵力/默认坐标，不接受客户端耐久、能源、弹药、公共库存或验收标记，不把本地手动配置冒充agent配置。初始资源由总册内核赋值。

`setup.can_create=false`是**保守的来源目录标记**，不是完整实时开战检查；创建端会再次核对数据库发布状态、命令约束与执行器。不能将读取配置成功当成获准开战。

## 3. 事务、幂等及失败行为

- 创建键使用与旧创建接口相同的PostgreSQL事务级advisory lock；现有唯一键继续生效。新旧模式使用不同请求协议摘要，同一个键不能跨模式绕过验证。
- 规则、容量和场景登记使用`FOR SHARE`核对定义、摘要、相互绑定及`active`状态，不允许客户端指定过期或未发布来源。
- 创建前只读检查012/013命令CHECK，不自动运行迁移。
- 必须注入总册`Executor`，并调用新局专用`Geometry.validate_deployment`；缺实现、非严格True或其他验收失败一律拒绝。传给回调的是深拷贝，不能通过修改回调入参改变新局。
- `games`、分支、三席位、根快照与自动存档一次事务提交；最后快照失败也整体回滚。
- 不生成固定AI建议、AI运行或席位会话。正式席位仍需走原受控签发流程。
- 响应超时先按创建键查询恢复；同键异参409，状态冲突需重新读取后用新的操作键，不盲目重试异参。

本阶段复用现有表，**没有新增数据库迁移，没有向用户库创建测试局或写入测试数据**。

## 4. 席位信息隔离修复

同时修复了既有手动投影视图中的隐藏信息问题：

- 总册执行器不再把敌方能源/弹药写入观察联系人；视图对联系人再做白名单投影，兼容旧快照也不能带出库存、货物或规划。
- 赛中红蓝席位的对手`*_score`和`*_breakdown`为null；新增双方`*_control_score`仅表示公开占点分。主持人可审计全局，终局三席位均能读取完整结算。
- 非本方占领阶段不返回真实推进阵营/进度；用固定的`progress_hidden`表达信息权限，标记本身不用于暗示敌方正在圈内。归属和争夺状态仍公开。
- 档案继承所属席位的脱敏摘要，包含公开占点分，不含双方私有草稿或执行账本。
- Unity轮次栏与结果页将未知分数显示为“—”并说明终局公开，不伪造为0；据点标签明确对方进度不公开。

已有历史档案为冻结快照；本次不重写用户库中的旧档案，也不保证已泄露信息能够撤回。旧WebGL构建不会自动获得本次C#源代码修改。
