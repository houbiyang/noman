## 3. 统一术语与已确认边界

| 术语 | 唯一含义 |
| --- | --- |
| 逻辑智能体 | 每方总指挥、侦察、陆兵、保障四角色；共八个，不等于八模型或八单位 |
| 虚拟单位 | 兵营配置的具体实例；每方初始三类各一个，准备阶段免费追加且暂无产品数量上限 |
| 道路／路线 | 道路是地图连接；路线是单位选用的道路段或空中航段计划 |
| 仿真步／现实时间 | 一步一分钟、最多六十；保存时间、模型耗时独立，不按停机时长补步 |
| 胜利分／资源 | 占点胜利分决定主局结果；能源、补给、库存约束行动，损失仅作复盘。旧二十条计费指令预算不适用于占点局 |
| 当前／历史／未知 | 当前有效观察、最后发现记录、通信未知分别表达，未知不填零 |
| 存档／检查点／复盘 | 整局恢复、AI 流程恢复、只读历史查看各自独立 |
| 当前 UI | Unity 三维沙盘总览＋单位跟随；地图优先，周边按钮、浮层及按需面板 |
| 资产／模板／实例 | 源制作资产、版本化模板与组织节点、实际参战单位分别表达，父子不重复展开 |
| 草稿／采用／执行／回执 | 未提交意图、有效计划、实际规则事实与处理结果分别关联；受理或采用不等于任务完成 |
| 恢复分支／分析身份 | 恢复分支可成为当前游戏有效分支；分析只保存假设与结果，不能写主局 |
| 来源／目标实现 | Army_Editor 与 Gentactix-DSH 提供能力参考；源运行时与目标 Unity、FastAPI、LangGraph、PostgreSQL 架构不能混称已接入 |
| 本机／目标平台 | 当前 Windows 首版与后续鲲鹏、OpenHarmony 实机分别验收 |

## 9. 三项目融合文档同步

### 9.1 定义链与阶段

阅读与交接顺序为：PRD 范围 → 规则和参数 → Unity/交互线框 → 架构 → 接口/数据库 → 样例/智能体协议 → 实施 → 验收。字段以其定义归属文件为准；若出现冲突，记录差异并逐文件对齐，不另建第三套规格。

| 范围 | 现行定位 | 主要入口 |
| --- | --- | --- |
| 核心闭环 | 原三角色、四逻辑角色、确定性规则、人工确认、资料证据、保存恢复与 Unity 双视角；补齐场景版本、命令及基础事实边界 | PRD 原要求、规则、架构与 FUS-01 至 FUS-03 |
| 融合候选 | 资产/装备/地图编辑、单位 Agent、高级配置、完整审计与兼容导入导出 | PRD-24 至 PRD-36 各项状态；FUS-04 至 FUS-10、FUS-12 |
| 后续分析 | 冻结来源与干预结果，不改主局，不混同历史复盘或读档 | PRD-33；FUS-11；TS-25 |

PRD-31 的“增强候选”不降低 PRD-23 已有混合 RAG、重排序和来源证据要求；PRD-34 的兼容增强不降低既有完整存档恢复要求。候选列出模块、接口或实体不等于批准首版新增依赖、页面、数据表或功能。
