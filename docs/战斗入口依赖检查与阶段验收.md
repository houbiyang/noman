## HTTP契约

`POST /api/v1/games/{game_id}/battle/preflight`

需当前对局主持人席位Bearer请求头；不接受URL凭据或bootstrap替代席位。

```json
{"mode":"manual","probe_ai":false,"acknowledge_cost":false}
```

`mode` 仅 `agent` / `manual`；布尔值严格校验；`probe_ai=true` 必须同时 `acknowledge_cost=true`。未知字段拒绝。

返回 `mode / checks / ready / manual_fallback_available / can_start / read_only`。`checks` 为定型数组，兼容Unity JsonUtility。`can_start` 当前恒为false，检查结果不是开局授权。响应 `Cache-Control: no-store`，不缓存真实模型连通结果、不持久保存模式选择。

数据库不可用/授权失效等由原有异常边界返回401/403/404/503，Unity在浮层显示失败并不启动对局。网络超时后远端计费可能已发生，必须手动决定是否重试。

## 风险、失败处理与监控

| 风险 | 影响 | 防护/处理 |
|---|---|---|
| 把连通/登记误认为新规则执行成功 | 用旧规则进行新模式演示 | 引擎和场景绑定硬门禁；禁用开局且不调用旧命令 |
| 红蓝越权检查对方配置 | 私有信息泄漏 | API先验证同局主持人；输出仅固定公开状态，不返回配置 |
| 收费探针重复/超时 | 额外额度消耗 | 明确勾选；既有同方互斥；每方8秒总预算；不自动重试 |
| 模型测试占用数据库连接 | 对局写入阻塞 | 所有联网在短事务退出后进行 |
| 检查时会话撤销或阶段变化 | 结果过期 | 网络后重新授权与读取；结果也不构成开局授权 |
| 网络后关闭面板/切换模式 | 旧结果覆盖新UI | 面板generation校验；检查中禁止切换 |
| 多次只读检查被当作事务写入探针 | 误改旧局或误报写权限就绪 | 明确只验证读取；未宣称本次已执行数据库写入验收 |

检查完成写入客户端本机运行日志（只有完成/失败摘要，不记录请求正文和凭据）；API沿用脱敏错误码，不记录模型原始响应。诊断先看浮层各门禁，再看本地日志，不通过更换请求键或篡改旧规则补救。
