## 1. 阶段结论

S1 的代码、接口和自动化验证已完成。Unity 页面已经可以在后端模式下读取当前快照、读取存档摘要、提交手动存档、请求恢复新分支、暂停后保存退出，以及在命令成功后退出页面。

当前阶段状态：**技术实现通过；真实浏览器三席位最终点击验收待补。**

此前一次浏览器操作在最后连接按钮点击前被用户物理 Escape 中断，因此本记录不把浏览器点击或用户接受写成已完成证据。后续补验只需要使用本记录的联调脚本完成三席位连接和保存恢复操作，不需要改接口契约。

## 2. 本阶段已完成

| 能力 | 实现位置 | 当前行为 |
| --- | --- | --- |
| 三席位会话绑定 | `backend/service.py`、`SandboxServerPanel.cs` | 页面只接受单席位 Bearer 令牌，服务端按角色过滤单位、建议和事件 |
| 同一快照投影 | `SandboxServerClient.cs`、`SandboxServerProjection` | 只有通过对局、分支、快照、地图摘要校验的视图才发布到地图、单位和 HUD |
| 后端存档摘要 | `GET /api/v1/games/{game_id}/saves`、`SandboxServerClient.LoadSaves` | 页面读取存档标识、分支、步数、阶段和是否可恢复，不下载快照正文 |
| 手动存档 | `create_save` 命令、页面“保存当前后端快照” | 后端新增独立手动存档，不覆盖旧记录；成功后重新读取视图 |
| 恢复新分支 | `restore_save` 命令、页面确认对话框 | 校验摘要后从保存点建立新分支，旧分支保留，恢复后暂停 |
| 保存退出 | `begin_exit`、`complete_exit`、`CommandFinished` | 先暂停，再按原命令成功结果退出；失败时保留页面和当前状态 |
| 网络与状态反馈 | `SandboxServerClient`、HUD 通知 | 断连、状态冲突、权限错误、服务器错误和待核对命令显示可读信息 |
| 重试保护 | `pendingBody`、`pendingKey`、原请求核对 | 网络结果不明确时保留原正文和请求键，不自动改键重发 |

## 5. 尚待补验的页面验收

1. 用引导工具创建一局并分别签发 host、red、blue 三个席位。
2. 在三个页面窗口分别输入对应对局 UUID 和令牌，确认单位、任务、事件和时间线来自同一 `snapshot_id`。
3. 主持人打开“存档”，创建手动存档，刷新列表并确认存档摘要出现。
4. 主持人选择存档恢复，确认 `branch_id` 变化、步数回到保存点且页面显示暂停。
5. 主持人执行“准备退出”后选择保存退出，确认命令成功才结束页面；模拟失败时确认页面保留。

这些是用户操作证据，不由静态检查替代。完成后应在本文件追加浏览器时间、构建文件时间、截图路径和实际接受人。
