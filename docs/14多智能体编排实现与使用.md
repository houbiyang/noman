# 多智能体编排实现与使用

日期：2026-11-09。适用范围仅为本项目。本文记录本次实现，正式作战、地图公平性、真实模型质量和目标设备验收分别进行。

## 1. 实际实现

- 每方总指挥、侦察、陆兵、保障四个逻辑角色，红蓝分别配置模型和策略。
- 使用 LangGraph `StateGraph`：三个兵种节点从同一冻结输入并行分析，等待全部报告后进入总指挥节点。
- 规则工具包括本方状态、规则、路线预览和服务预览；按角色和对象授权，不提供文件、SQL 或任意脚本工具。
- 模型输出严格结构化候选；程序校验任务依赖、环路、兵种资格、单位互斥和路线。
- 人工批准、驳回通过统一幂等命令执行。分析完成不表示任务执行完成。
- 原生 LangGraph 检查点和节点待提交写入保存在既有 `ai_runs.checkpoint_ref.langgraph`，不增加业务表。成功报告另行保存，恢复不会重复请求这些角色。
- 启动请求幂等、取消、手动恢复、分支与依据失效、会话撤销和晚到响应检查。
- 运行、报告、工具结果、用量和候选按本方保存与读取。关闭未明确配置的外部 LangSmith 追踪。

人工等待保存在 `ai_runs.status=waiting_human` 与 `proposals` 中，由应用命令采用；图负责生成候选，实际世界始终由后端命令和仿真步维护。

## 3. 红蓝分别配置

在工作台选择红方或蓝方并连接，保存该方配置。主持人不能代读或代写双方私有配置。

| 参数 | 含义 |
| --- | --- |
| 接口根地址 | HTTPS 服务根地址，或本机 HTTP；应包含服务所需版本前缀，例如 `/v1` |
| 模型标识 | 服务实际提供的模型名；要求支持消息和工具调用协议 |
| 密钥环境变量名 | 例如 `RED_AI_API_KEY`、`BLUE_AI_API_KEY`；只填写名称，不填写实际密钥 |
| 单次超时、输出上限 | 限制每次网络请求和生成长度 |
| 总 token 预算 | 按提供方返回用量停止后续调用和方案发布；不是供应商计费的硬上限 |
| 每角色工具、模型调用上限 | 限制循环；不自动重试可能已计费的请求 |
| 风险偏好、保留能源、信息年龄、规划范围 | 作为明确策略输入提供给角色，不覆盖物理与权限硬约束 |

实际密钥从后端进程环境读取，设置后须让后端进程重新加载相应环境。配置仅保存在 `backend/.local/agents/<数据库摘要>/red.json` 和 `blue.json`，使用 Windows 文件权限保护，不提交 Git。配置按当前数据库和方别共享，不是每局各一份。

每次运行冻结配置；修改配置后启动新运行。恢复继续使用原运行配置和检查点。未配置模型会产生 `MODEL_NOT_CONFIGURED` 失败记录，不使用固定文案代替真实模型。

模型提供方可能不返回用量，或在超时后仍计费；界面及记录不保证精确费用。三个兵种同时调用，预算检查也不能撤销已经发生的远端请求。

## 4. 启用与执行流程

1. 在三维沙盘完成双方兵营和单位配置，使用空间测试局。
2. 主持人在准备阶段点击“启用协同测试”。该命令冻结测试参数，保留原地图点位。
3. 双方完成准备并由主持人开始；在暂停或待确认阶段分别规划。也可在准备阶段规划，但后续准备状态变化会使旧候选失效，届时应重新规划。
4. 红蓝分别启动四角色规划。三类兵种报告完成后，总指挥形成待确认任务图。
5. 本方检查方案后批准或驳回。批准不立即移动单位。
6. 双方方案均已采用后，主持人单步或继续播放。单位按依赖执行动作。
7. 出现受阻、资源不足、依赖失败时，工作台显示原因。暂停后可以提交新的规划；草稿不抢占有效计划。
8. 存档保存任务进度、占点、积分、观察与资源。恢复建立新分支，旧运行不能取得新分支采用资格。

任务动作：`move`、`observe`、`capture`、`hold`、`resupply`、`wait`。依赖在后继仿真步生效；一单位一步一个主动作。相同单位多任务须显式排序。服务对象本步移动或执行互斥动作时不能同时接受保障。

## 5. 显式协同测试规则

| 规则 | 默认测试值／语义 |
| --- | --- |
| 控制点 | 原地图 TASK_A/B/C，保留坐标 |
| 占领／中立化 | 各连续两个合格步，敌点先中立化再占领 |
| 占点范围 | 150 米，单位还必须通过测试地表通行检查 |
| 争夺 | 双方有效陆兵在场时停分、清空未完成进度、保留归属 |
| 计分 | 完整稳定控制每点每步一分；新占点当步不计分 |
| 胜负 | 连续全控三步、六十分阈值或第六十步统一结算；同分平局 |
| 观察 | 无人机范围八百米、观察高度八十米；保守建筑柱体和五十米地形采样 |
| 保障 | 七十五米内每步最多二十单位；一单位补给转换一单位能源，受库存和目标能源上限约束 |

这些是本项目可配置测试值，不是《断箭》的统一参数。占点、观察和保障只在显式启用的对局生效；已有演示局继续执行原逻辑。

几何限制：首版使用现有移动网格的测试地表层，在原控制区内寻找通过检查的接近点；没有合法接近点则标记待核验。尚未完成正式桥上／桥下规则和场景公平性验收，不宣称精确三维导航已完成。

观察限制：建筑规则高度缺失，暂用保守不透明柱体，可能漏报；不依据模型猜测产生观察。没有本步有效观察时，原当前发现降为历史记录。控制区争夺公开状态不能推断敌方身份与精确坐标。

本次不启用正式交战、维修、运输、烟幕或四类事件的实际效果。模型工具会明确报告这些边界。

## 6. API 与文件

所有以下路径均以 `/api/v1/games/{game_id}` 为前缀，使用 Bearer 席位身份：

| 入口 | 用途 |
| --- | --- |
| `GET/POST /agents/configuration` | 本方配置，不接受实际密钥 |
| `POST /agents/runs` | 启动规划，需 `Idempotency-Key` 与当前 `context` |
| `GET /agents/runs` | 最近六十条本方角色运行 |
| `GET /agents/runs/{run_id}` | 单次本方运行 |
| `POST /agents/runs/{run_id}/cancel` | 撤销分析采用资格 |
| `POST /agents/runs/{run_id}/resume` | 显式恢复有效检查点，可能重调尚未完成的请求 |
| `POST /commands` | 新增 `enable_coordination`、`review_agent_plan`；沿用幂等与快照事务 |

主持人启用测试命令的 payload 可为空；本方批准命令为：

```json
{"command_type":"review_agent_plan","payload":{"run_id":"本方总指挥运行 UUID","decision":"approve"}}
```

实际请求还须提供 `/view` 返回的完整当前 `context`，不要自行构造签名。

核心文件：`agent_contracts.py`、`agent_model.py`、`agent_tools.py`、`agent_graph.py`、`agent_service.py`、`coordination.py`；工作台为 `agent-workbench.html`。

本次核对 PyPI 发布元数据及本机已安装版本，LangGraph 最新稳定版仍为 `1.2.20`，无需更换主包版本。`backend/requirements-agents.txt` 固定已经安装的五个关键组件，避免后续安装时关键组件版本漂移；这不是完整环境锁文件，也没有新增第三方组件。

| langgraph-checkpoint | 4.3.1 |
| langgraph-prebuilt | 1.1.1 |
| langgraph-sdk | 0.4.14 |
| langchain-core | 1.7.6 |

本次调整仅涉及编排运行与恢复：

- 配置检查点保存器时显式使用 `durability='sync'`，每步检查点成功写入后才进入下一步。没有保存器的隔离图沿用默认执行方式，避开当前版本在无保存器时强制同步的运行错误。
- 后台任务边界统一记录未预期的执行异常，根运行和未完成子运行结束为失败；公开固定的 `AGENT_EXECUTION_FAILED` 错误，日志仅记录运行标识与异常类型，不包含异常原文。数据库整体不可用时，失败状态仍须等待数据库恢复后才能写入；进程被强制终止仍使用原有租约和人工恢复流程。
- 总指挥结果已经通过校验并保存时，恢复复用原结果，继续完成检查点与待确认方案发布，避免重复调用已完成的总指挥模型。恢复仍使用原冻结配置，并检查取消、席位、分支与本方依据。
- 保留显式人工恢复，不增加模型自动重试。尚未确认落库的远端请求仍可能在恢复时重新调用，不能保证供应商请求恰好执行一次。

新增回归覆盖输入检查点写入失败时不进入分析节点、未知节点异常正确记录失败、总指挥结果已保存但节点尚未确认完成时恢复不重复调用且只发布一份待确认方案。测试使用隔离 PostgreSQL 数据库与模型替身，不产生供应商推理请求。
