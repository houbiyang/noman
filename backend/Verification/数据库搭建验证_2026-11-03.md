## 自动验证

执行入口为 `python backend/database.py verify`，实际使用随机命名的独立 PostgreSQL 测试库与恢复库。测试完成后只清理本次创建的数据库；业务新库不写入测试对局。

验证脚本包含 43 项真实数据库检查：

- 建表与有效头完整性、迁移重复执行。
- 悬空／跨局头、重复席位、会话归属及有效期。
- 命令幂等唯一、成功终态完整性及终态不可覆盖。
- 同一步多修订、修订唯一、快照生命周期与列一致、历史不可变。
- 非法分叉来源和合法恢复新分支，恢复命令结果允许属于新分支。
- 事件快照修订引用、手动存档幂等与不可覆盖。
- 建议运行同方约束、证据来源必需字段。
- 私有文档作用域、检索发布前置状态、片段父子解析代次及摘要格式。
- 活动任务去重、运行租约完整性及错误领取代次条件更新。
- 应用账号正向读取／控制更新与反向越权检查。
- 两个独立连接竞争同一控制版本，仅一次条件更新成功。
- 使用 `pg_dump -Fc` 备份临时库并以 `pg_restore` 恢复到另一库，核对对局及建议／运行关联。
- pgvector 原生类型、实际维度与声明维度一致、空间维度复合外键、来源片段摘要、同空间片段唯一、应用账号向量读写及余弦距离计算、向量不可变和向量备份恢复。
- 对局头与执行世代变更需递增控制版本，任务领取代次及资料发布修订不得倒退。

最终执行 43 项，通过 43 项，失败 0 项、错误 0 项、跳过 0 项；本轮测试耗时约 18.5 秒。机器可读摘要保存在本机 `backend/.local/database-verification-v1.json`，后续运行会更新该摘要。测试夹具只写入临时库，结束后核对临时库残留为 0。用例中的空单位状态、三维向量和示例摘要只用于验证数据库结构，不能当作完整快照格式、正式模型或作战规则已经验收。

同日早先曾先落地 19 张非向量业务表；本节结果已由补齐向量表后的全量验证覆盖。当前旧库 `battle_sandbox` 的扩展路径仍为 `$system`，其 vector 扩展数仍为 0；独立扩展路径没有应用到旧库。
