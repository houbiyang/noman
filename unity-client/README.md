## 已提供的前端功能

地图现为 `qinglan-strategic-v6` 青岚都市圈：可操作范围 **12,000 × 12,000 米，共 144 平方公里**，1 Unity 单位对应 1 米。布局包含中央城市、东岸工业货场、北部机场、三处外围村镇、丘陵、河流、农田及林地；以三处跨河通路和两岸联络路组织非对称区域。外围四公里仅用于连续远景，不扩大可操作范围。

使用 Blender 5.2 原创建立十五类米制原型，当前实际布置 1,769 栋建筑与 25,507 株树木，按两公里空间块及材质合并为 637 个网格分块，共 1,572,765 个三角形，数量包含远景。原型涵盖板楼、塔楼、办公楼、四档住宅、仓库、机库、货运棚、储罐、塔台、掩体、兵营与变电设施。道路数据为 144 个节点、243 条边与 3 座桥；它是静态连通图，未实现权威寻路。统计与同源哈希见 `MapPreview/Strategic12km/map-build-summary.json`。

参考用户提供的《断箭》图像，使用深灰沥青、灰白与暖砖色墙面、低饱和绿地、密集林冠、米制平铺底色和法线、斜射日光、阴影及 ACES 色调映射。保持既有全屏 HUD 与角色入口；军队按钮已接入兵营放置与单位管理，设置入口提供服务连接、红蓝 AI 草稿和显示设置，战斗入口仍待接入。Blender 离线渲染与实际网页截图分别提供，当前模型属于可运行策略地图首版，不声称达到参考游戏的美术精度。

当前资源与重建方法见 [十二公里地图说明](MapPreview/Strategic12km/README.md)。旧演示及存档字段保留，业务坐标 120×80 在显示层映射为 12,000×12,000 米；单位模型维持米制尺寸。初始相机显示中央城市与河流通路，滚轮缩小可观察全图，`R` 返回初始观察位置。水面、桥梁及建筑占地供本机单位演示寻路使用；尚未接入正式后端通行、实际测绘、GIS、遮蔽裁决或动态摧毁。

## 激活后的打开步骤

1. 在 Unity Hub 中登录并激活适用的 Editor 许可证。
2. 确认本机编辑器安装已完成；将本目录添加到 Unity Hub，使用 `6000.6.7f1` 打开。
3. 等待模板包解析、资源导入和编译完成，先检查 Console。
4. 在编辑器菜单选择 **穹图 → 阶段一 → 生成作战沙盘场景**，生成 `Assets/Scenes/Sandbox.unity` 并登记构建入口。
5. 点击 Play。首次直接运行模板 `SampleScene` 时也有启动入口，但应使用生成的 `Sandbox` 场景进行正式检查。

在本目录使用 Windows PowerShell：

```powershell
# 打开编辑器
& .\start-unity.ps1

# 直接在图形编辑器中生成场景并进入 Play Mode
& .\start-unity.ps1 -Action Run

# 编辑器关闭时，以批处理方式生成场景
& .\start-unity.ps1 -Action Prepare

# 编辑器关闭时，构建 Windows 客户端
& .\start-unity.ps1 -Action Build
```

编辑器位置不同时可通过 `-EditorPath` 指定实际 `Unity.exe`。批处理日志放在仓库根目录 `.local/unity/`，不纳入 Git。脚本不会自动关闭已有编辑器，也不会安装或激活软件。

Windows 构建成功后的入口为 `Builds/Windows/QiongtuSandbox.exe`；当前没有可宣称已经生成和验收的可执行文件。

## macOS 启动

Apple Silicon Mac 使用与工程一致的 `6000.6.7f1` ARM64 编辑器。网页构建需要 Web Build Support；在 Mac 上构建本工程的 Windows Mono 客户端还需要 Windows Build Support (Mono)。

编辑器安装并激活后，可双击本目录 `start-unity.command` 生成场景并进入 Play Mode，或在终端中选择操作：

```sh
./start-unity.command Open          # 打开工程
./start-unity.command Run           # 生成场景并运行（默认）
./start-unity.command Prepare       # 关闭编辑器后，以批处理生成场景
./start-unity.command BuildWeb      # 关闭编辑器后，构建网页
./start-unity.command BuildWindows  # 关闭编辑器后，构建 Windows Mono 客户端
```

脚本从 `ProjectSettings/ProjectVersion.txt` 读取版本，默认使用 `/Applications/Unity/Hub/Editor/<版本>/Unity.app`。若编辑器安装在其他目录，设置 `UNITY_EDITOR_PATH` 为该应用内 `Contents/MacOS/Unity` 的完整路径。日志保存在仓库根目录 `.local/unity/`。Windows `.exe` 需要在 Windows 环境中运行。

## 网页构建与打开

开发电脑需要已激活的 Unity Editor 及 Web 构建模块；访问已部署网页的使用者不需要安装 Unity 或 Unity Hub。网页加载的仍是本工程的 Unity 场景，不使用旧 Vue 原型。

```powershell
# 首次或修改源码后：先关闭本工程编辑器，再构建网页
& .\start-unity.ps1 -Action BuildWeb

# 使用本机已有 Python 3 启动 HTTP 服务并在浏览器打开
& .\start-web.ps1

# 重新构建后启动；只核对服务时追加 -NoBrowser
& .\start-web.ps1 -Build
```

构建输出为 `Builds/Web/index.html`，本机地址为 `http://127.0.0.1:18766/`。也可双击 `打开网页版.cmd`。不能直接双击构建目录的 HTML 文件；该页面会提示改用本地服务。端口冲突时使用 `-Port 其他端口`。服务仅监听本机，不修改防火墙；更换端口会形成不同浏览器存档空间。

2026-11-01 已成功生成网页构建，本机 HTTP 与程序文件完整性检查通过。网页实测发现并修复了启动时引用 Editor 默认材质导致的黑屏，以及动态模型碰撞组件被裁剪的问题。地图和中文显示、角色切换、缩放、单位跟随、保存及刷新后恢复已经分别验收；v4 战损构建的实际产物大小、截图及本批验证范围见验证记录。

加载页显示实际加载进度、失败说明和重试入口。画面右下角提供全屏按钮；地图鼠标右键操作不会弹出网页菜单。服务使用 Python 标准库，不安装额外依赖。构建采用 Gzip 及 Unity 解压回退，便于本地静态服务访问。

网页中文使用随工程提供的 Noto Sans CJK SC Regular 字体，许可证和来源位于 `Assets/Sandbox/Resources/Fonts/`，构建时保留许可证副本。网页存档使用浏览器 `localStorage`，按站点及部署目录隔离；不会上传到服务器或与 Windows 文件存档互通。清理站点数据、关闭无痕窗口或更换浏览器可能导致无法读取原存档。

对外部署时，将**完整的 `Builds/Web/` 内容**交给 HTTP(S) 静态站点服务，保留 `ThirdPartyNotices/`。本次只提供本机访问，不自动发布公网网址。当前角色切换仍是演示审阅工具，不提供服务器鉴权或多人同步。

## 操作方式

| 操作 | 输入 |
| --- | --- |
| 选择单位 | 左键单击三维单位，或在单位列表中选择；拖动不会触发单位选择 |
| 拖动地图 | 按住左键或中键拖动，地图跟随鼠标平移；也可使用 WASD／方向键 |
| 旋转观察 | 按住右键左右拖动旋转，上下拖动调整俯仰角 |
| 放大／缩小 | 滚轮向前放大、向后缩小；也可使用右侧加减按钮；距离有上下限 |
| 跟随／返回总览 | 底部跟随按钮，或 F |
| 回到初始总览 | 右侧“总览”，或 R |
| 关闭当前浮层 | Esc；先取消确认框，再关闭抽屉，再退出跟随 |

表单与确认框占用键盘时暂停相机快捷键，交互面板上的鼠标不会穿透选择地图单位。桌面中文字体从 Windows 系统动态加载，网页使用随构建提供的开源字体，没有复制或分发系统字体文件。

拖动或旋转必须从地图区域按下；从面板开始的拖动不会移动地图，跨入面板或移出画面后会取消当前手势，窗口失焦也会释放手势。单位跟随时手动平移会退出跟随并保留当前观察中心；右键旋转和滚轮缩放可以继续围绕跟随单位操作。网页端屏蔽地图画布的右键菜单、中键自动滚动及滚轮默认页面行为。

## 军队配置与兵营部署（2026-11-04）

地图右侧「军队」打开深色竖向抽屉。三张建筑卡片对应无人机机库、履带单元兵营、保障车兵营，缩略图由地图上的 Unity 建筑模型渲染。

- 点击兵种图标或「选点建造兵营」，再点击地图陆地放置。已有兵营可「重新选址」，已有单位的位置、目标和路径保持不变。
- 只建造建筑，无数量选择、部署计数器或人工出兵按钮。后续单位由仿真／AI 指令从对应兵营出发；本次不添加自动补兵计时器，也不模拟后端已接入。
- 本地演示沿用红蓝合计最多 10 个单位（包含初始 6 个）；兵营不占名额。该限制来自当前演示需求，不是正式接口契约的单位总量上限。
- 兵营校验陆地、坡度、建筑占用、兵营间距及集结区。地面移动绕开兵营。兵营尺寸与十二公里地图均使用世界米制：三种建筑统一放大至原来的 1.5 倍，出兵口位于建筑前方 15.75 米，集结行距与列距为 6 米，集结区位于前方 24–36 米；仅在保存位置时换算回原业务坐标。
- 点击地图兵营后显示选中环，并在右侧打开该阵营、该兵种的统一管理面板：显示兵种数量、任务状态分布、各单位位置和血量，可搜索、定位、移动、跟随及确认删除。原底部「单位」、直接点选单位及卡片「管理单位」均复用此面板，不再保留独立单位列表。红蓝只能管理本方，主持人可查看双方；删除不会拆除兵营。
- 已放置的兵营带有随镜头移动、缩放和重新选址更新的地图标签：阵营名＋建筑名，例如「红方无人机机库」「红方履带单元兵营」「红方补给站」。红蓝标签使用对应阵营颜色；红蓝席位只显示本方，主持人可显示双方。标签不拦截地图点击，不受公共设施图层开关影响。
- 无人机「选择定位」按完整模型、标签及地面投影共同计算镜头距离与观察中心，并避开顶部／底部 HUD 和右侧管理抽屉；选中时显示连接模型与地表的投影线和实时 X／Z 坐标。定位保持自由观察，跟随返回保留定位构图，重置总览清除定位高度。
- 三类单位模型（侦察无人机、履带地面单元、六轮保障车）统一为原始尺寸的 2 倍；兵营仍保持此前 1.5 倍。无人机基准离地高度由 6 米提高为 48 米（原来的 8 倍），不是绝对海拔；移动、出兵、切换角色和恢复存档均共用此高度。按动画后模型完整包围盒计算三角地形与桥面最高点，必要时抬升显示模型，保持地面单位底部至少 0.08 米、无人机底部至少 48 米净空。碰撞选取范围、地图标签、选中环、跟随距离、车轮滚动和建筑导航安全余量同步适配，不改业务坐标或存档格式。
- 血量使用可存档的 `health` / `maxHealth` 整数字段；`maxHealth = 0` 表示未提供，兼容旧存档，不显示虚构的满血。已提供时显示数值和血条。此轮不新增伤害、回血或自动任务仿真。初始演示单位按阵营与兵种纳入统计，即使没有历史兵营关联。

## 沙盘设置（2026-11-04）

右上角「设置」打开右侧面板，按 [交互与视觉设计](../docs/04交互与视觉设计.md) §5 使用深色 HUD、24/18/14/12 字号层级、8px 卡片圆角和 44px 控件。内容局部滚动，底部保留校验、关闭和保存操作。

- **服务连接**：保存 `/api/v1` 根地址及检测超时。检测实际发送 `GET /health`，200 只说明可达，503 和网络失败均有文字提示，可取消。服务地址保存不会切换本地演示为真实后端。
- **红方 AI／蓝方 AI**：分别记录生成、向量检索、重排序的供应商、地址、模型和凭据引用，以及版本、调用预算、超时和只读重试。所有本机角色均可直接切换、编辑并保存红蓝双方设置，无需切换右上角角色；这些本机草稿不替代后端授权。
